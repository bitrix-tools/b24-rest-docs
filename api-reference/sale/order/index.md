Заказ — это запись о покупке: клиент, товары или услуги, их количество, стоимость и статус выполнения. Методы `sale.order.*` создают, изменяют, возвращают и удаляют заказы Интернет-магазина.

> Быстрый переход: [все методы](#all-methods)
>
> Пользовательская документация: [Как покупателю оформить заказ в интернет-магазине](https://helpdesk.bitrix24.ru/open/28841930/)

## Как начать работу с заказом

1. Получите тип плательщика методом [sale.persontype.list](../person-type/sale-person-type-list.md)
2. Создайте заказ методом [sale.order.add](./sale-order-add.md): передайте идентификатор сайта `lid`, например `s1`, тип плательщика `personTypeId` и валюту `currency`. Сохраните `id` заказа из ответа
3. Добавьте в заказ товары или услуги методами [sale.basketitem.*](../basket-item/index.md) с этим `id` в поле `orderId`. Минуя корзину, добавить товар в заказ нельзя
4. Создайте оплаты методами [sale.payment.*](../payment/index.md) и отгрузки методами [sale.shipment.*](../shipment/index.md)
5. Проверьте заказ методом [sale.order.get](./sale-order-get.md): он вернет заказ вместе с позициями корзины, оплатами и отгрузками
6. Измените статус заказа методом [sale.order.update](./sale-order-update.md): передайте новый `statusId`

## Что важно учитывать

- Поля `lid`, `personTypeId`, `currency` и `userId` задаются только при создании заказа. Метод [sale.order.update](./sale-order-update.md) не изменит их и не вернет ошибку
- Метод [sale.order.list](./sale-order-list.md) возвращает заказы массивом `result.orders` — до 50 за вызов. Методы add, update и get возвращают один заказ в `result.order`
- Метод [sale.order.list](./sale-order-list.md) молча пропускает условие `filter` с неизвестным именем поля. Точные имена полей возвращает [sale.order.getFields](./sale-order-get-fields.md)
- Заказ, у которого есть оплата с `paid` = `Y`, удалить нельзя: [sale.order.delete](./sale-order-delete.md) вернет ошибку `SALE_ORDER_CANCEL_PAYMENT_EXIST_ACTIVE`

Коды ошибок перечислены на страницах методов, общие ошибки REST — в статье [Коды ошибок](../../../error-codes.md).

## Связь заказа с другими объектами

Заказ ссылается на тип плательщика, валюту и статус через свои поля и хранит значения свойств, а корзина, оплаты и отгрузки ссылаются на заказ.

**Тип плательщика.** Поле `personTypeId` определяет, к какому виду клиентов относится покупатель: физическое или юридическое лицо. Типы плательщиков настраивают методы [sale.persontype.*](../person-type/index.md).

**Валюта.** Поле `currency` задает валюту оплаты заказа. Список валют возвращает метод [crm.currency.list](../../crm/currency/crm-currency-list.md).

**Свойства заказа.** Свойства — это данные, которые заполняет покупатель при оформлении заказа, например «Станция метро» или «Дата и время доставки». Свойства создают методы [sale.property.*](../property/index.md), их набор зависит от типа плательщика. Значения свойств конкретного заказа задают методы [sale.propertyvalue.*](../property-value/index.md), в ответе [sale.order.get](./sale-order-get.md) они приходят в `propertyValues`.

**Статус.** Поле `statusId` показывает этап выполнения заказа. Статусы создают и изменяют методы [sale.status.*](../status/index.md).

**Корзина, оплаты и отгрузки.** Как эти объекты связаны между собой, показано в разделе «Как устроен заказ» [справочника типов данных](../data-types.md) Интернет-магазина.
