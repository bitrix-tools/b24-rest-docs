# Интерактивные блоки: обзор сценариев

Интерактивные блоки добавляют на страницу клиентское поведение без отдельной разработки скриптов: слайдер, галерею или счетчик обратного отсчета. Готовое расширение подключают в [манифесте блока](../manifest.md), элементы размечают служебными классами, а поведение настраивают `data-*` атрибутами. Остальное Битрикс24 инициализирует сам при выводе страницы.

Готовых сценария три. Поведение, которого среди них нет, реализуют собственным скриптом: его подключают в ключе `assets` манифеста.

> Быстрый переход: [все сценарии раздела](#all-scenarios)
>
> Пользовательская документация: [Как создать и настроить сайт в Битрикс24](https://helpdesk.bitrix24.ru/open/25309314/)

## Связь с другими объектами

**Манифест блока.** Сценарий определяется набором расширений в ключе `assets.ext`, а настройки поведения описывают в ключе `attrs`. Структура файла разобрана в статье [Файл манифеста](../manifest.md).

**Методы блока.** Содержимое и атрибуты размещенного блока меняют методы раздела [Работа с блоками](../methods/index.md): [landing.block.updateattrs](../methods/landing-block-update-attrs.md) для `data-*` настроек и [landing.block.updatenodes](../methods/landing-block-update-nodes.md) для содержимого слайдов и карточек.

**Специальные блоки.** Если задача относится к меню, навигации, поиску, картам или CRM-формам, откройте раздел [Специальные блоки](../special/index.md).

## Как применить сценарий

1. Посмотрите готовую реализацию: получите список блоков репозитория методом [landing.block.getrepository](../methods/landing-block-get-repository.md), а затем манифест нужного блока методом [landing.block.getmanifestfile](../methods/landing-block-get-manifest-file.md). Коды штатных блоков приведены на страницах сценариев в разделе «Примеры штатных блоков».
2. Подключите расширение в `assets.ext` своего манифеста и разметьте элементы служебными классами. У каждого сценария свое расширение и свои классы: `landing_gallery_cards` и `.js-gallery-cards`, `landing_carousel` и `.js-carousel`, `landing_countdown` и `.js-countdown`. Пример для слайдера:

   ```php
   'assets' => [
       'ext' => ['landing_carousel'],
   ],
   ```

   ```html
   <div class="js-carousel" data-slides-show="1">
       <div class="js-slide">Слайд 1</div>
   </div>
   ```

3. Настройте поведение через `data-*` атрибуты. У слайдера и счетчика их задают на контейнере, у галереи — на самих изображениях. Те атрибуты, которые пользователь должен менять в редакторе, опишите в ключе [attrs](../attributes.md) манифеста.
4. Зарегистрируйте блок методом [landing.repo.register](../../user-blocks/landing-repo-register.md) и добавьте его на страницу методом [landing.landing.addblock](../../page/block-methods/landing-landing-add-block.md).

Зависимости расширений перечислять не нужно: Битрикс24 подключает их сам. Вместе с `landing_gallery_cards` подключаются `landing_core` и `landing_fancybox`. Первое отвечает за базовую инициализацию расширений блока, второе открывает окно просмотра. Вместе с `landing_carousel` и `landing_countdown` подключаются `landing_core` и `landing_jquery`: слайдер и счетчик построены на библиотеках jQuery.

## Права и ограничения

> Scope: [`landing`](../../../scopes/permissions.md)
>
> Кто может выполнять метод: в зависимости от метода

Ограничения:

- поведение включает подключенное расширение, а не отдельный `subtype`. Без расширения в `assets.ext` разметка останется статичной
- расширения находят элементы по служебным CSS-классам: `.js-carousel` для слайдера, `.js-gallery-cards` для галереи, `.js-countdown` для счетчика. Свой класс контейнера задать нельзя
- значения `data-*` атрибутов меняет метод [landing.block.updateattrs](../methods/landing-block-update-attrs.md), но только для атрибутов, описанных в манифесте блока
- в режиме редактирования часть поведения отключается принудительно: галерея не открывается, зацикливание слайдера выключено. Итог проверяют в превью или на опубликованной странице
- при совместном использовании слайдера и галереи сначала подключают `landing_carousel`, затем `landing_gallery_cards`
