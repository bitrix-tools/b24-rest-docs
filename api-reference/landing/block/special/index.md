# Специальные блоки: обзор сценариев

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Специальные блоки решают не общую задачу верстки, а отдельные сценарии: навигацию по странице, меню, поиск, карты и встраивание CRM-форм. Такой блок получает часть содержимого от Битрикс24: система сама подставляет в него пункты меню, ссылку на страницу результатов поиска, код CRM-формы или стартовые настройки карты.

Сценарий включается в [манифесте блока](../manifest.md): в ключе `block` указывают `subtype` и при необходимости `subtype_params`. Исключение — навигация и заголовок страницы: там достаточно маркеров в HTML блока.

В документации описаны сценарии, доступные для собственных блоков. У `subtype` есть и другие значения, но они обслуживают системные блоки Битрикс24 и через REST не настраиваются.

## Связь с другими объектами

**Манифест блока.** Большая часть специальных возможностей задается в [манифесте](../manifest.md): через секцию `block`, секцию `assets` и настройки атрибутов. Файл манифеста можно получить методом [landing.block.getmanifestfile](../methods/landing-block-get-manifest-file.md).

**Методы блока.** Содержимое блока читают и меняют методы раздела [Работа с блоками](../methods/index.md).

**Интерактивные блоки.** Если задача связана не с системными подтипами (`subtype`), а с поведением блока в редакторе и на клиентской стороне, посмотрите раздел [Интерактивные блоки](../interactive/index.md).

Сценарии поиска используют в паре: [Формы поиска](./search-forms.md) описывают блок, который отправляет запрос, а [Результаты поиска](./search.md) — страницу, которая его обрабатывает. [Навигация и заголовок](./navigation.md) обычно дополняет другой сценарий, а меню, карты и CRM-формы чаще решают основную задачу блока.

## Что означают ключи манифеста

- `subtype` — код сценария в секции `block` манифеста. По нему система находит обработчик, который дополняет манифест блока: описывает ноды, добавляет атрибуты и подключает нужные расширения. Можно передать массив подтипов: обработчики применятся по очереди, но колбэк `afterAdd` сработает только у последнего
- `subtype_params` — параметры сценария. Например, у поисковой формы это код шаблона страницы результатов
- `afterAdd` — колбэк, который обработчик регистрирует при необходимости. Он срабатывает один раз, когда блок добавляют на страницу, и заполняет блок данными Битрикс24

## Как применить сценарий

1. Посмотрите готовую реализацию: получите список шаблонов методом [landing.block.getrepository](../methods/landing-block-get-repository.md), а затем манифест нужного блока методом [landing.block.getmanifestfile](../methods/landing-block-get-manifest-file.md). Коды штатных блоков приведены на страницах сценариев.
2. Повторите в своем блоке разметку и ключ `subtype` из манифеста.
3. Зарегистрируйте блок методом [landing.repo.register](../../user-blocks/landing-repo-register.md), передав манифест в параметре `manifest`.
4. Добавьте блок на страницу методом [landing.landing.addblock](../../page/block-methods/landing-landing-add-block.md) и проверьте результат: подготовку система выполняет при добавлении блока на страницу.

## Права и ограничения

> Scope: [`landing`](../../../scopes/permissions.md)
>
> Кто может выполнять метод: в зависимости от метода

Ограничения:

- подтип обрабатывается, когда система собирает манифест блока. Задать сценарий у размещенного блока через REST нельзя: подтип указывают в манифесте при регистрации блока
- подготовка опирается на разметку. Если в блоке нет нужного элемента, например ноды карты или контейнера формы, подтип не сработает
- часть сценариев зависит от контекста Битрикс24: меню каталога — от магазина, карты — от ключа провайдера, CRM-формы — от доступных форм
