# Обзор событий при работе с приложением

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

События дают возможность приложениям реагировать на изменения практически в реальном времени: получать уведомления о жизненном цикле приложения — установке, создании системного пользователя, обновлении, удалении и оплате, — о решении администратора по методам с подтверждением и о добавлении пользователя.

Подробно работа с событиями описана в статье [Концепция и преимущества обработки событий](../../events/index.md).

> Быстрый переход: [все события](#all-events)

## Как получать события

Подписаться на событие onUserAdd можно через:

- [исходящий вебхук](../../../local-integrations/local-webhooks.md)
- [приложение](../../../settings/app-installation/index.md) и метод [event.bind](../../events/event-bind.md)

Подписаться на остальные события раздела можно только через [приложение](../../../settings/app-installation/index.md) и метод [event.bind](../../events/event-bind.md).

Чтобы получать события:

- установите приложение и укажите публичный URL обработчика
- завершите установку методом `installFinish`, если у приложения есть интерфейс, — до этого события в приложение не отправляются. Подробнее в статье [{#T}](../../../settings/app-installation/installation-finish.md)

На URL установки приложения Битрикс24 сам регистрирует обработчик [ONAPPUSERREADY](./on-app-user-ready.md), а у приложений без интерфейса — еще и [onAppInstall](./on-app-install.md). Для этих событий вызывать `event.bind` не нужно. Локальным приложениям ONAPPUSERREADY не отправляется.

Битрикс24 не отправляет события приложению, если подписка на приложение или его оплаченный период истекли.

Пример кода обработчика для события описан в статье [Как проверить свой обработчик для обработки событий Битрикс24](../../events/test-handler.md).

## Токены в событиях

Формат запроса к обработчику описан в статье [Концепция и преимущества обработки событий](../../events/index.md#auth).

#|
|| **Событие** | **Токены в auth** ||
|| onAppInstall, ONAPPUSERREADY, onAppUpdate | `access_token` и `refresh_token` ||
|| onAppPayment, onUserAdd | `access_token` без `refresh_token` ||
|| onAppUninstall, onAppMethodConfirm | Токенов нет ||
|#

## Связь с другими объектами

События раздела связаны с методами работы с пользователями и приложением.

**Пользователь.** Данные из события [onUserAdd](./on-user-add.md) можно использовать вместе с методом [user.get](../../user/user-get.md), если после регистрации нужно получить дополнительную информацию о пользователе или настроить доступ.

**Приложение.** После события [onAppPayment](./on-app-payment.md) текущий статус приложения и срок оплаты можно получить методом [app.info](../system/app-info.md).
