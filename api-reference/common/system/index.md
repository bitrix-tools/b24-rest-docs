# Системные методы: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Системные методы проверяют доступность методов и scope, получают информацию о приложении, кодах доступа, доступных возможностях и времени сервера.

> Быстрый переход: [все методы](#all-methods)

## Что проверять перед вызовом метода

**Контекст приложения.** Метод [app.info](./app-info.md) возвращает полную информацию о приложении только в контексте приложения.

**Доступность метода.** Проверяйте метод через [method.get](./method-get.md): он показывает, есть ли метод в Битрикс24 и доступен ли вызов с текущими scope.

**Доступность возможности.** Метод [feature.get](./feature-get.md) проверяет, включена ли в Битрикс24 возможность, от которой зависит поведение приложения, например расширенный режим офлайн-событий.

## Связь с другими объектами

**Права доступа.** Метод [access.name](./access-name.md) расшифровывает коды `ACCESS`, которые использует, например, [user.access](../users/user-access.md).

**Разрешения приложения.** Метод [scope](./scope.md) возвращает scope текущего приложения. Значения кодов scope описаны на странице [доступных scope](../../scopes/permissions.md).

**Пользователь.** Метод [profile](../users/profile.md) получает базовые данные текущего пользователя. Методы [user.access](../users/user-access.md) и [user.admin](../users/user-admin.md) проверяют коды доступа и права пользователя.
