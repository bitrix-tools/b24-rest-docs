События дают возможность приложениям реагировать на изменения практически в реальном времени: получать уведомления о добавлении, обновлении или удалении комментария в задаче.

Подробно работа с событиями описана в статье [Концепция и преимущества обработки событий](../../../events/index.md).

## Какие события приходят в старой и новой карточке

Какие события придут, зависит от карточки задачи:
- старая карточка, до версии модуля `tasks 25.700.0`, — все три события: о добавлении, изменении и удалении комментария
- новая карточка, с версии модуля `tasks 25.700.0`, — только [OnTaskCommentAdd](./on-task-comment-add.md)

В новой карточке комментарии стали сообщениями чата задачи. Событие приходит при добавлении сообщения в чат.

Как устроена новая карточка, описано в статье [Новая карточка задач: обзор изменений](../../tasks-new.md).

## Какие данные приходят в событиях

В событиях нет текста комментария, только идентификаторы в `data.FIELDS_AFTER`. В событиях изменения и удаления есть еще поле `ACTION`. Как получить комментарий по идентификаторам, зависит от карточки задачи.

В старой карточке приходят `ID` комментария и `TASK_ID`. Чтобы получить комментарий, передайте их в метод [task.commentitem.get](../task-comment-item-get.md): `TASK_ID` — в `TASKID`, `ID` — в `ITEMID`. Удаленный комментарий метод не вернет.

В новой карточке приходят `ID` со значением `0`, `MESSAGE_ID` и `TASK_ID`. Чтобы получить сообщение:
1. вызовите метод [tasks.task.get](../../tasks-task-get.md) с `taskId`, равным `TASK_ID`, — идентификатор чата задачи придет в `result.task.chatId`
2. вызовите метод [im.dialog.messages.get](../../../chats/messages/im-dialog-messages-get.md) с `DIALOG_ID`, равным `chat{chatId}`, — он вернет последние сообщения чата
3. найдите в `result.messages` сообщение, у которого `id` равен `MESSAGE_ID`. Если его нет среди последних, загрузите более ранние: передайте в `LAST_ID` минимальный `id` из полученных сообщений
