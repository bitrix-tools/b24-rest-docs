# Комментарии в задачах: обзор методов и событий

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

В комментариях участники обсуждают работу по задаче, задают вопросы и фиксируют результат. В старой карточке задач комментарий — это сообщение форума задачи. Остальные методы задач собраны в разделе [Задачи](../index.md).

{% note warning "В новой карточке задач комментарии заменены чатом" %}

Новая карточка задач доступна с версии модуля `tasks 25.700.0`. В ней комментарий хранится как сообщение чата, поэтому часть методов раздела не работает. С этой же версии остановлено развитие методов, которые создают, читают, изменяют и удаляют комментарии: в новых интеграциях используйте методы-замены. Чем заменить каждый метод, описано ниже.

## Связь комментариев с другими объектами

Комментарий связан с задачей, пользователем, файлами Диска и результатом задачи.

**Задача.** Комментарии привязаны к задаче по идентификатору `TASKID`. Получить его можно методом [tasks.task.add](../tasks-task-add.md) или [tasks.task.list](../tasks-task-list.md).

**Комментарий.** Сам комментарий адресуется по идентификатору `ITEMID`. Его возвращает метод [task.commentitem.add](./task-comment-item-add.md), а найти комментарий среди существующих можно методом [task.commentitem.getlist](./task-comment-item-get-list.md).

**Пользователь.** Комментарий привязан к автору по числовому идентификатору `AUTHOR_ID`. Получить идентификатор пользователя можно методом [user.get](../../user/user-get.md).

**Файлы Диска.** В старой карточке к комментарию можно прикрепить файлы Диска через параметр `UF_FORUM_MESSAGE_DOC` — это массив строк с префиксом `n` перед идентификатором файла, например `["n4755", "n4753"]`. Идентификатор файла возвращают методы загрузки [disk.storage.uploadfile](../../disk/storage/disk-storage-upload-file.md) и [disk.folder.uploadfile](../../disk/folder/disk-folder-upload-file.md) или методы получения списка [disk.storage.getchildren](../../disk/storage/disk-storage-get-children.md) и [disk.folder.getchildren](../../disk/folder/disk-folder-get-children.md).

В новой карточке файл отправляют в чат задачи методом [im.v2.File.upload](../../chat-bots/chat-bots-v2/im.v2/files/file-upload.md): он загружает файл и отправляет сообщение за один вызов. Если файл уже лежит на Диске, используйте [im.disk.file.commit](../../chats/files/im-disk-file-commit.md).

**Результат задачи.** Комментарий можно закрепить как результат выполнения задачи группой методов [tasks.task.result.*](../result/index.md). В старой карточке метод [tasks.task.result.deleteFromComment](../result/tasks-task-result-delete-from-comment.md) только снимает фиксацию результата, сам комментарий остается; в новой карточке этот метод не работает. Удаление комментария удаляет и связанный с ним результат.

## Как начать работу

Новую карточку включают на портале, поэтому порядок действий зависит от того, какая карточка активна. Статус каждого метода — в таблице [Статус методов в новой карточке задач](#status).

В старой карточке:

1. Получите идентификатор задачи `TASKID`
2. Добавьте комментарий методом [task.commentitem.add](./task-comment-item-add.md) и сохраните `ITEMID` из ответа
3. Измените или удалите комментарий по `TASKID` и `ITEMID` методами [task.commentitem.update](./task-comment-item-update.md) и [task.commentitem.delete](./task-comment-item-delete.md)

В новой карточке работа идет через чат задачи: запросите у задачи поле `CHAT_ID` методом [tasks.task.get](../tasks-task-get.md) — значение придет в поле `chatId`, — а дальше используйте методы из колонки «Чем заменить» таблицы статусов.

## Кто может работать с комментариями

Права относятся к методам этого раздела.

- добавлять комментарий, получать его по идентификатору и получать список комментариев может пользователь с правом доступа на чтение задачи или выше
- изменять и удалять комментарий может администратор, а также автор комментария — но только если это последний комментарий в задаче. Обе операции можно выключить в настройках модуля задач: тогда метод вернет ошибку даже администратору

## Особенности методов раздела

- в новой карточке методы, помеченные в таблице статусов как неработающие, ведут себя по-разному: [task.commentitem.getlist](./task-comment-item-get-list.md) возвращает пустой список без ошибки, [task.commentitem.get](./task-comment-item-get.md) — ошибку, а [task.commentitem.update](./task-comment-item-update.md) и [task.commentitem.delete](./task-comment-item-delete.md) — ошибку `4/TE/ACTION_NOT_ALLOWED`. По этим признакам можно понять, что комментарии задачи уже переехали в чат
- в методах `get`, `getlist`, `update` и `delete` параметры передаются позиционно: имена ключей остаются обычными, но их порядок должен совпадать с порядком в таблице параметров на странице метода, иначе запрос вернет ошибку
- методы работы с комментариями возвращают ошибки с кодом `ERROR_CORE`, а причина отличается текстом в `error_description`. Машиночитаемая часть текста — конструкция вида `TASKS_ERROR_EXCEPTION_#4; Action is not allowed; 4/TE/ACTION_NOT_ALLOWED`. Типовые причины — неверный тип параметров, отсутствие обязательного параметра и отсутствие прав на задачу. Общий формат ошибки описан в статье [Коды ошибок](../../../error-codes.md), а коды конкретного метода — в разделе «Обработка ошибок» на его странице. У методов-замен из раздела [Чаты](../../chats/index.md) своя модель ошибок и свой формат ответа
- поля комментария возвращаются в верхнем регистре, а числовые идентификаторы, например `ID` и `AUTHOR_ID`, приходят строками. Это относится к методам, которые возвращают комментарий. Метод `add` отвечает числом. Вложения лежат в объекте `ATTACHED_OBJECTS`, где ключ — идентификатор вложения. Полная структура ответа и типы полей описаны в разделе «Обработка ответа» на страницах методов
