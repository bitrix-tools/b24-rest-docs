Потоки автоматизируют распределение и выполнение задач. Сотрудник ставит задачу в поток отдела, и поток сам назначает исполнителя. Искать, кто будет делать задачу, не нужно.

Эффективность потока — доля задач без просрочки. Ее считают по формуле `(1 − <количество просроченных задач> / <количество всех задач в потоке>) * 100%`. У потока без задач эффективность — 100%. Чтобы ее повысить, смените тип распределения задач или команду потока.

## Типы распределения

- **Ручное распределение** `manually`. Все задачи получает модератор потока и сам распределяет их по сотрудникам.
- **Распределение по очереди** `queue`. Поток назначает задачи по очереди сотрудникам из команды потока — списка ответственных `responsibleList`. Если в списке отдел, задачи получают его сотрудники. Поток пропускает сотрудника, который отсутствует на рабочем месте, например в отпуске или на больничном.
- **Самостоятельное распределение** `himself`. Задача назначается на постановщика, а каждый участник команды получает уведомление. Исполнителем станет участник, который нажмет кнопку «Взять в работу». Статус задачи сменится на «Выполняется».

Если при распределении по очереди или самостоятельном распределении никого из команды не окажется на рабочем месте, поток перейдет на ручное распределение. Модератором станет администратор потока — он получит уведомление.

## Связь потока с другими объектами

**Группа.** Поток привязан к группе, ее идентификатор передают в параметре `groupId`. Если не указать группу при создании потока, будет создана новая. Идентификатор группы вернет метод [получения списка групп](../../sonet-group/socialnetwork-api-workgroup-list.md) или метод [создания группы](../../sonet-group/sonet-group-create.md).

**Пользователь.** У потока есть администратор, его идентификатор передают в параметре `ownerId`. Если не указать администратора при создании потока, им станет создатель потока. Идентификатор пользователя вернет метод [user.get](../../user/user-get.md).

**Шаблон задачи.** Задачи потока можно создавать по шаблону — идентификатор шаблона передают в параметре `templateId`.

## Как добавить задачу в поток

Чтобы поставить задачу в поток, передайте идентификатор потока в параметре `FLOW_ID` метода [создания новой задачи](../tasks-task-add.md) или [обновления существующей задачи](../tasks-task-update.md). Остальные нужные для потока поля Битрикс24 заполнит сам по настройкам потока.

Без потока у новой задачи обязательны название и исполнитель. Для задачи во включенном потоке достаточно названия и `FLOW_ID`: исполнителя назначит поток.

## Как включить или выключить поток

Поток можно временно выключить и потом включить снова методом [tasks.flow.Flow.activate](./tasks-flow-flow-activate.md). Пока поток выключен, он не назначает исполнителей новым задачам. Задачи, которые уже стоят в потоке, остаются в нем.

Метод принимает идентификатор потока `flowId`. Его вернет метод [создания нового потока](./tasks-flow-flow-create.md), а для задачи из потока — метод [получения информации о задаче](../tasks-task-get.md).

## Как проверить уникальность названия потока

Название потока должно быть уникальным. Занято ли название, проверяет метод [tasks.flow.Flow.isExists](./tasks-flow-flow-is-exists.md).

## Ограничения

- В потоке должен быть хотя бы один ответственный: при создании потока параметр `responsibleList` обязателен для любого типа распределения
- Срок выполнения задачи `plannedCompletionTime` — не меньше одного часа
- Метод [tasks.flow.Flow.update](./tasks-flow-flow-update.md) сбрасывает к значениям по умолчанию описание, флаги и уведомления, которых нет в запросе: описание очистится, уведомления выключатся. Перед изменением получите текущие значения методом [tasks.flow.Flow.get](./tasks-flow-flow-get.md)

## Обзор методов {#all-methods}

> Scope: [`task`](../../scopes/permissions.md)
>
> Кто может выполнять метод:
> - создать поток — администратор Битрикс24 или пользователь с правом создавать потоки, кроме экстранет-пользователей
> - изменить, удалить, включить или выключить поток — администратор Битрикс24, создатель или администратор потока
> - получить и закрепить поток — пользователь, который видит поток: администратор Битрикс24, участник потока или сотрудник отдела, указанного в потоке. Если ставить задачи в поток могут все пользователи, поток видят все сотрудники
> - проверить название — любой пользователь
