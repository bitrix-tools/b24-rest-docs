# Поля шаблона задачи v 3.0

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Страница описывает поля шаблона задачи в REST 3.0. В блоке [Объект шаблона](#templatedto) перечислены все поля шаблона, в других блоках — поля вложенных и связанных объектов.

Методы REST 3.0 вызываются по адресу с `/rest/api/`. Имена методов шаблонов совпадают с именами методов прошлой версии, например `tasks.template.get`, но формат параметров и ответа у них другой. Особенности новой версии описаны в [обзоре REST 3.0](../../rest-v3.md).

## Какие поля принимают и возвращают методы {#methods}

#|
|| **Метод** | **Принимает** | **Возвращает** ||
|| [tasks.template.add](./tasks-template-add-rest-v3.md) | Изменяемые поля [объекта шаблона](#templatedto) в `fields`. Обязательные — `title`, `creatorId` и исполнитель в `responsibleId` или `responsibleCollection` | Созданный шаблон со всеми заполненными полями, включая `tags`, `permissions` и `replicateParams` ||
|| [tasks.template.update](./tasks-template-update-rest-v3.md) | Изменяемые поля [объекта шаблона](#templatedto) в `fields`, кроме `creatorId` и `tParamType` | Признак успеха `true` ||
|| [tasks.template.get](./tasks-template-get-rest-v3.md) | `id` шаблона и `select` | Без `select` — простые поля шаблона без вложенных и связанных объектов. Объекты `tags`, `permissions`, `replicateParams`, `userFields`, `creator`, `group`, `task` возвращаются, только если указаны в `select`. Поля `parent`, `templateChildrenCount`, `subTemplateIds` метод не возвращает ||
|| [tasks.template.list](./tasks-template-list-rest-v3.md) | `select`, `filter`, `order`, `pagination` | Без `select` — только `id`. В `select` недоступны `permissions`, `crmItemIds`, `checklist`, `requireResult`, `checklistAutonumbering`, `parent`, `group`, `task` ||
|| [tasks.template.copy](./tasks-template-copy-rest-v3.md) | `id` исходного шаблона | Копию шаблона в том же составе, что `tasks.template.add` ||
|| [tasks.template.delete](./tasks-template-delete-rest-v3.md) | `id` шаблона | Признак успеха `true` ||
|#

Поля со значением `null` в ответ не попадают. Например, если у шаблона нет родительского шаблона, поля `baseTemplateId` в ответе не будет.

Логические поля принимают и возвращают `true` или `false`. Строковые значения `Y` и `N` из методов прошлой версии в REST 3.0 не подходят: метод вернет ошибку валидации. Исключение — `workdayOnly` в объекте [параметров повторения](#replicate-params).

Поле, которое нельзя изменить, метод отклоняет с ошибкой «Поле не доступно к заполнению». Такие поля отмечены в таблице как «только для чтения».

## Объект права доступа {#permissions}

Элемент массива `permissions`. При записи список прав заменяется целиком. При создании шаблона постановщик получает право `full` автоматически.

Изменить права может администратор, автор шаблона или пользователь с правом `full`. Настройка прав доступна не на всех тарифах: на тарифе без этой возможности метод вернет ошибку, уберите `permissions` из запроса.

[`string`](../../data-types.md) | Кому выдано право. Возможные значения:
- `U<id>` — сотрудник, например `U1`
- `D<id>` — подразделение
- `DR<id>` — подразделение со всеми вложенными
- `G<id>` — группа пользователей
- `UA` — все сотрудники ||
|| **permission***
[`string`](../../data-types.md) | Вид доступа. Возможные значения:
- `read_only` — только чтение
- `full` — чтение, изменение и удаление ||
