Канбан показывает задачи группы или проекта колонками и карточками: колонка — стадия работы, карточка — задача.

«Мой план» — канбан своих задач сотрудника. У каждого сотрудника в нем свои стадии.

Методы раздела получают, добавляют, меняют и удаляют стадии канбана и «Моего плана» и перемещают задачи между стадиями.

## Как начать работу

1. Получите стадии методом [task.stages.get](./task-stages-get.md). Чтобы получить стадии канбана группы, передайте в `entityId` идентификатор группы, а чтобы получить стадии своего «Моего плана» — `0`.
2. Если нужной стадии нет, добавьте ее методом [task.stages.add](./task-stages-add.md). Место задает `AFTER_ID` — идентификатор стадии, после которой добавится новая. Без `AFTER_ID` или с `0` новая стадия окажется первой. Метод вернет идентификатор новой стадии.
3. Переместите задачу в стадию методом [task.stages.movetask](./task-stages-move-task.md). Проверить заранее, может ли пользователь перемещать задачи в группе, можно методом [task.stages.canmovetask](./task-stages-can-move-task.md).
4. Проверьте результат: получите задачи стадии методом [tasks.task.list](../tasks-task-list.md) с фильтром `STAGE_ID`, как описано ниже в разделе «Как получить список задач стадии».

## Связь стадий канбана и «Моего плана» с другими объектами

**Группа.** Стадия канбана принадлежит группе: идентификатор группы передают в `ENTITY_ID`. Его возвращают методы [создания новой группы](../../sonet-group/sonet-group-create.md) и [получения списка групп](../../sonet-group/socialnetwork-api-workgroup-list.md).

**Пользователь.** Стадия «Моего плана» привязана к пользователю. Любой пользователь, в том числе администратор Битрикс24, может менять стадии только в своем плане.

## Как перемещать задачи по стадиям

Переместить задачу в другую стадию можно методом [task.stages.movetask](./task-stages-move-task.md). В стадии задачу можно поставить перед другой задачей или после нее — для этого передайте `ID` соседней задачи в `before` или `after`. Идентификаторы задач возвращают методы [создания задачи](../tasks-task-add.md) и [получения списка задач](../tasks-task-list.md).

Можно переместить задачу:
- в канбане группы, если у пользователя есть право сортировать задачи в группе
- в «Моем плане»

Проверить заранее, может ли пользователь перемещать задачи в группе, можно методом [task.stages.canmovetask](./task-stages-can-move-task.md).

## Как получить список задач стадии

Список задач стадии можно получить методом [tasks.task.list](../tasks-task-list.md).

**Выборка из стадий канбана группы.** Передайте в фильтре `STAGE_ID` с идентификатором стадии и `GROUP_ID` с идентификатором группы. Для первой стадии передайте в `STAGE_ID` массив `[0, ID]`: задачи, которые еще не перемещали по стадиям, хранятся со стадией `0` и видны в первой стадии.

**Выборка из «Моего плана».** Передайте в фильтре `STAGE_ID` с идентификатором стадии. Массив `[0, ID]` здесь не нужен.

## Обзор методов {#all-methods}

> Scope: [`task`](../../scopes/permissions.md)
>
> Кто может выполнять метод:
> - работать со стадиями своего «Моего плана» — любой пользователь
> - получать стадии канбана группы — пользователь с правом просматривать задачи группы
> - добавлять, изменять и удалять стадии канбана группы — владелец или модератор группы
> - перемещать задачи в канбане группы — пользователь с правом сортировать задачи в группе
