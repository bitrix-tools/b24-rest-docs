# Справочник REST API: инструменты и методы Битрикс24

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

С помощью REST API приложение работает с инструментами Битрикс24. Например, оно может создать сделку в CRM, получить задачу, загрузить файл на Диск, обработать событие об изменении данных или встроить виджет в карточку CRM.

> Быстрый переход: [все разделы справочника](#all-methods)

## Как найти нужный метод

Имя метода подсказывает объект и действие: [crm.deal.add](./crm/deals/crm-deal-add.md) создает сделку, [tasks.task.get](./tasks/tasks-task-get.md) возвращает задачу, [disk.file.get](./disk/file/disk-file-get.md) возвращает файл.

Метод можно проверить программно, не открывая его страницу. Метод [method.get](./common/system/method-get.md) показывает, существует ли метод и доступен ли он приложению. Метод [scope](./common/system/scope.md) возвращает список выданных скоупов. Полный машиночитаемый перечень методов новой версии есть в [OpenAPI-документации](./rest-v3.md#openapi).

## Порядок работы с REST API

Если вы еще не отправляли запросы к REST API, начните с раздела [Первый запрос к REST API](../first-steps/first-rest-api-call.md). Шаги ниже описывают работу со старой версией REST API. Отличия новой версии собраны в блоке [Какую версию API выбрать](#version).

1. Определите объект и найдите метод в [обзоре разделов справочника](#all-methods).

2. Выдайте права. Почти каждый метод входит в [скоуп](./scopes/index.md) — группу методов, к которой приложение получает доступ. Скоупы перечисляют при настройке прав приложения. Системные методы работают без отдельного скоупа: в блоке Scope на их страницах стоит `базовый`. Скоуп не открывает доступ сам по себе — приложение работает только с теми данными, которые видит пользователь, выполняющий запрос.

3. Выберите способ авторизации. Вебхук подходит для интеграции внутри своего Битрикс24, приложение с авторизацией по OAuth 2.0 — для решений, которые устанавливают на разные Битрикс24. Оба способа описаны в разделе [Авторизация в REST](../settings/how-to-call-rest-api/authorization.md), а инструменты для локальных интеграций — в разделе [Инструменты для локальных интеграций](../local-integrations/index.md).

4. Вызовите метод. Адрес зависит от способа авторизации:

    - вебхук — идентификатор пользователя и секретный код передают в пути: `https://your-domain.bitrix24.com/rest/USER_ID/WEBHOOK_CODE/method`
    - приложение — токен передают в параметре `auth`: `https://your-domain.bitrix24.com/rest/method?auth=ACCESS_TOKEN`

    Правила передачи параметров описаны в разделе [Как выполняется запрос](../settings/how-to-call-rest-api/general-principles.md), форматы значений — в разделе [Типы данных и форматы параметров](./data-types.md). Имена полей и формат логических значений зависят от модуля и версии API, поэтому сверяйте их на странице метода.

5. Разберите ответ. Данные метода возвращаются в поле `result`, время выполнения — в поле `time`. Списочные методы возвращают не более 50 элементов за раз и передают смещение для следующей страницы в поле `next`. Подробности — в разделах [Как вызывать методы REST API](../settings/how-to-call-rest-api/index.md) и [Особенности списочных методов](../settings/how-to-call-rest-api/list-methods-pecularities.md).

6. Обработайте ошибки. Вместо данных сервер возвращает поля `error` и `error_description`. Общий перечень — в разделе [Коды ошибок](../error-codes.md), ошибки конкретного метода — на его странице.

После первого рабочего вызова пригодятся:

- [События](./events/index.md) — регистрация обработчиков, если интеграция должна реагировать на изменения в Битрикс24, а не только запрашивать данные
- [batch](../settings/how-to-call-rest-api/batch.md) — объединяет до 50 вызовов в один запрос
- [Лимиты REST API](../limits.md) — ограничения на интенсивность и ресурсоемкость запросов
- [Библиотеки для разработки](../sdk/index.md) — готовые клиенты для JavaScript, PHP, Python и Go

## Какую версию API выбрать {#version}

Обе версии REST API работают одновременно и не заменяют друг друга. На [REST 3.0](./rest-v3.md) переведена часть разделов. В таблицах ниже такие разделы помечены, остальные методы вызывают по-прежнему. Один и тот же метод может существовать в обеих версиях с разными параметрами и ответом. Если метод доступен и там, и там, для новой разработки рекомендуется REST 3.0: единый формат ответа, связанные объекты в одном запросе и защита от повторного выполнения по заголовку `Idempotency-Key`.

В REST 3.0 отличаются вызов и разбор ответа:

- адрес содержит сегмент `/rest/api/`
- тело запроса передают только в формате JSON
- список приходит массивом в ключе `items` внутри `result`
- размер и смещение страницы задают объектом `pagination` в запросе — состав его полей описан на странице метода
- ошибка приходит объектом `error` с полями `code`, `message` и `validation`
- тело пакета [batch](./rest-v3.md#batch) передают JSON-массивом объектов с полями `method` и `query`
- формат пакета с оберткой `cmd` в новой версии не работает

Плашка в начале страницы метода показывает его версию. Там же стоит предупреждение, если развитие семейства методов остановлено, — так бывает и вне раздела устаревших методов. Полное сравнение версий — в таблице [Сравнение REST 3.0 со старой версией API](./rest-v3.md#table).

## Когда открывать туториал

Страницы методов помогают подготовить отдельные запросы, но не описывают рабочий сценарий целиком. Если задачу нужно решить от начала до конца, начните с обзорной страницы инструмента или откройте [Туториалы](../tutorials/index.md) — там разобраны готовые сценарии из нескольких вызовов.

## Обзор разделов справочника {#all-methods}

Разделы сгруппированы по задачам. Список методов раздела находится в блоке с якорем `#all-methods` в конце его страницы. В больших разделах в этом же блоке перечислены подразделы и их методы. Три раздела устроены иначе:

- «Бот-платформа» — методы разложены по подразделам, точка входа на индексной странице раздела
- «Виджеты» — методы `placement.*` лежат в корне раздела, каталог точек встраивания находится на странице [Точки встраивания](./widgets/placements.md)
- «Устаревшие методы» — методы вынесены в подраздел RPA

Собственных методов не содержат «Типы данных и форматы параметров», «Скоупы методов» и «Как работать с файлами» — это правила, общие для всего API. Раздел [REST 3.0](./rest-v3.md) описывает правила новой версии и два ее собственных метода: `rest.documentation.openapi` и `rest.scope.list`.
