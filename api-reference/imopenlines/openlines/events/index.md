# Обзор событий при работе с открытыми линиями

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

События открытых линий сообщают приложению о двух вещах: сессия с клиентом началась или закрылась, а в чате добавили, изменили или удалили сообщение. Чаще всего события нужны приложению-коннектору, которое подключает к открытым линиям свой канал связи. Например, по событию о новом сообщении коннектор передает ответ оператора клиенту во внешний мессенджер.

Подробно работа с событиями описана в статье [Концепция и преимущества обработки событий](../../../events/index.md).

Событие получает каждое подписанное приложение, причем по всем коннекторам открытых линий. Свой коннектор определяйте по его коду — `connector_id` или `CONNECTOR`.

> Быстрый переход: [все события](#all-events)

## Как получать события

Подписаться на события открытой линии можно через [приложение](../../../../settings/app-installation/index.md) и метод [event.bind](../../../events/event-bind.md).

Пример кода обработчика для события описан в статье [Как проверить свой обработчик для обработки событий Битрикс24](../../../events/test-handler.md).

## Что приходит в обработчик

Данные приходят в поле `data`, а их состав зависит от события.

**Начало и закрытие сессии.** В `data.DATA` приходят коннектор, чат и открытая линия:

```json
{
    "event": "ONSESSIONSTART",
    "data": {
        "DATA": {
            "connector": {
                "connector_id": "my_connector",
                "line_id": "1",
                "chat_id": "17",
                "user_id": "10"
            },
            "chat": {
                "chat_id": "17"
            },
            "line": {
                "id": "1",
                "name": "Открытая линия"
            }
        }
    }
}
```

- `connector_id` — код коннектора
- `line_id` и `line.id` — идентификатор открытой линии, `line.name` — ее название
- `connector.chat_id` и `chat.chat_id` — идентификатор чата в Битрикс24
- `user_id` — идентификатор клиента в Битрикс24

**Сообщения клиента.** Когда клиент пишет, изменяет или удаляет сообщение через коннектор, в `data` приходит только `DATA` с объектами `connector`, `chat` и `message`. Состав одинаков для всех трех событий, а `message.id` — идентификатор сообщения во внешней системе.

**Сообщения оператора и системы.** Такие сообщения Битрикс24 передает коннектору, чтобы тот доставил их клиенту. Кроме `DATA`, в `data` приходят `CONNECTOR` — код коннектора и `LINE` — идентификатор линии:

#|
|| **Событие** | **Что приходит в `DATA`** ||
|| [OnOpenLineMessageAdd](./on-open-line-message-add.md) | Объекты `connector` и `message`: текст, автор, файлы и идентификатор сообщения в Битрикс24 ||
|| [OnOpenLineMessageUpdate](./on-open-line-message-update.md) | Объекты `im` — чат и сообщение в Битрикс24, `message` — новый текст и массив идентификаторов во внешней системе, `chat` — чат во внешней системе ||
|| [OnOpenLineMessageDelete](./on-open-line-message-delete.md) | Массив объектов `im`, `message` и `chat`. Здесь `message.id` — один идентификатор, а не массив ||
|#

В событиях сообщений `connector.chat_id` и `chat.id` — идентификатор чата во внешней системе, а не в Битрикс24.

{% note warning "" %}

События об изменении и удалении сообщения оператора приходят, только если коннектор подтвердил его доставку методом [imconnector.send.status.delivery](../../imconnector/imconnector-send-status-delivery.md). Без подтверждения Битрикс24 их не отправит, и ошибки при этом не будет.

{% endnote %}

## Как обработать событие

1. Проверьте код коннектора и пропускайте события чужих коннекторов
2. Передайте клиенту во внешнюю систему сообщение оператора из события [OnOpenLineMessageAdd](./on-open-line-message-add.md) и подтвердите доставку методом [imconnector.send.status.delivery](../../imconnector/imconnector-send-status-delivery.md)
3. По событиям [OnOpenLineMessageUpdate](./on-open-line-message-update.md) и [OnOpenLineMessageDelete](./on-open-line-message-delete.md) с ключом `CONNECTOR` найдите сообщение оператора во внешней системе по `message.id`, затем измените или удалите его

## Обзор событий {#all-events}

> Scope: [`imopenlines`](../../../scopes/permissions.md)
>
> Кто может подписаться: любой пользователь

#|
|| **Событие** | **Вызывается** ||
|| [OnSessionStart](./on-session-start.md) | При начале сессии открытой линии, например когда клиент пишет в линию, или методом [imopenlines.session.start](../sessions/imopenlines-session-start.md) ||
|| [OnOpenLineMessageAdd](./on-open-line-message-add.md) | При новом сообщении в чате открытой линии — от клиента, оператора или системы, в том числе методом [imopenlines.crm.message.add](../messages/imopenlines-crm-message-add.md) ||
|| [OnOpenLineMessageUpdate](./on-open-line-message-update.md) | При изменении сообщения: клиентом через коннектор или оператором, если коннектор подтвердил доставку ||
|| [OnOpenLineMessageDelete](./on-open-line-message-delete.md) | При удалении сообщения: клиентом через коннектор или оператором, если коннектор подтвердил доставку ||
|| [OnSessionFinish](./on-session-finish.md) | При закрытии сессии открытой линии. Если после завершения диалога сессия ждет ответа клиента, событие придет, когда она закроется окончательно ||
|#
