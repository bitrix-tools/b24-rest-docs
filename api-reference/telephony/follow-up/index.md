BitrixGPT Follow-up — AI-помощник для видеозвонков Битрикс24. После звонка он разбирает встречу и выделяет ключевые темы. Итог разбора — Follow-up звонка: материалы, по которым команда фиксирует результат встречи.

В Follow-up могут быть доступны:

- итоги встречи
- договоренности
- рекомендации и оценка эффективности
- резюме и расшифровка встречи

## Когда использовать каждый метод

Используйте [call.followup.list](./call-followup-list.md), когда нужно получить список Follow-up за период, отфильтровать звонки по участнику или пройти по страницам результата.

Используйте [call.followup.get](./call-followup-get.md), когда нужно получить Follow-up одного звонка по идентификатору `callId`.

Используйте [call.followup.field.list](./call-followup-field-list.md) и [call.followup.field.get](./call-followup-field-get.md), когда нужно получить список доступных полей Follow-up или описание конкретного поля для настройки `select`.

Методы [call.followup.*](#all-methods) возвращают Follow-up звонков Битрикс24 и звонков Битрикс24 Синк. Если нужны только звонки Синка, используйте [методы Битрикс24 Синк](#sync-methods).

## Порядок работы с Follow-up звонков

1. Получите список Follow-up за нужный период через [call.followup.list](./call-followup-list.md)
2. Возьмите `callId` из результата списка
3. Получите полный Follow-up звонка через [call.followup.get](./call-followup-get.md)
4. Настройте `select`, чтобы получать только нужные поля и AI-блоки
5. При необходимости уточните структуру полей через `*.field.list` и `*.field.get`

## Доступ к данным {#access}

Администратор получает все Follow-up. Обычный пользователь получает Follow-up звонков, в которых он участвовал или в чате которых состоит. У звонка Битрикс24 Синк участие означает, что пользователь говорил в той части звонка, к которой относится Follow-up.

Scope `call` дает приложению доступ к методам, но не расширяет видимость данных. Метод все равно проверяет доступ пользователя, от имени которого выполняется запрос.

## Выбор полей {#select}

Параметр `select` задает, какие поля придут в ответе. AI-блоки — то, что подготовил AI: расшифровка, обзор встречи, саммари, инсайты и оценка эффективности. Можно запросить корневые поля Follow-up, AI-блок целиком или его часть через точку. Например, `overview` вернет весь обзор встречи, а `overview.topic` — только тему.

Полный список полей и вложенных объектов смотрите в статье [Поля Follow-up звонков](./fields.md).

## Связь с другими объектами

**Звонки.** Идентификатор `callId` связывает Follow-up со звонком, а у звонка Синка — со страницей подробного разбора. Подробнее — в разделе [Follow-up звонков Битрикс24 Синк](#sync). Получить `callId` можно из [call.followup.list](./call-followup-list.md), затем передать его в [call.followup.get](./call-followup-get.md).

**Чаты.** Follow-up звонка получают и участники его чата, даже если их не было на звонке. Если пользователь не участвовал в звонке и не состоит в чате, метод вернет ошибку доступа.

**Пользователи.** В поле `participants` приходят участники звонка: идентификатор пользователя, имя, должность и время в секундах. У звонка Битрикс24 это время участия в звонке, у звонка Синка — сколько пользователь говорил. По идентификатору можно найти сотрудника.

## Follow-up звонков Битрикс24 Синк {#sync}

Битрикс24 Синк — отдельный сервис звонков, который подключается к Битрикс24. Follow-up его звонков возвращают два набора методов:

- [call.followup.*](#all-methods) — вместе с Follow-up звонков Битрикс24. Отличить звонок Синка можно по полю `source` со значением `sync`
- [syncconnector.followup.*](#sync-methods) — только Follow-up звонков Синка

Follow-up звонка Синка привязан не к звонку, а к странице подробного разбора. Эту страницу открывает ссылка «Подробный разбор» в чате. Один звонок Синка может дать несколько страниц, по одной на каждую часть звонка. Оба набора строят `callId` из идентификатора этой страницы:

- [syncconnector.followup.*](#sync-methods) возвращают идентификатор страницы как есть, например `128`
- [call.followup.*](#all-methods) прибавляют к нему `10000000000`, например `10000000128`. Сдвиг нужен, чтобы `callId` звонка Синка не совпал с идентификатором звонка Битрикс24

Параметры и поля ответа у [syncconnector.followup.*](#sync-methods) такие же, как у [call.followup.*](#all-methods). Методам Синка нужен scope `syncconnector`, а для Follow-up Синка через [call.followup.*](#all-methods) достаточно scope `call`. Кто какие Follow-up получает — в разделе [Доступ к данным](#access).

Методы — в разделе [Методы Битрикс24 Синк](#sync-methods).
