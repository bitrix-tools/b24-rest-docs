# Источники: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Источник — это рабочее подключение к внешней системе в модуле BIconnector. Он хранит значения параметров авторизации, которые объявил коннектор, и связывает с ними таблицы.

{% note warning "" %}

Методы работают только в контексте [приложения](../../../settings/app-installation/index.md) и только с теми источниками, которые приложение создало само. При вызове вебхуком методы возвращают ошибку `ACCESS_DENIED`. Исключение — метод [biconnector.source.fields](./biconnector-source-fields.md): он возвращает описание полей и доступен вебхуку

{% endnote %}

## Связь источника с коннектором и таблицами

Источник — средний уровень в иерархии работы с данными в модуле BIconnector:

- **Коннектор** хранит адреса эндпоинтов и коды параметров авторизации. Методы — [biconnector.connector.*](../connector/index.md)
- **Источник** хранит значения этих параметров. Связан с коннектором через `connectorId`. Методы — [biconnector.source.*](#all-methods)
- **Таблица** описывает конкретный набор данных. Связана с источником через `sourceId`. Методы — [biconnector.table.*](../table/index.md)

Общие для всего раздела правила — [формы ответа](../index.md#responses), [формат ошибки](../index.md#errors) и [постраничная навигация](../index.md#pagination) — описаны в обзоре модуля BIconnector.

## Как начать работу

1. Создайте коннектор методом [biconnector.connector.add](../connector/biconnector-connector-add.md) или выберите существующий коннектор методом [biconnector.connector.list](../connector/biconnector-connector-list.md).
2. Получите коды параметров авторизации из [поля `settings`](../connector/index.md#settings) коннектора.
3. Создайте источник методом [biconnector.source.add](./biconnector-source-add.md) и передайте `connectorId`, название и значения параметров авторизации в поле `settings`. При создании Битрикс24 обратится к эндпоинту [urlCheck](../connector/index.md#urlCheck) коннектора: если внешняя система не ответит, метод вернет ошибку `SOURCE_CREATE_CONNECTION_ERROR` и источник не создастся.
4. Проверьте источник методом [biconnector.source.get](./biconnector-source-get.md) или [biconnector.source.list](./biconnector-source-list.md).

Удалить источник методом [biconnector.source.delete](./biconnector-source-delete.md) можно, только когда у него не осталось таблиц: иначе приходит ошибка `BX_ERROR` с требованием сначала удалить связанные таблицы.

## Описание полей источника {#fields}

Таблица описывает состав объекта, который методы `add` и `update` принимают в параметре `fields`. Идентификатор объекта в него не входит: методы `update`, `get` и `delete` принимают его отдельным обязательным параметром `id`.

Колонка «Обязательное» показывает, когда поле нужно передавать в `fields`, «Чтение» — приходит ли оно в ответе, «Запись» — принимают ли его методы на входе. Галочка в колонке «Запись» не означает, что поле можно менять после создания: ограничения указаны в описании поля.

`тип` | **Описание** | **Обязательное** | **Чтение** | **Запись** ||
|| **id**
[`integer`](../../data-types.md) | Уникальный идентификатор источника | Нет | ✅ | ❌ ||
|| **title**
[`string`](../../data-types.md) | Название источника, которое видно в интерфейсе «Рабочее место аналитика» | При создании и обновлении | ✅ | ✅ ||
|| **type**
[`string`](../../data-types.md) | Тип источника. У источников, созданных через REST, значение всегда равно `rest` | Нет | ✅ | ❌ ||

Плоский список выше описывает состав источника, но в ответе метода [biconnector.source.get](./biconnector-source-get.md) поля лежат на двух уровнях: собственные поля источника — во вложенном объекте `item.connection`, а `connectorId` и `settings` — прямо в `item`. Путь к названию источника выглядит как `result.item.connection.title`, а не `result.item.title`.

Метод [biconnector.source.fields](./biconnector-source-fields.md) отдает `active` как доступное для записи, но значение этого поля методы `add` и `update` не читают.

### Поле settings {#settings}

Поле `settings` содержит значения параметров авторизации, которые объявил коннектор. На входе и в ответе оно устроено по-разному.

**Что передавать в `add` и `update`.** Объект, где ключ — это `code` параметра из поля `settings` коннектора. Состав этого поля описан в разделе [Поле settings](../connector/index.md#settings) коннектора, а получить коды можно методами [biconnector.connector.get](../connector/biconnector-connector-get.md) или [biconnector.connector.list](../connector/biconnector-connector-list.md). Если в коннекторе объявлен параметр с кодом `token`, источник создается так:

```json
{
    "fields": {
        "connectorId": 12,
        "title": "Sales source",
        "settings": {
            "token": "12345"
        }
    }
}
```

Ключи, которых нет в описании коннектора, отбрасываются без ошибки. При обновлении настройки сливаются по ключу: передавайте только те параметры, которые нужно изменить, — остальные сохранят прежние значения. Параметр исчезает из источника в одном случае — когда коннектор перестал объявлять его в своем поле `settings`. Тогда при следующем сохранении источника настройка удаляется.

**Что приходит в ответе `get` и `list`.** Массив объектов — по одному на каждый параметр коннектора:

#|
|| **Название**
`тип` | **Описание** ||
|| **id**
[`integer`](../../data-types.md) | Идентификатор сохраненного параметра ||
|| **code**
[`string`](../../data-types.md) | Код параметра, заданный коннектором ||
|| **name**
[`string`](../../data-types.md) | Название параметра, которое видит пользователь в интерфейсе ||
|| **type**
[`string`](../../data-types.md) | Тип параметра: `STRING` или `INT` ||
|| **value**
[`string`](../../data-types.md) | Значение, которое указали при создании или обновлении источника ||
|#

```json
[
    {
        "id": 42,
        "code": "token",
        "name": "Токен",
        "type": "STRING",
        "value": "12345"
    }
]
```

{% note warning "" %}

Значения параметров возвращаются в открытом виде, включая пароли и токены. Фильтрации по коду параметра нет: настройка с кодом `password` придет в ответе так же, как любая другая

{% endnote %}
