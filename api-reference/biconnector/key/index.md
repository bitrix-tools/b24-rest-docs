# Ключи доступа BI-коннектора: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Ключ доступа BI-коннектора — это секретная строка, с которой внешние аналитические системы получают данные Битрикс24 через BI-коннектор, например Microsoft Power BI или Google Looker Studio. Методы `biconnector.key.*` позволяют приложению создавать такие ключи, получать их значения, включать, отключать и удалять ключи.

{% note warning "" %}

Методы работают только в контексте [приложения](../../../settings/app-installation/index.md) и только с теми ключами, которые создало это приложение. При вызове вебхуком методы возвращают ошибку `insufficient_auth_type`

{% endnote %}

> Быстрый переход: [все методы](#all-methods)
>
> Пользовательская документация: [Как работают ключи в BI-аналитике](https://helpdesk.bitrix24.ru/open/18017360/)

## Как устроен ключ

Ключ создает метод [biconnector.key.add](./biconnector-key-add.md). Значение ключа Битрикс24 генерирует сам: это строка из 32 латинских букв и цифр. Задать свое значение нельзя.

Ключ принадлежит приложению, которое его создало, и пользователю, от имени которого вызван метод. Другие приложения этот ключ не видят. Значение ключа в поле `ACCESS_KEY` метод [biconnector.key.list](./biconnector-key-list.md) возвращает, только если ключ создал тот же пользователь. У ключей, которые создали другие пользователи этого приложения, поля `ACCESS_KEY` в ответе нет.

{% note warning "" %}

Не публикуйте значение ключа и не храните его в открытом коде: с ключом можно получить данные Битрикс24 через BI-коннектор. Если значение стало известно посторонним, удалите ключ методом [biconnector.key.delete](./biconnector-key-delete.md) и создайте новый

{% endnote %}

## Как начать работу

1. Создайте ключ методом [biconnector.key.add](./biconnector-key-add.md) со значением `ACTIVE` = `Y`: без него ключ создается отключенным и данные по нему не отдаются. В ответе придет идентификатор ключа.
2. Получите значение ключа методом [biconnector.key.list](./biconnector-key-list.md): передайте в `filter` идентификатор ключа, значение придет в поле `ACCESS_KEY`.
3. Передайте значение во внешнюю аналитическую систему. Как ключ передается в запросах к BI-коннектору, показано в статье [Отладка запросов в BI-коннекторе Битрикс24](https://helpdesk.bitrix24.ru/open/17463074/).
4. Чтобы временно закрыть доступ, отключите ключ методом [biconnector.key.update](./biconnector-key-update.md) со значением `ACTIVE` = `N`. Чтобы закрыть доступ навсегда, удалите ключ методом [biconnector.key.delete](./biconnector-key-delete.md).

## Отличия от других методов BIconnector

Методы ключей устроены иначе, чем методы [коннекторов](../connector/index.md), [источников](../source/index.md) и [таблиц](../table/index.md):

- ошибки приходят в корне ответа, а не [внутри поля `result`](../index.md#errors)
- для доступа нужно право управления ключами BI-коннектора, права «Доступ к BI Конструктору» и «Доступ к рабочему месту аналитика» не проверяются
- постраничная навигация в [biconnector.key.list](./biconnector-key-list.md) задается параметрами `limit` и `offset`, а не `page`
- поля передаются и возвращаются в верхнем регистре: `ACTIVE`, `CONNECTION`
