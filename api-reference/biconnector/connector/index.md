# Коннекторы: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Коннектор описывает, как Битрикс24 обращается к внешней системе и забирает оттуда данные для аналитики и отчетов.

Каждый коннектор хранит настройки для работы с внешней системой:

- эндпоинты — URL, по которым Битрикс24 обращается к внешней системе
- параметры авторизации, значения которых задает источник

{% note warning "" %}

Методы работают только в контексте [приложения](../../../settings/app-installation/index.md) и только с теми коннекторами, которые приложение создало само. При вызове вебхуком методы возвращают ошибку `ACCESS_DENIED`. Исключение — метод [biconnector.connector.fields](./biconnector-connector-fields.md): он возвращает описание полей и доступен вебхуку

{% endnote %}

## Связь коннектора с источниками и таблицами

Коннектор — верхний уровень в иерархии работы с данными в модуле BIconnector:

- **Коннектор** описывает, как Битрикс24 обращается к внешней системе: адреса эндпоинтов и коды, названия и типы параметров авторизации в поле [settings](#settings). Методы — [biconnector.connector.*](#all-methods)
- **Источник** — рабочее подключение к внешней системе. Связан с коннектором через `connectorId` и хранит значения параметров авторизации. Методы — [biconnector.source.*](../source/index.md)
- **Таблица** задает состав колонок, которые приложение отдает по этому подключению. Таблица связана с источником через `sourceId`. Методы — [biconnector.table.*](../table/index.md)

Общие для всего раздела правила — [формы ответа](../index.md#responses), [формат ошибки](../index.md#errors) и [постраничная навигация](../index.md#pagination) — описаны в обзоре модуля BIconnector.

## Как начать работу

1. Разместите на своей стороне четыре [эндпоинта](#endpoints): для проверки подключения, списка таблиц, описания таблицы и получения данных.
2. Создайте коннектор методом [biconnector.connector.add](./biconnector-connector-add.md): передайте название, логотип, адреса эндпоинтов и список параметров авторизации в поле [settings](#settings). В ответе придет `id` коннектора.
3. Создайте источник методом [biconnector.source.add](../source/biconnector-source-add.md): передайте `id` коннектора в параметре `connectorId` и значения параметров авторизации. При создании источника Битрикс24 обратится к эндпоинту [urlCheck](#urlCheck).

Если нужно заранее узнать, какие поля принимает коннектор, запросите схему методом [biconnector.connector.fields](./biconnector-connector-fields.md).

Изменить настройки коннектора можно методом [biconnector.connector.update](./biconnector-connector-update.md), удалить — методом [biconnector.connector.delete](./biconnector-connector-delete.md). Удалить коннектор получится только после удаления всех его источников: иначе метод вернет ошибку `CONNECTOR_DELETE_RESTRICTED`.

При обновлении коннектора обязательных полей нет: метод [biconnector.connector.update](./biconnector-connector-update.md) принимает любой набор полей и меняет только переданные.

### Поле settings {#settings}

Поле `settings` содержит массив параметров, которые пользователь заполнит при создании источника. Каждый параметр — объект с тремя ключами:

- `code` — код параметра. Используется как идентификатор параметра: именно с такими названиями параметры передаются во внешнюю систему. Максимальная длина — 512 символов
- `name` — название параметра, которое отображается в интерфейсе, в разделе «Рабочее место аналитика». Максимальная длина — 512 символов
- `type` — тип параметра. Поддерживаются значения `STRING` и `INT`, тип определяет поле ввода в интерфейсе. Значение регистрозависимо: `string` в нижнем регистре вызовет ошибку `VALIDATION_SETTINGS_INVALID_TYPE`

```json
[
    {
        "code": "login",
        "name": "Логин",
        "type": "STRING"
    },
    {
        "code": "password",
        "name": "Пароль",
        "type": "STRING"
    }
]
```

## Эндпоинты коннектора {#endpoints}

Эндпоинты размещаются на стороне внешней системы. Битрикс24 обращается к ним сам, когда пользователь настраивает подключение или запрашивает данные для отчета. Максимальная длина каждого адреса — 2048 символов.

Сбой эндпоинта виден по-разному в зависимости от того, в каком сценарии он произошел. Если эндпоинт не ответил при создании источника, метод [biconnector.source.add](../source/biconnector-source-add.md) вернет ошибку `SOURCE_CREATE_CONNECTION_ERROR`. Если сбой произошел при работе с таблицей или при запросе данных для отчета, ошибку увидит только пользователь в разделе «Рабочее место аналитика» — в ответе REST ее не будет.

Общие правила для всех четырех эндпоинтов:

- запрос приходит методом POST, тело запроса — в формате `application/x-www-form-urlencoded`. Вложенные объекты передаются в нотации `connection[login]=user`
- в объекте `connection` приходят параметры авторизации: ключ — это `code` параметра из поля [settings](#settings) коннектора, значение — то, что указал пользователь при создании источника
- ответ нужно возвращать с HTTP-статусом **200**, иначе Битрикс24 считает подключение недоступным
- на установку соединения отводится 250 секунд, на передачу тела ответа — отдельный и более короткий лимит в 60 секунд. Долгая выгрузка оборвется, даже если соединение установилось сразу
- по умолчанию Битрикс24 не обращается к адресам в локальной сети

### urlCheck {#urlCheck}

Эндпоинт `urlCheck` решает две задачи:

- подтверждает, что соединение с внешней системой доступно
- подтверждает, что параметры авторизации, которые указал пользователь, верны

Битрикс24 обращается к эндпоинту:

- при создании нового подключения
- при редактировании существующего подключения
- при создании таблицы

Параметры запроса:

- `connection` — объект с параметрами авторизации источника

Тело запроса для коннектора с параметрами `login` и `password`:

```
connection[login]=user&connection[password]=secret
```

Формат ответа свободный, но тело не должно быть пустым — Битрикс24 проверяет только сам факт успешного ответа.

Отправить проверочный запрос можно в интерфейсе, в разделе «Рабочее место аналитика».

Отдельного формата отказа у эндпоинта нет: чтобы сообщить, что подключение не работает, ответьте любым HTTP-статусом кроме 200 или верните пустое тело. Тогда метод [biconnector.source.add](../source/biconnector-source-add.md) вернет ошибку `SOURCE_CREATE_CONNECTION_ERROR` и источник не создастся.

### urlTableList {#urlTableList}

Эндпоинт `urlTableList` возвращает список доступных таблиц. Битрикс24 обращается к нему при создании таблицы через интерфейс и передает строку поиска. Отбор по ней выполняет сама внешняя система.

Параметры запроса:

- `searchString` — строка поиска, которую ввел пользователь. Может быть пустой
- `connection` — объект с параметрами авторизации источника

Тело запроса:

```
searchString=sales&connection[login]=user&connection[password]=secret
```

Ответ — массив объектов в формате `JSON`:

- `code` — код таблицы во внешней системе. Битрикс24 сохраняет его как `externalCode` таблицы
- `title` — название таблицы, которое увидит пользователь при выборе
- `id` — идентификатор таблицы во внешней системе, необязательный. Если его передать, `externalCode` таблицы получит именно это значение, а `code` уйдет в описание таблицы

```json
[
    {
        "code": "sales_2024",
        "title": "Продажи 2024"
    }
]
```

Поля `code` и `title` обязательные. Если хотя бы у одной таблицы одно из них пустое, Битрикс24 считает ответ некорректным и показывает ошибку.

### urlTableDescription {#urlTableDescription}

Эндпоинт `urlTableDescription` возвращает список полей конкретной таблицы. Битрикс24 обращается к нему при создании таблицы через интерфейс.

Параметры запроса:

- `table` — код таблицы, для которой запрошено описание. Это значение `code` из ответа эндпоинта [urlTableList](#urlTableList)
- `connection` — объект с параметрами авторизации источника

Тело запроса:

```
table=sales_2024&connection[login]=user&connection[password]=secret
```

Ответ — массив объектов в формате `JSON`:

- `code` — код поля во внешней системе
- `name` — название поля, которое увидит пользователь
- `type` — тип поля. Поддерживаются значения `int`, `string`, `double`, `date`, `datetime`, `money` и `timezone`. Неизвестный тип Битрикс24 обрабатывает как `string`

```json
[
    {
        "code": "deal_id",
        "name": "Сделка",
        "type": "int"
    },
    {
        "code": "created_at",
        "name": "Дата создания",
        "type": "datetime"
    }
]
```

Значения типа `money` Битрикс24 хранит как число: из значения отбрасывается все, кроме цифр, минуса и десятичного разделителя, — валюта не сохраняется. Тип `timezone` содержит идентификатор часового пояса, но к данным источников, созданных через REST, сдвиг по нему не применяется.

Все три поля обязательные. Если хотя бы у одного поля `code`, `name` или `type` пустые, Битрикс24 считает ответ некорректным и показывает ошибку. Пустой массив тоже считается некорректным ответом: у таблицы должно быть хотя бы одно поле.

### urlData {#urlData}

Эндпоинт `urlData` возвращает данные конкретной таблицы.

Битрикс24 обращается к эндпоинту:

- при создании таблицы через интерфейс
- при синхронизации полей таблицы через интерфейс
- при выполнении запросов на получение данных для BI-Конструктора

Параметры запроса:

- `table` — код таблицы, для которой запрошены данные
- `select` — массив названий полей таблицы, которые нужно вернуть
- `filter` — фильтр по полям таблицы: ключ — название поля, значение — условие отбора
- `limit` — максимальное количество строк в ответе, целое число
- `mapFields` — соответствие полей: ключ — код поля во внешней системе, значение — название этого поля в таблице. Если задан `select`, в объекте остаются только выбранные поля
- `connection` — объект с параметрами авторизации источника

Параметры `select`, `filter` и `limit` приходят не в каждом запросе — обработчик должен работать и без них.

Других параметров в запросе не будет: Битрикс24 передает только перечисленные.

Тело запроса:

```
table=sales_2024&limit=100&mapFields[deal_id]=Сделка&connection[login]=user&connection[password]=secret
```

Ответ — массив массивов в формате `JSON`. Первый элемент — коды полей, остальные элементы — строки данных в том же порядке:

```json
[
    ["deal_id", "created_at"],
    [101, "2024-08-30T12:19:57+02:00"],
    [102, "2024-08-30T13:41:12+02:00"]
]
```
