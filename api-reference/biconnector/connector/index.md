# Коннектор: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Коннектор — это инструмент для интеграции Битрикс24 с внешними системами данных. Он отвечает за подключение к сторонним API и базам данных, импорт данных для аналитики и отчетов.

Каждый коннектор содержит настройки для работы с конкретным источником:
- эндпоинты — URL, по которым Битрикс24 обращается к внешней системе
- параметры авторизации, значения которых задает источник

{% note warning "" %}

Методы работают только в контексте [приложения](../../../settings/app-installation/index.md) и только с теми коннекторами, которые приложение создало само. При вызове вебхуком методы возвращают ошибку `ACCESS_DENIED`. Исключение — метод [biconnector.connector.fields](./biconnector-connector-fields.md): он возвращает описание полей и доступен вебхуку

{% endnote %}

## Связь коннектора с источниками и датасетами

Коннектор — верхний уровень в иерархии работы с данными в модуле BIconnector:
- **Коннектор** описывает, как Битрикс24 обращается к внешней системе. Методы — [biconnector.connector.*](#all-methods)
- **Источник** определяет, какие именно данные доступны из подключенного сервиса. Источник связан с коннектором через `connectorId` и хранит значения параметров авторизации. Методы — [biconnector.source.*](../source/index.md)
- **Датасет** формирует итоговый набор данных, который можно использовать в отчетах и аналитике. Датасет связан с источником через `sourceId`. Методы — [biconnector.dataset.*](../dataset/index.md)

Коннектор хранит только коды параметров авторизации в поле [settings](#settings). Значения задает источник.

## Как начать работу

1. Разместите на своей стороне четыре [эндпоинта](#endpoints): для проверки подключения, списка таблиц, описания таблицы и получения данных
2. Проверьте список доступных полей методом [biconnector.connector.fields](./biconnector-connector-fields.md), если нужно заранее узнать, какие поля можно передать
3. Создайте коннектор методом [biconnector.connector.add](./biconnector-connector-add.md): передайте название, логотип, адреса эндпоинтов и список параметров авторизации в поле [settings](#settings). В ответе придет `id` коннектора
4. Создайте источник методом [biconnector.source.add](../source/biconnector-source-add.md): передайте `id` коннектора в параметре `connectorId` и значения параметров авторизации. При создании источника Битрикс24 обратится к эндпоинту [urlCheck](#urlCheck)
5. Измените настройки коннектора методом [biconnector.connector.update](./biconnector-connector-update.md) или удалите коннектор методом [biconnector.connector.delete](./biconnector-connector-delete.md). Удалить коннектор можно только после удаления всех его источников

### Поле settings {#settings}

Поле `settings` содержит массив параметров, необходимых для настройки источников данных. Каждый параметр — это объект со следующей структурой:

- `code` — код параметра. Используется как идентификатор параметра: именно с такими названиями параметры передаются во внешнюю систему. Максимальная длина — 512 символов
- `name` — название параметра, которое отображается в интерфейсе, в разделе «Рабочее место аналитика». Максимальная длина — 512 символов
- `type` — тип параметра. Поддерживаются значения `STRING` и `INT`, тип определяет поле ввода в интерфейсе

```json
[
    {
        "code": "login",
        "name": "Логин",
        "type": "STRING"
    },
    {
        "code": "password",
        "name": "Пароль",
        "type": "STRING"
    }
]
```

## Эндпоинты коннектора {#endpoints}

Эндпоинты размещаются на стороне внешней системы. Битрикс24 обращается к ним сам, когда пользователь настраивает подключение или запрашивает данные для отчета.

Общие правила для всех четырех эндпоинтов:

- запрос приходит методом POST, тело запроса — в формате `application/x-www-form-urlencoded`. Вложенные объекты передаются в нотации `connection[login]=user`
- в объекте `connection` приходят параметры авторизации: ключ — это `code` параметра из поля [settings](#settings) коннектора, значение — то, что указал пользователь при создании источника
- ответ нужно возвращать с HTTP-статусом **200**, иначе Битрикс24 считает подключение недоступным
- время ожидания ответа — 250 секунд
- по умолчанию Битрикс24 не обращается к адресам в локальной сети

### urlCheck {#urlCheck}

Эндпоинт `urlCheck` решает две задачи:

1. Проверяет доступность соединения с внешней системой
2. Проверяет параметры авторизации, которые указал пользователь

Битрикс24 обращается к эндпоинту:

- при создании нового подключения
- при редактировании существующего подключения
- при создании датасета

Параметры запроса:

- `connection` — объект с параметрами авторизации источника

Тело запроса для коннектора с параметрами `login` и `password`:

```
connection[login]=user&connection[password]=secret
```

Формат ответа свободный, но тело не должно быть пустым — Битрикс24 проверяет только сам факт успешного ответа. Отправить проверочный запрос можно в интерфейсе, в разделе «Рабочее место аналитика».

### urlTableList {#urlTableList}

Эндпоинт `urlTableList` возвращает список доступных таблиц. Битрикс24 обращается к нему при создании датасета через интерфейс и передает строку поиска — отбирает таблицы по ней сама внешняя система.

Параметры запроса:

- `searchString` — строка поиска, которую ввел пользователь. Может быть пустой
- `connection` — объект с параметрами авторизации источника

Тело запроса:

```
searchString=sales&connection[login]=user&connection[password]=secret
```

Ответ — массив объектов в формате `JSON`:

- `code` — код таблицы во внешней системе. Битрикс24 сохраняет его как `externalCode` датасета
- `title` — название таблицы, которое увидит пользователь при выборе

```json
[
    {
        "code": "sales_2024",
        "title": "Продажи 2024"
    }
]
```

Оба поля обязательные. Если хотя бы у одной таблицы `code` или `title` пустые, Битрикс24 считает ответ некорректным и показывает ошибку.

### urlTableDescription {#urlTableDescription}

Эндпоинт `urlTableDescription` возвращает список полей конкретной таблицы. Битрикс24 обращается к нему при создании датасета через интерфейс.

Параметры запроса:

- `table` — код таблицы, для которой запрошено описание. Это значение `code` из ответа эндпоинта [urlTableList](#urlTableList)
- `connection` — объект с параметрами авторизации источника

Тело запроса:

```
table=sales_2024&connection[login]=user&connection[password]=secret
```

Ответ — массив объектов в формате `JSON`:

- `code` — код поля во внешней системе
- `name` — название поля, которое увидит пользователь
- `type` — тип поля. Поддерживаются значения `int`, `string`, `double`, `date`, `datetime`. Неизвестный тип Битрикс24 обрабатывает как `string`

```json
[
    {
        "code": "deal_id",
        "name": "Сделка",
        "type": "int"
    },
    {
        "code": "created_at",
        "name": "Дата создания",
        "type": "datetime"
    }
]
```

Все три поля обязательные. Если хотя бы у одного поля `code`, `name` или `type` пустые, Битрикс24 считает ответ некорректным и показывает ошибку.

### urlData {#urlData}

Эндпоинт `urlData` возвращает данные конкретной таблицы.

Битрикс24 обращается к эндпоинту:
- при создании датасета через интерфейс
- при синхронизации полей датасета через интерфейс
- при выполнении запросов на получение данных для BI Конструктора

Параметры запроса:

- `table` — код таблицы, для которой запрошены данные
- `select` — список полей датасета, которые нужно вернуть. Параметр может отсутствовать в запросе
- `filter` — фильтр по полям датасета. Параметр может отсутствовать в запросе
- `limit` — максимальное количество строк в ответе. Параметр может отсутствовать в запросе
- `mapFields` — соответствие полей: ключ — код поля во внешней системе, значение — название этого поля в датасете. Если задан `select`, в объекте остаются только выбранные поля
- `connection` — объект с параметрами авторизации источника

Тело запроса:

```
table=sales_2024&limit=100&mapFields[deal_id]=Сделка&connection[login]=user&connection[password]=secret
```

Ответ — массив массивов в формате `JSON`. Первый элемент — коды полей, остальные элементы — строки данных в том же порядке:

```json
[
    ["deal_id", "created_at"],
    [101, "2024-08-30T12:19:57+02:00"],
    [102, "2024-08-30T13:41:12+02:00"]
]
```
