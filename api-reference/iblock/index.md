# Инфоблоки в REST 3.0: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Информационный блок, или инфоблок, хранит однотипные элементы с разделами и свойствами. На инфоблоках построены [универсальные списки](../lists/index.md) и [торговый каталог](../catalog/index.md). Методы `iblock.element.*` читают элементы инфоблока со значениями свойств и возвращают описание полей элемента.

{% note warning "" %}

Методы `iblock.element.get` и `iblock.element.list` работают только с инфоблоками, у которых в административной панели задан «Символьный код API» и включен «Доступ через REST». В облачном Битрикс24 административной панели нет, поэтому эти методы возвращают ошибку для любого инфоблока.

{% endnote %}

> Быстрый переход: [все методы](#all-methods)

{% note info "" %}

Методы раздела относятся к REST 3.0. Особенности вызова и формат ответа новой версии API описаны в [обзоре REST 3.0](../rest-v3.md).

{% endnote %}

## Как начать работу

1. В административной панели коробочного Битрикс24 откройте настройки инфоблока, задайте «Символьный код API» и включите «Доступ через REST»
2. Уточните доступные поля элемента методом [iblock.element.field.list](./iblock-element-field-list.md)
3. Получите элементы инфоблока методом [iblock.element.list](./iblock-element-list.md), передав идентификатор инфоблока в фильтре `iblockId`
4. Получите один элемент методом [iblock.element.get](./iblock-element-get.md) по идентификатору инфоблока и элемента

## Ограничения и особенности {#restrictions}

- «Символьный код API» (`API_CODE`) и «Доступ через REST» (`REST_ON`) задаются только в настройках инфоблока в административной панели. Через REST эти настройки изменить нельзя
- Если у инфоблока не задан символьный код API, методы возвращают ошибку `Unable to compile iblock entity.`. Если код задан, а доступ через REST выключен, — ошибку `Restricted iblock ID:N (код)`. Для несуществующего инфоблока возвращается `Iblock not found.`
- В облачном Битрикс24 административной панели нет, поэтому методы `iblock.element.get` и `iblock.element.list` в облаке не работают. Элементы универсальных списков получайте методом [lists.element.get](../lists/elements/lists-element-get.md), товары каталога — методами [catalog.product.*](../catalog/product/index.md)
- Методы [iblock.element.field.list](./iblock-element-field-list.md) и [iblock.element.field.get](./iblock-element-field-get.md) не обращаются к инфоблоку и работают в облаке
- Методы только читают данные. Создавать, изменять и удалять элементы инфоблока через `iblock.element.*` нельзя
- Элемент возвращается с полями `id`, `iblockId`, `name`, `iblockSectionId` и `properties`. Для свойства возвращаются только идентификатор значения, значение и описание
- Права пользователя на инфоблок методы не проверяют: доступ к элементам открывает настройка «Доступ через REST»

## Связь с другими объектами

**Универсальные списки.** Каждый универсальный список — это инфоблок, а идентификатор списка совпадает с идентификатором инфоблока. Для работы с элементами списков в облаке используйте методы [lists.element.*](../lists/elements/index.md).

**Торговый каталог.** Каталог товаров тоже хранится в инфоблоке. Идентификатор инфоблока каталога возвращают методы [catalog.catalog.*](../catalog/catalog/index.md), товары читают и изменяют методы [catalog.product.*](../catalog/product/index.md).
