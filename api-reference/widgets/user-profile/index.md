# Виджеты в профиле пользователя: обзор точек встраивания

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Точки встраивания раздела добавляют пункт приложения туда, где пользователь работает с профилями: в собственное меню пользователя и в карточку сотрудника. Обе точки требуют scope `user`.

Для регистрации виджета используйте метод [placement.bind](../placement-bind.md) и передавайте нужный код в параметре `PLACEMENT`.

> Быстрый переход: [все точки встраивания](#all-placements)

## Как выбрать точку встраивания

Точки различаются тем, чей идентификатор приходит обработчику.

#|
|| **Точка встраивания** | **Где пользователь ее видит** | **Когда использовать** ||
|| [USER_PROFILE_MENU](./profile-menu.md) | В меню по аватару в правом верхнем углу, по кнопке *Расширения* | Когда действие относится к самому пользователю: личные настройки приложения, переход в свой раздел. Обработчик получает идентификатор того, кто открыл меню ||
|| [USER_PROFILE_TOOLBAR](./profile-toolbar.md) | В меню кнопки в правом верхнем углу карточки сотрудника | Когда действие относится к конкретному сотруднику: данные из внешней системы, заявка по человеку. Обработчик получает идентификатор владельца открытой карточки ||
|#

## Как начать работу

1. Выберите точку встраивания по тому, чей идентификатор нужен обработчику
2. Зарегистрируйте обработчик методом [placement.bind](../placement-bind.md), передайте код точки в `PLACEMENT` и название пункта в `TITLE`
3. Завершите установку приложения — до этого пункт в интерфейсе не появится
4. Откройте меню пользователя или карточку сотрудника и выберите свой пункт
5. Разберите `PLACEMENT_OPTIONS` в обработчике и получите данные сотрудника методом [user.get](../../user/user-get.md)

## Что получает обработчик

Данные передаются POST-запросом: часть параметров — в query-строке адреса обработчика, остальные — в теле запроса {.b24-info}

### PLACEMENT_OPTIONS

Значение `PLACEMENT_OPTIONS` передается как JSON-строка с контекстом вызова. Набор ключей у точек одинаковый, а вот значение `USER_ID` — разное.

#|
|| **Точка встраивания** | **Ключи** | **Что в USER_ID** ||
|| [USER_PROFILE_MENU](./profile-menu.md) | `USER_ID`, `URI` | Текущий пользователь — тот, кто открыл меню ||
|| [USER_PROFILE_TOOLBAR](./profile-toolbar.md) | `USER_ID`, `URI` | Владелец открытой карточки сотрудника ||
|#

Ключ `URI` — универсальный: в нем приходит адрес страницы, с которой открыт виджет.

Ни одна из точек не поддерживает параметр `OPTIONS` метода [placement.bind](../placement-bind.md): переданные значения не сохраняются, [placement.get](../placement-get.md) возвращает пустой массив.

## Связь с другими объектами

**Пользователь.** По `USER_ID` из контекста вызова приложение получает данные сотрудника методом [user.get](../../user/user-get.md). Список сотрудников и структуру компании отдают методы разделов [{#T}](../../user/index.md) и [{#T}](../../departments/index.md).

## Типовые ошибки

#|
|| **Ошибка** | **Как решить** ||
|| Пункт не появился после регистрации | Завершите установку приложения и обновите страницу: меню и карточка собирают список пунктов при загрузке ||
|| Обработчик получает не того сотрудника | Проверьте код точки: `USER_PROFILE_MENU` отдает текущего пользователя, а `USER_PROFILE_TOOLBAR` — владельца открытой карточки ||
|| Переданный при регистрации `OPTIONS` не приходит обработчику | Точки раздела не поддерживают `OPTIONS`. Передавайте свои значения через адрес обработчика ||
|#
