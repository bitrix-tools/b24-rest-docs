# Автозаполнение реквизитов в карточке CRM

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

> Scope: [`placement, crm`](../../../scopes/permissions.md)
>
> Быстрый переход: [все точки встраивания](#all-placements)

Точки автозаполнения реквизитов подключают приложение к поиску данных в карточке CRM. Приложение работает как внешний источник: получает строку поиска, возвращает найденные варианты и передает данные выбранного варианта для подстановки в карточку.

Код точки встраивания передается в параметре `PLACEMENT` метода [placement.bind](../../placement-bind.md). Если приложение работает только с отдельными странами, передайте их идентификаторы через запятую без пробелов в параметре `OPTIONS[countries]`. Идентификаторы стран возвращает метод [crm.requisite.preset.countries](../../../crm/requisites/presets/crm-requisite-preset-countries.md).

Битрикс24 вызывает внешний поиск, когда пользователь ввел в строку поиска не менее трех символов.

Команды `crmShowFoundEntities` и `crmShowCreatedEntity` вызываются через [BX24.placement.call](../../ui-interaction/bx24-placement-call.md), а событие `onCrmEntityIsNeedToCreate` обрабатывается через [BX24.placement.bindEvent](../../ui-interaction/bx24-placement-bind-event.md). Отдельно регистрировать их не нужно.

{% note info "" %}

Обработчик не будет доступен в интерфейсе выбора источника поиска, пока установка приложения не завершена. [Проверьте установку приложения](../../../../settings/app-installation/installation-finish.md)

{% endnote %}

## Как выбрать точку встраивания {#all-placements}

#|
|| **Точка встраивания** | **Код** | **Когда использовать** ||
|| [Автозаполнение реквизитов клиента](./requisite-autocomplete.md) | `CRM_REQUISITE_AUTOCOMPLETE` | Для поиска и подстановки реквизитов компании или контакта ||
|| [Автозаполнение банковских реквизитов](./bank-detail-autocomplete.md) | `CRM_BANK_DETAIL_AUTOCOMPLETE` | Для поиска и подстановки банковских реквизитов, например по БИК ||
|#

## Порядок работы

1. Пользователь вводит строку в поле автозаполнения реквизитов
2. Битрикс24 вызывает обработчик приложения и передает строку поиска в `PLACEMENT_OPTIONS.searchQuery`
3. Приложение передает найденные варианты командой `crmShowFoundEntities`
4. Если пользователь выбирает вариант, приложение получает событие `onCrmEntityIsNeedToCreate` и передает данные для подстановки командой `crmShowCreatedEntity`

## Что получает обработчик

Для обеих точек Битрикс24 передает обработчику одинаковый контекст: в `PLACEMENT_OPTIONS` приходит строка поиска `searchQuery` и адрес страницы `URI`, с которой вызван поиск. Значение передается JSON-строкой. После разбора оно выглядит так — пример для поиска реквизитов клиента из карточки компании:

```json
{
    "searchQuery": "7712345678",
    "URI": "/crm/company/details/2979/?any=details%2F2979%2F&IFRAME=Y&IFRAME_TYPE=SIDE_SLIDER"
}
```

Для банковских реквизитов в `URI` приходит адрес формы реквизита, а не карточки. Остальные параметры запроса к обработчику — стандартные для виджетов, их состав описан на страницах точек встраивания.

## Как вернуть найденные варианты

Найденные варианты приложение передает командой [BX24.placement.call](../../ui-interaction/bx24-placement-call.md) с именем `crmShowFoundEntities`. В поле `data` передайте массив вариантов: `id` — идентификатор варианта на стороне приложения, `name` — название, которое увидит пользователь:

```javascript
BX24.placement.call(
    'crmShowFoundEntities',
    {
        data: [
            { id: 'company-123', name: 'ООО Ромашка' },
            { id: 'company-124', name: 'ООО Василек' }
        ]
    }
);
```

Полный состав варианта — телефон, e-mail, сайт — и подстановка выбранного варианта в карточку командой `crmShowCreatedEntity` описаны на страницах [автозаполнения реквизитов клиента](./requisite-autocomplete.md) и [банковских реквизитов](./bank-detail-autocomplete.md).

## Типовые ошибки

#|
|| **Ошибка** | **Как решить** ||
|| Обработчик зарегистрирован, но недоступен при поиске | Проверьте, что приложение установлено, а в `PLACEMENT` передан код нужной точки встраивания ||
|| Обработчик недоступен для нужной страны | Проверьте значение `OPTIONS[countries]`. Строка должна содержать идентификаторы стран через запятую без пробелов ||
|| Найденные варианты не отображаются | Передавайте массив вариантов в поле `data` команды `crmShowFoundEntities` ||
|| `placement.bind` возвращает `WRONG_AUTH_TYPE` с описанием `Application context required` | Регистрируйте точку от имени приложения. Вебхуком точку не привязать ||
|| После выбора вариант не подставляется в карточку | Подпишитесь на `onCrmEntityIsNeedToCreate` и после выбора варианта вызовите `crmShowCreatedEntity` с полями для подстановки ||
|#

Другие коды ошибок регистрации перечислены в разделе «Возможные коды ошибок» страницы [placement.bind](../../placement-bind.md).
