# Взаимодействие с UI: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы `BX24.placement.*` дают виджету доступ к интерфейсу Битрикс24: возвращают контекст вызова, показывают доступные команды и события, вызывают команды и регистрируют обработчики. Работают они в той точке встраивания, где открыт виджет, и обмениваются данными с окном Битрикс24 через `postMessage`.

{% note warning "" %}

Это методы js-библиотеки, а не REST API. Их вызывают в браузере из кода виджета — через [BX24.js](../../../sdk/bx24-js-sdk/index.md) или библиотеку [b24jssdk](../../../sdk/b24jssdk/index.md). Методов REST `placement.call` и `placement.bindEvent` не существует: запрос к `/rest/` с такими именами вернет ошибку. Через REST регистрируют только саму точку встраивания — методом [placement.bind](../placement-bind.md).

{% endnote %}

У отдельных точек встраивания есть собственные команды и события — например, у карточки звонка. Их описывают дочерние разделы.

> Быстрый переход: [все методы](#all-methods)

## Как начать работу

1. Зарегистрируйте виджет методом [placement.bind](../placement-bind.md) и откройте его в нужной точке встраивания
2. Подключите в коде виджета клиентскую библиотеку. [BX24.js](../../../sdk/bx24-js-sdk/index.md) подключается одним скриптом и работает через функции обратного вызова, [b24jssdk](../../../sdk/b24jssdk/index.md) ставится пакетом и возвращает промисы. Без библиотеки объекта `BX24` на странице не будет
3. Получите контекст вызова методом [BX24.placement.info](./bx24-placement-info.md) — из него видно, в какой точке встраивания открыт виджет и какие параметры пришли вместе с ним
4. Запросите доступные команды и события методом [BX24.placement.getInterface](./bx24-placement-get-interface.md) — набор зависит от точки встраивания
5. Подписывайтесь на события методом [BX24.placement.bindEvent](./bx24-placement-bind-event.md) и вызывайте команды методом [BX24.placement.call](./bx24-placement-call.md)
6. Если нужно открыть стандартную страницу Битрикс24, отдельный слайдер приложения или системный диалог, используйте [дополнительные методы BX24.js](../bx24-widget-methods.md) и [системные диалоги](../../../sdk/bx24-js-sdk/system-dialogues/index.md)

```js
BX24.ready(function () {
    BX24.init(function () {
        BX24.placement.getInterface(function (result) {
            // result.command — доступные команды, result.event — доступные события
            console.log(result);
        });
    });
});
```

## Ограничения и особенности

- Набор команд и событий свой у каждой точки встраивания. Один и тот же вызов может быть валиден для `CALL_CARD` и не существовать в другом месте интерфейса
- Незнакомую команду и подписку на незарегистрированное событие интерфейс точки встраивания игнорирует молча: функция обратного вызова не срабатывает, ошибка не приходит. Поэтому перед вызовом проверяйте интерфейс методом [BX24.placement.getInterface](./bx24-placement-get-interface.md)
- Методы раздела работают на стороне интерфейса и не заменяют REST API: получать и сохранять данные по-прежнему нужно методами REST. Это касается и навигационных методов [BX24.openPath](../bx24-widget-methods.md), [BX24.openApplication](../bx24-widget-methods.md), [BX24.closeApplication](../bx24-widget-methods.md)

## Специальные возможности отдельных точек встраивания

Некоторые точки встраивания поддерживают не только базовые методы `BX24.placement.*`, но и собственные команды и события для управления конкретными элементами Битрикс24.

#|
|| **Точка встраивания** | **Что доступно** ||
|| [Карточка звонка `CALL_CARD`](./call-card/index.md) | Данные текущего звонка, управление автозакрытием карточки и события карточки звонка ||
|| [Карточка, дело и список CRM](#crm-card) | Команда `reloadData` для обновления данных в интерфейсе CRM ||
|| [Дело в таймлайне CRM](../crm/detail-activity-area.md) | Команды отрисовки штатного интерфейса дела: `setLayout`, `setLayoutItemState`, `setPrimaryButtonState`, `setSecondaryButtonState`, `bindLayoutEventCallback`, `bindValueChangeCallback`, `lock`, `unlock`, `finish` ||
|| [Поиск клиента в карточке CRM](../crm/detail-search.md) | Команды `crmShowFoundEntities` и `crmShowCreatedEntity`, событие `onCrmEntityIsNeedToCreate` ||
|| [Автозаполнение реквизитов](../crm/requisites-autocomplete/requisite-autocomplete.md) | Команды `crmShowFoundEntities` и `crmShowCreatedEntity`, событие `onCrmEntityIsNeedToCreate` ||
|| [Фоновая точка встраивания `PAGE_BACKGROUND_WORKER`](./page-background-worker/index.md) | Управление интерфейсом карточки звонка из фонового виджета и события действий оператора ||
|| [Календарь `CALENDAR_GRIDVIEW`](../../calendar/calendar-grid-view.md) | Команды `getEvents`, `viewEvent`, `addEvent`, `editEvent`, `deleteEvent` и события `Calendar.customView:*` — обновление списка и смена периода ||
|| [Пользовательский тип поля `USERFIELD_TYPE`](../user-field/index.md) | Команды `setValue` и `getValue` для чтения и записи значения поля. Пример вызова — в туториале [{#T}](../../../tutorials/crm/crm-widgets/widget-as-field-in-lead-page.md) ||
|| [Блок на сайте](../../landing/embedding/block.md) | Команда `refreshBlock` для перерисовки блока после правок приложения ||

Кроме команд точки встраивания, каждому виджету доступны общие методы — например [BX24.resizeWindow](../../../sdk/bx24-js-sdk/additional-functions/bx24-resize-window.md), меняющий размеры фрейма. В списке [BX24.placement.getInterface](./bx24-placement-get-interface.md) они не возвращаются.

## Обновление данных в CRM {#crm-card}

Команда `reloadData` обновляет данные в интерфейсе CRM после действий приложения. Ее вызывают через [BX24.placement.call](./bx24-placement-call.md), а доступна она виджетам трех семейств точек встраивания:

- `CRM_*_DETAIL_TAB` — вкладка карточки элемента, обновляется форма карточки
- `CRM_*_DETAIL_ACTIVITY` — дело в таймлайне карточки, обновляется та же карточка
- `CRM_*_LIST_MENU` — пункт меню над списком элементов, обновляется список

```js
BX24.placement.call('reloadData', {}, function () {
    console.log('reloadData called');
});
```

Команда обновляет данные только в интерфейсе и вызывает функцию обратного вызова без аргументов. Изменения в CRM она не сохраняет: чтобы данные попали в базу, пользователь должен сохранить карточку.
