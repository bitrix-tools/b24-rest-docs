# Пользовательские типы полей: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Приложение может зарегистрировать собственный тип пользовательского поля — не само поле, а его тип и адрес обработчика. Когда пользователь открывает карточку с полем такого типа, Битрикс24 открывает обработчик во фрейме прямо в поле — дальше работа не отличается от обычного виджета.

В облачном Битрикс24 такие поля работают в карточке CRM. Метод [crm.userfield.types](../../crm/universal/user-defined-fields/crm-userfield-types.md) показывает приложению стандартные и только его собственные типы. Но создать поле по полному коду типа `rest_<APP_ID>_<USER_TYPE_ID>` можно и из другого приложения, и через вебхук администратора.

> Быстрый переход: [все методы](#all-methods)

## Как начать работу

1. Зарегистрируйте тип поля методом [userfieldtype.add](./userfieldtype-add.md). Передайте короткий код типа `USER_TYPE_ID` и публичный адрес обработчика `HANDLER`. Метод приводит код к нижнему регистру, поэтому сразу передавайте его строчными буквами

2. Получите идентификатор приложения методом [app.info](../../common/system/app-info.md) и соберите полный код типа по форме `rest_<APP_ID>_<USER_TYPE_ID>`. Например, для приложения с `ID: 123` и `USER_TYPE_ID: phone_data` полный код будет `rest_123_phone_data`

3. Создайте поле с этим типом. В универсальном методе [userfieldconfig.add](../../crm/universal/userfieldconfig/userfieldconfig-add.md) передайте полный код в `field.userTypeId`, в объектном методе CRM, например [crm.lead.userfield.add](../../crm/leads/userfield/crm-lead-userfield-add.md), — в `fields.USER_TYPE_ID`. Для этого шага приложению нужны scope `crm`, а для универсального метода еще `userfieldconfig`

4. Добавьте поле в форму карточки и откройте карточку — в поле загрузится обработчик

5. Разберите в обработчике `PLACEMENT_OPTIONS` и запишите значение поля командой `setValue`

Полный сценарий с кодом обработчика — в туториале [{#T}](../../../tutorials/crm/crm-widgets/widget-as-field-in-lead-page.md).

## Что получает обработчик {#handler-data}

Обработчик открывается в точке встраивания `USERFIELD_TYPE`. Регистрировать его методом [placement.bind](../placement-bind.md) не нужно: метод [userfieldtype.add](./userfieldtype-add.md) сам привязывает обработчик к этой точке.

Вместе с запросом Битрикс24 передает обработчику `PLACEMENT_OPTIONS` — данные поля и элемента, в карточке которого поле открыто. В HTTP-запросе они приходят JSON-строкой, в библиотеке b24jssdk те же данные доступны объектом `$b24.placement.options`.

#|
|| **Ключ** | **Что содержит** ||
|| `MODE` | Режим отображения поля: `view` или `edit` ||
|| `ENTITY_ID` | Код объекта, в карточке которого открыто поле. Например, `CRM_LEAD` ||
|| `FIELD_NAME` | Имя пользовательского поля с префиксом `UF_CRM_` ||
|| `ENTITY_VALUE_ID` | Идентификатор элемента, чья карточка открыта. Для новой карточки приходит `0` ||
|| `VALUE` | Текущее значение поля. У множественного поля — массив значений ||
|| `MULTIPLE`, `MANDATORY` | Признаки множественного и обязательного поля: `Y` или `N` ||
|| `XML_ID` | Внешний код поля ||
|| `ENTITY_DATA` | Объект карточки CRM: `entityTypeId` — [идентификатор типа объекта](../../crm/data-types.md#object_type), `entityId` — идентификатор элемента, `module` — `crm` ||
|| `URI` | Адрес открытой карточки ||
|#

Остальные данные запроса — авторизация пользователя и параметры приложения — такие же, как у других точек встраивания. Как выглядит весь запрос, показано в статье [{#T}](../index.md), а `PLACEMENT_OPTIONS` для поля в карточке сделки — на странице метода [userfieldtype.add](./userfieldtype-add.md).

Из обработчика доступны две команды точки встраивания — `setValue` и `getValue`. Их вызывают методом [BX24.placement.call](../ui-interaction/bx24-placement-call.md):

```js
BX24.placement.call('setValue', value, () => {});
```

В режиме редактирования, когда `MODE` равен `edit`, команда `setValue` записывает значение в форму карточки. В базу значение попадет, когда пользователь сохранит карточку.

## Связь с другими объектами

Тип поля связывает три темы: карточку CRM, где выводится поле, приложение, которое зарегистрировало тип, и механизм виджетов, через который работает обработчик.

**CRM.** Поля пользовательского типа выводятся в карточках сделок, лидов, контактов, компаний, новых счетов, коммерческих предложений и смарт-процессов. Какими методами создать поле в каждой из карточек — в статье [{#T}](../../crm/universal/user-defined-fields/userfield-type.md).

**Приложение.** Тип поля принадлежит приложению, которое его зарегистрировало, поэтому через входящий вебхук создать тип нельзя — нужен контекст [установленного приложения](../../../settings/app-installation/index.md). Метод [app.info](../../common/system/app-info.md) возвращает `ID` приложения для полного кода типа и в поле `INSTALLED` показывает, завершена ли установка. Пока она не завершена, обработчик в поле не загружается.

**Виджеты.** `USERFIELD_TYPE` — одна из точек встраивания приложений. Остальные точки перечислены в статье [{#T}](../placements.md), общий механизм встраивания — в статье [{#T}](../index.md).

## Ограничения

- Сменить код `USER_TYPE_ID` у зарегистрированного типа нельзя: новый код — это новый тип, и поля для него придется создать заново. Адрес обработчика, название, описание и высоту поля меняет [userfieldtype.update](./userfieldtype-update.md)
- Если Битрикс24 работает по HTTPS, используйте HTTPS и для обработчика, иначе браузер заблокирует загрузку содержимого поля

Требования к коду типа и адресу обработчика перечислены в параметрах метода [userfieldtype.add](./userfieldtype-add.md).

## Типовые ошибки

#|
|| **Что происходит** | **Причина** | **Что сделать** ||
|| [Методы `userfieldtype.*`](#all-methods) возвращают `WRONG_AUTH_TYPE` | Метод вызван через вебхук, а типы полей регистрирует только приложение | Вызывайте методы с токеном установленного приложения ||
|| [userfieldconfig.add](../../crm/universal/userfieldconfig/userfieldconfig-add.md) возвращает `Указан неверный пользовательский тип` | В `userTypeId` передан короткий код типа или тип удален | Передайте полный код `rest_<APP_ID>_<USER_TYPE_ID>` и проверьте тип методом [userfieldtype.list](./userfieldtype-list.md) из приложения, которое его зарегистрировало ||
|| [userfieldtype.add](./userfieldtype-add.md) возвращает `ERROR_CORE` с текстом `Unable to set placement handler: Handler already binded` | Код типа уже зарегистрирован в Битрикс24, или у другого типа этого приложения тот же адрес обработчика | Выберите другой код или адрес ||
|| Поле пропало из карточки, методы CRM не возвращают его значение | Тип поля удален методом [userfieldtype.delete](./userfieldtype-delete.md) | Зарегистрируйте тип с тем же кодом тем же приложением — поля и значения вернутся ||
|#

Как создать поле в разных карточках CRM и что делать, если в поле не загружается обработчик, — в статье [{#T}](../../crm/universal/user-defined-fields/userfield-type.md).

## Обзор методов {#all-methods}

> Scope: [`placement`](../../scopes/permissions.md)
>
> Кто может выполнять метод: администратор

#|
|| **Метод** | **Описание** ||
|| [userfieldtype.add](./userfieldtype-add.md) | Регистрирует новый тип пользовательских полей и возвращает `true` ||
|| [userfieldtype.update](./userfieldtype-update.md) | Изменяет настройки зарегистрированного приложением типа и возвращает `true` ||
|| [userfieldtype.list](./userfieldtype-list.md) | Возвращает типы, которые зарегистрировало текущее приложение, не больше 50 за вызов ||
|| [userfieldtype.delete](./userfieldtype-delete.md) | Удаляет зарегистрированный приложением тип и возвращает `true` ||
|#
