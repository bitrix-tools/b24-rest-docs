# Пользовательские типы полей: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Группа методов `userfieldtype.*` управляет собственными типами пользовательских полей приложения. Приложение регистрирует не само поле, а его тип и адрес обработчика. Когда пользователь открывает карточку с полем такого типа, Битрикс24 открывает обработчик во фрейме прямо в поле — дальше работа не отличается от обычного виджета.

В облачном Битрикс24 такие поля работают в карточке CRM. Приложение создает поля стандартных типов и тех типов, которые зарегистрировало само. Администратор создает поля любых зарегистрированных типов, в том числе типов других приложений.

> Быстрый переход: [все методы](#all-methods)

## Как начать работу

1. Зарегистрируйте тип поля методом [userfieldtype.add](./userfieldtype-add.md). Передайте короткий код типа `USER_TYPE_ID` и публичный адрес обработчика `HANDLER`

2. Получите идентификатор приложения методом [app.info](../../common/system/app-info.md) и соберите полный код типа по форме `rest_<APP_ID>_<USER_TYPE_ID>`. Например, для приложения с `ID: 123` и `USER_TYPE_ID: phone_data` полный код будет `rest_123_phone_data`

3. Создайте поле с этим типом — универсальным методом [userfieldconfig.add](../../crm/universal/userfieldconfig/userfieldconfig-add.md) или объектным методом CRM, например [crm.lead.userfield.add](../../crm/leads/userfield/crm-lead-userfield-add.md). В параметре `USER_TYPE_ID` передайте полный код типа, а не короткий

4. Добавьте поле в форму карточки и откройте карточку — в поле загрузится обработчик

5. Разберите в обработчике `PLACEMENT_OPTIONS` и запишите значение поля командой `setValue`

Полный сценарий с кодом обработчика — в туториале [{#T}](../../../tutorials/crm/crm-widgets/widget-as-field-in-lead-page.md).

## Что получает обработчик

Обработчик открывается в точке встраивания `USERFIELD_TYPE`. Регистрировать ее методом [placement.bind](../placement-bind.md) не нужно: точку создает `userfieldtype.add`.

Вместе с запросом Битрикс24 передает обработчику `PLACEMENT_OPTIONS` — данные поля и элемента, в карточке которого поле открыто. В HTTP-запросе они приходят JSON-строкой, в библиотеке b24jssdk те же данные доступны объектом `$b24.placement.options`.

#|
|| **Ключ** | **Что содержит** ||
|| `MODE` | Режим отображения поля: `view` или `edit` ||
|| `ENTITY_ID` | Код объекта, в карточке которого открыто поле. Например, `CRM_LEAD` ||
|| `FIELD_NAME` | Имя пользовательского поля с префиксом `UF_CRM_` ||
|| `ENTITY_VALUE_ID` | Идентификатор элемента, чья карточка открыта. Для новой карточки может прийти `0` ||
|| `VALUE` | Текущее значение поля. У множественного поля — массив значений ||
|| `MULTIPLE`, `MANDATORY` | Признаки множественного и обязательного поля: `Y` или `N` ||
|| `XML_ID` | Внешний код поля ||
|#

Из обработчика доступны две команды точки встраивания — `setValue` и `getValue`. Их вызывают методом [BX24.placement.call](../ui-interaction/bx24-placement-call.md):

```js
BX24.placement.call('setValue', value, () => {});
```

Команда `setValue` записывает значение в форму карточки. В базу значение попадет, когда пользователь сохранит карточку.

## Связь с другими объектами

Тип поля связывает три темы: карточку CRM, где выводится поле, приложение, которое зарегистрировало тип, и механизм виджетов, через который работает обработчик.

**CRM.** Поля пользовательского типа выводятся в карточках сделок, лидов, контактов, компаний, новых счетов, коммерческих предложений и смарт-процессов. Какими методами создать поле в каждой из карточек — в статье [{#T}](../../crm/universal/user-defined-fields/userfield-type.md).

**Приложение.** Тип поля принадлежит приложению, которое его зарегистрировало, поэтому через входящий вебхук создать тип нельзя — нужен контекст [установленного приложения](../../../settings/app-installation/index.md). Метод [app.info](../../common/system/app-info.md) возвращает `ID` приложения для полного кода типа и в поле `INSTALLED` показывает, завершена ли установка.

**Виджеты.** `USERFIELD_TYPE` — одна из точек встраивания приложений. Остальные точки перечислены в статье [{#T}](../placements.md), общий механизм встраивания — в статье [{#T}](../index.md).

## Ограничения

- Сменить код `USER_TYPE_ID` у зарегистрированного типа нельзя: удалите тип методом [userfieldtype.delete](./userfieldtype-delete.md) и зарегистрируйте заново. Адрес обработчика, название, описание и высоту поля меняет [userfieldtype.update](./userfieldtype-update.md)
- Используйте для обработчика HTTPS, иначе браузер заблокирует загрузку содержимого поля

Требования к коду типа и адресу обработчика перечислены в параметрах метода [userfieldtype.add](./userfieldtype-add.md). Что делать с ошибкой `Указан неверный пользовательский тип` при создании поля и с полем, в котором не загружается обработчик, — в статье [{#T}](../../crm/universal/user-defined-fields/userfield-type.md).
