# Виджеты в мессенджере: обзор точек встраивания

- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

Раздел описывает точки встраивания виджетов в интерфейс чата Битрикс24. Через них разработчик может добавить кнопку в панели над полем ввода, отдельный пункт в сайдбаре чата, действие в контекстном меню конкретного сообщения или свой раздел в меню навигации мессенджера.

Для регистрации виджета используйте метод [placement.bind](../placement-bind.md) и передавайте нужный код в параметре `PLACEMENT`.

> Быстрый переход: [все точки встраивания](#all-placements)

## Как выбрать точку встраивания

Выбор точки встраивания зависит от того, с чем пользователь будет работать в интерфейсе чата.

- запускать действие во время работы с текущим чатом — [IM_TEXTAREA](./textarea.md)
- показать отдельный экран с дополнительной информацией или инструментами по чату — [IM_SIDEBAR](./sidebar.md)
- привязать действие к конкретному сообщению чата — [IM_CONTEXT_MENU](./context-menu.md)
- открыть отдельный раздел мессенджера, не привязанный к чату — [IM_NAVIGATION](./navigation.md)

Чат мобильного приложения — отдельная точка [IMMOBILE_CONTEXT_MENU](../mobile-app.md): она тоже получает `dialogId`, но живет в мобильном мессенджере и в вебе не выводится.

## Как начать работу

1. Выберите точку встраивания под ваш сценарий: панель ввода, сайдбар, меню сообщения или меню навигации.
2. Зарегистрируйте обработчик методом [placement.bind](../placement-bind.md) и передайте нужный код в параметре `PLACEMENT`. Метод доступен только администратору и требует контекст приложения: вебхуком точку не привязать. При успешной регистрации метод возвращает `result: true` — разбор ответа и коды ошибок есть на его странице.
3. Передайте в `OPTIONS` имя иконки, если точка его требует, и ограничения показа, если они нужны.
4. Завершите установку приложения. До этого виджет в интерфейсе не отображается.
5. Откройте чат и вызовите виджет.
6. Разберите `PLACEMENT_OPTIONS` в обработчике, чтобы получить контекст вызова: идентификатор текущего чата или сообщения, если точка их передает.
7. Если нужно, используйте полученные идентификаторы для вызова REST API или открытия дополнительного интерфейса.

## Что получает обработчик

Данные передаются POST-запросом: часть параметров — в query-строке адреса обработчика, остальные — в теле запроса {.b24-info}

Пример показан для панели над полем ввода. У остальных точек меняются только значение `PLACEMENT` и контекст вызова в `PLACEMENT_OPTIONS` — их состав приведен в таблице ниже.

```php
Array
(
    [DOMAIN] => xxx.bitrix24.com
    [PROTOCOL] => 1
    [LANG] => ru
    [APP_SID] => 99c80eff6378726287350416ee5fef0
    [AUTH_ID] => 6061e72600631fcd00005a4b00000001f0f1076700000000f69dd5fc643d9ce2fdbc1
    [AUTH_EXPIRES] => 3600
    [REFRESH_ID] => 50e00aa340631fcd00005a4b00000001f0f1071111116580a5b83c2de639ef28c12
    [SERVER_ENDPOINT] => https://oauth.bitrix24.tech/rest/
    [APPLICATION_TOKEN] => ec1b2074a9d3f5c81b6e40d27a95cf38
    [APPLICATION_SCOPE] => im,placement
    [member_id] => da45a03b265ed12127f8a258d793cc5d
    [status] => L
    [PLACEMENT] => IM_TEXTAREA
    [PLACEMENT_OPTIONS] => {"dialogId":"chat1","URI":"\/online\/"}
)
```

Строка `PLACEMENT_OPTIONS` из этого примера после разбора выглядит так:

```json
{
    "dialogId": "chat1",
    "URI": "/online/"
}
```

### PLACEMENT_OPTIONS

Значение `PLACEMENT_OPTIONS` передается как JSON-строка с контекстом вызова.

#|
|| **Точка встраивания** | **Ключи** | **Описание** ||
|| [IM_TEXTAREA](./textarea.md) | `dialogId`, `URI` | Идентификатор текущего чата ||
|| [IM_SIDEBAR](./sidebar.md) | `dialogId`, `URI` | Идентификатор текущего чата ||
|| [IM_CONTEXT_MENU](./context-menu.md) | `dialogId`, `messageId`, `URI` | Идентификатор текущего чата и выбранного сообщения ||
|| [IM_NAVIGATION](./navigation.md) | `URI` | Виджет открывается для мессенджера целиком, а не для конкретного чата ||
|#

Ключ `URI` приходит всем точкам веб-мессенджера и содержит адрес страницы, с которой открыт виджет, — для мессенджера это `/online/`. Мобильная точка `IMMOBILE_CONTEXT_MENU` его не получает: там виджет открывается отдельной страницей, а не фреймом внутри интерфейса.

## OPTIONS при регистрации через placement.bind

Точки мессенджера принимают параметр `OPTIONS` метода [placement.bind](../placement-bind.md). Набор поддерживаемых ключей у точек разный.

#|
|| **Точка встраивания** | **Поддерживаемые ключи `OPTIONS`** ||
|| [IM_TEXTAREA](./textarea.md) | `iconName`*, `extranet`, `context`, `role`, `color`, `width`, `height` ||
|| [IM_SIDEBAR](./sidebar.md) | `iconName`*, `extranet`, `context`, `role`, `color` ||
|| [IM_CONTEXT_MENU](./context-menu.md) | `extranet`, `context`, `role` ||
|| [IM_NAVIGATION](./navigation.md) | `iconName`*, `extranet`, `role` ||
|#

Ключ со звездочкой обязателен: без `iconName` метод `placement.bind` возвращает ошибку `ERROR_ARGUMENT`.

Ключ `context` ограничивает показ типом чата. Возможные значения: `ALL` — все чаты, `USER` — личные чаты пользователей, кроме чатов с ботами, `CHAT` — групповые чаты, кроме `LINES` и `CRM`, `LINES` — чаты открытых линий, `CRM` — чаты, созданные в рамках CRM. Несколько значений передаются через `;`. Точка `IM_NAVIGATION` этот ключ не поддерживает: пункт навигации не привязан к чату.

Ключи `role` и `extranet` определяют, каким категориям пользователей доступен виджет. Полное описание всех ключей с типами и значениями по умолчанию — на странице каждой точки.

В таблице перечислены действующие точки. Архивная `IM_SMILES_SELECTOR` принимает `context`, `role` и `extranet`, но обработчик для нее не вызывается — [подробнее на ее странице](./smile-selector.md).

## Связь с другими объектами

**Чат.** Параметр `dialogId` в `PLACEMENT_OPTIONS` указывает, для какого чата был вызван обработчик. Получить информацию о чате по идентификатору можно методом [im.dialog.get](../../chats/im-dialog-get.md).

**Пользователь.** Для личной переписки `dialogId` равен идентификатору собеседника, поэтому его данные вернет метод [user.get](../../user/user-get.md).

**Сообщение.** Параметр `messageId` указывает, для какого сообщения чата был вызван обработчик. Приходит только в точке `IM_CONTEXT_MENU`. По этому идентификатору приложение работает с сообщением [методами раздела](../../chats/messages/index.md) — например, обновляет его методом [im.message.update](../../chats/messages/im-message-update.md) или удаляет методом [im.message.delete](../../chats/messages/im-message-delete.md).

## Типовые ошибки

#|
|| **Ошибка** | **Как решить** ||
|| `placement.bind` возвращает `WRONG_AUTH_TYPE` с описанием `Application context required` | Регистрируйте точку от имени приложения. Вебхуком точку не привязать ||
|| `placement.bind` возвращает `ERROR_ARGUMENT` | Не передан обязательный параметр. Для `IM_TEXTAREA`, `IM_SIDEBAR` и `IM_NAVIGATION` в `OPTIONS` обязателен `iconName`. Код незаполненного поля приходит в `argument` ||
|| Виджет не отображается после регистрации | Завершите установку приложения и повторно откройте чат ||
|| Виджет не появляется в интерфейсе, потому что сценарий проверяют вне чата | Проверяйте встраивание только в интерфейсе чата ||
|| Регистрация через `placement.bind` завершается ошибкой из-за неверного значения `OPTIONS.context` | Используйте только допустимые значения `ALL`, `USER`, `CHAT`, `LINES`, `CRM` ||
|| Ограничение по `context` работает не так, как ожидалось, потому что вместе с другими значениями передан `ALL` | Передавайте только `ALL` или список конкретных контекстов через `;` ||
|#

Ошибка приходит в теле ответа — код в поле `error`, текст в `error_description`:

```json
{
    "error": "WRONG_AUTH_TYPE",
    "error_description": "Current authorization type is denied for this method Application context required"
}
```

Другие коды ошибок регистрации перечислены в разделе «Возможные коды ошибок» страницы [placement.bind](../placement-bind.md).

## Обзор точек встраивания {#all-placements}

> Scope: [`placement, im`](../../scopes/permissions.md)

Скоуп `placement` нужен, чтобы зарегистрировать обработчик. Чтобы работать с чатом из виджета — например, получить его по `dialogId` из контекста вызова — приложению нужен еще и скоуп `im`. Исключение — архивная `IM_SMILES_SELECTOR`: она объявлена в глобальном скоупе `placement` и второго скоупа не требует.

#|
|| **Точка встраивания** | **Когда использовать** ||
|| [IM_TEXTAREA](./textarea.md) | Пункт в панели над полем ввода ||
|| [IM_SIDEBAR](./sidebar.md) | Пункт в боковой панели чата ||
|| [IM_CONTEXT_MENU](./context-menu.md) | Пункт в контекстном меню сообщения ||
|| [IM_NAVIGATION](./navigation.md) | Пункт в меню навигации мессенджера ||
|| [IM_SMILES_SELECTOR](./smile-selector.md) | Архивная страница устаревшей точки. Не используйте для новых интеграций ||
|#
