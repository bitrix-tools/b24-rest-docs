# Виджеты в задачах: обзор точек встраивания

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Точки встраивания добавляют интерфейс приложения в задачи: пункт в контекстном меню, пункт в выпадающем меню над списком, кнопку в дизайнере роботов и свой экран в карточке.

Для регистрации виджета используйте метод [placement.bind](../placement-bind.md) и передавайте нужный код в параметре `PLACEMENT`.

> Быстрый переход: [все точки встраивания](#all-placements)

## Как выбрать точку встраивания

Выбирайте точку по задаче, которую решает приложение:

- добавить действие над отдельной задачей из списка — [TASK_LIST_CONTEXT_MENU](./list-context-menu.md)
- добавить действие над списком задач целиком — [TASK_USER_LIST_TOOLBAR и TASK_GROUP_LIST_TOOLBAR](./list-toolbar.md)
- добавить свою кнопку в дизайнер роботов задач — [TASK_ROBOT_DESIGNER_TOOLBAR](./robot-designer-toolbar.md)
- добавить свой экран в карточку задачи — [TASK_VIEW_TAB](./view-tab.md), [TASK_VIEW_SIDEBAR](./view-sidebar.md) или [TASK_VIEW_TOP_PANEL](./view-top-panel.md)

{% note info "" %}

Начиная с версии 25.700.0 модуля `tasks` задачи открываются в [новой карточке](../../tasks/tasks-new.md). Отдельного места у трех точек карточки в ней не осталось: все три выводятся одинаковыми строками в блоке *Приложения* и получают один и тот же `taskId`. Для новой интеграции достаточно одной точки из трех: каждая зарегистрированная точка добавляет еще одну строку.

{% endnote %}

Точки меню самой рабочей группы или проекта описаны в разделе рабочих групп: [SONET_GROUP_DETAIL_TAB](../workgroups/detail-tab.md) и [SONET_GROUP_TOOLBAR](../workgroups/toolbar.md) требуют скоуп `sonet_group` и вызываются из меню группы, а не из задач. Там же описана точка [SONET_GROUP_ROBOT_DESIGNER_TOOLBAR](../workgroups/robot-designer-toolbar.md): она выводится в том же дизайнере роботов, что и `TASK_ROBOT_DESIGNER_TOOLBAR`, но только когда дизайнер открыт из проекта.

## Как начать работу

1. Выберите точку встраивания под сценарий. Метод [placement.list](../placement-list.md) возвращает коды, доступные приложению в конкретном Битрикс24.
2. Зарегистрируйте обработчик методом [placement.bind](../placement-bind.md) и передайте код в параметре `PLACEMENT`. При успешной регистрации метод возвращает `result: true` — разбор ответа и коды ошибок есть на его странице.
3. Ограничьте вывод конкретными проектами, если это нужно. Параметр `groupId` поддерживают только `TASK_VIEW_TAB` и `TASK_VIEW_SIDEBAR` — см. [OPTIONS при регистрации](#options).
4. Завершите установку приложения. До этого виджет в интерфейсе не отображается.
5. Откройте место в интерфейсе и вызовите виджет. Где именно находится пункт, описано на странице каждой точки в разделе «Где находится в интерфейсе».
6. Разберите в обработчике `PLACEMENT_OPTIONS` — в нем приходит контекст вызова: идентификатор задачи, пользователя или проекта, а также адрес страницы, с которой открыт виджет.

## Что получает обработчик

Всем точкам раздела Битрикс24 передает один и тот же набор стандартных параметров. Различается только контекст вызова в `PLACEMENT_OPTIONS`.

Данные передаются POST-запросом: часть параметров — в query-строке адреса обработчика, остальные — в теле запроса {.b24-info}

```php

Array
(
    [DOMAIN] => xxx.bitrix24.com
    [PROTOCOL] => 1
    [LANG] => ru
    [APP_SID] => 0063a02ba25315469678f946ece50010
    [AUTH_ID] => 9c52ba6600705a0700005a4b00000001f0f107e81691773d119eb941ad045e36
    [AUTH_EXPIRES] => 3600
    [REFRESH_ID] => 8cd1e16600705a0700005a4b00000001f0f1070aef2cbe270a6f27bcaf791e45
    [SERVER_ENDPOINT] => https://oauth.bitrix24.tech/rest/
    [APPLICATION_TOKEN] => 3f0a7c19e5b84d2196c8ad470e5f2b31
    [APPLICATION_SCOPE] => task,placement
    [member_id] => da45a03b265edd8787f8a258d793cc5d
    [status] => L
    [PLACEMENT] => TASK_VIEW_TAB
    [PLACEMENT_OPTIONS] => {"taskId":"3957","URI":"\/company\/personal\/user\/1\/tasks\/task\/view\/3957\/"}
)

```

Строка `PLACEMENT_OPTIONS` из этого примера после разбора выглядит так:

```json
{
    "taskId": "3957",
    "URI": "/company/personal/user/1/tasks/task/view/3957/"
}
```

### PLACEMENT_OPTIONS

Значение `PLACEMENT_OPTIONS` передается как JSON-строка с контекстом вызова. Универсальный ключ `URI` приходит у всех точек, состав остальных ключей у каждой точки свой.

#|
|| **Точка встраивания** | **Собственные ключи** | **Что передается** ||
|| [TASK_LIST_CONTEXT_MENU](./list-context-menu.md) | `ID` | Идентификатор задачи, из меню которой открыт виджет ||
|| [TASK_USER_LIST_TOOLBAR](./list-toolbar.md) | `USER_ID` | Идентификатор пользователя, над списком задач которого открыт виджет ||
|| [TASK_GROUP_LIST_TOOLBAR](./list-toolbar.md) | `GROUP_ID` | Идентификатор группы или проекта, над списком задач которого открыт виджет ||
|| [TASK_ROBOT_DESIGNER_TOOLBAR](./robot-designer-toolbar.md) | `USER_ID` или `GROUP_ID` | Контекст автоматизации: личный план пользователя или проект ||
|| [TASK_VIEW_TAB](./view-tab.md) | `taskId` | Идентификатор задачи, из карточки которой открыт виджет ||
|| [TASK_VIEW_SIDEBAR](./view-sidebar.md) | `taskId` | Идентификатор задачи, из карточки которой открыт виджет ||
|| [TASK_VIEW_TOP_PANEL](./view-top-panel.md) | `taskId` | Идентификатор задачи, из карточки которой открыт виджет ||
|#

## OPTIONS при регистрации через placement.bind {#options}

Параметры подключения передают в `OPTIONS` метода [placement.bind](../placement-bind.md). Это не те данные, которые Битрикс24 передает обработчику при вызове точки. В разделе задач параметры подключения поддерживает только одна пара точек.

#|
|| **Точка встраивания** | **Ключи `OPTIONS`** ||
|| [TASK_VIEW_TAB](./view-tab.md#options), [TASK_VIEW_SIDEBAR](./view-sidebar.md#options) | `groupId` — идентификаторы проектов через запятую, например `129,130`. Пустое значение или отсутствие параметра означает вывод во всех задачах ||
|| Остальные точки раздела | `groupId` не объявлен ||
|#

## Связь с другими объектами

**Задача.** Ключ `ID` в контекстном меню списка и ключ `taskId` в карточке указывают, для какой задачи вызван обработчик. Данные задачи возвращает метод [tasks.task.get](../../tasks/tasks-task-get.md).

**Пользователь.** Ключ `USER_ID` указывает, чей список задач или чей личный план открыт. Данные пользователя возвращает метод [user.get](../../user/user-get.md).

**Рабочая группа и проект.** Ключ `GROUP_ID` указывает, к какой группе относится список задач или автоматизация. Данные группы возвращает метод [sonet_group.get](../../sonet-group/sonet-group-get.md).

## Типовые ошибки

#|
|| **Ошибка** | **Как решить** ||
|| `placement.bind` возвращает `WRONG_AUTH_TYPE` с описанием `Application context required` | Регистрируйте точку от имени приложения. Вебхуком точку не привязать ||
|| Виджет зарегистрирован, но в интерфейсе не появляется | Завершите [установку приложения](../../../settings/app-installation/installation-finish.md) и перезагрузите страницу ||
|| `placement.bind` возвращает `ERROR_PLACEMENT_NOT_FOUND` | Сверьте код с таблицей [Обзор точек встраивания](#all-placements) и проверьте, выдан ли приложению скоуп `task` ||
|| `placement.bind` возвращает `ERROR_ARGUMENT` | Проверьте обязательные параметры и их типы. Имя некорректного параметра приходит в поле `argument` ||
|| Обработчик не находит идентификатор задачи | Читайте идентификатор из ключа `ID` в контекстном меню списка и из `taskId` в карточке задачи ||
|#

Другие коды ошибок регистрации перечислены в разделе «Возможные коды ошибок» страницы [placement.bind](../placement-bind.md).
