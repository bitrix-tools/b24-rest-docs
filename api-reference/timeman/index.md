Методы учета рабочего времени помогают приложению управлять рабочим днем сотрудника, получать его рабочий график, отчеты об отсутствиях и записи о рабочем времени. Например, интеграция с системой пропусков может открывать рабочий день, когда сотрудник проходит турникет на входе, и закрывать на выходе.

> Быстрый переход: [все методы](#all-methods)
>
> Пользовательская документация: [Время и отчеты в Битрикс24](https://helpdesk.bitrix24.ru/open/17832334/)

## Как начать работу

1. Определите сценарий интеграции: управление текущим рабочим днем, чтение графика, контроль отсутствий, проверка офисной сети или получение записей рабочего времени
2. Для запуска, паузы, закрытия и проверки текущего рабочего дня используйте методы [Рабочий день](./base/index.md)
3. Для получения настроек графика используйте метод [Рабочий график](./schedule/index.md)
4. Для настройки контроля времени и получения отчетов о выявленных отсутствиях используйте методы [Контроль времени](./timecontrol/index.md)
5. Для проверки IP-адресов офисной сети используйте методы [Офисные сети](./networkrange/index.md)
6. Для выборки записей о рабочем времени в REST 3.0 используйте методы [Записи о рабочем времени](./record/index.md)

Если в Битрикс24 выключен инструмент «Учет рабочего времени», методы рабочего дня, графика, контроля времени и офисных сетей, а также метод [timeman.record.list](./record/timeman-record-list.md) вернут ошибку `TIMEMAN_TOOL_DISABLED`.

## Рабочий день

Учет рабочего времени фиксирует отработанные часы сотрудника. Для этого сотрудник отмечает начало и конец рабочего дня в системе. Управлять рабочим днем можно методами раздела [Рабочий день](./base/index.md).

Рабочий день обычно проходит так:

1. Проверьте, открыт ли день, методом [timeman.status](./base/timeman-status.md)
2. Начните день методом [timeman.open](./base/timeman-open.md)
3. Поставьте паузу методом [timeman.pause](./base/timeman-pause.md)
4. Продолжите работу тем же методом [timeman.open](./base/timeman-open.md)
5. Закройте день методом [timeman.close](./base/timeman-close.md)

## Рабочий график

Рабочий график задает режим и продолжительность работы сотрудников. Получить настройки рабочего графика можно методом [timeman.schedule.get](./schedule/timeman-schedule-get.md).

## Контроль времени

Контроль времени фиксирует, когда сотрудник в рабочее время был офлайн или в статусе «Отошел». Руководитель смотрит отчет об отсутствиях за месяц, а сотрудник может указать причину каждого отсутствия.

Работать с отчетами и настраивать контроль времени можно с помощью группы методов [timeman.timecontrol.*](./timecontrol/index.md).

## Офисные сети

Офисная сеть — это диапазоны IP-адресов локальной сети организации. Диапазоны задают и проверяют методы группы [timeman.networkrange.*](./networkrange/index.md).

Методы офисных сетей связаны с контролем времени: в отчетах о выявленных отсутствиях можно проверить, был ли сотрудник в офисной сети в момент начала или завершения рабочего дня.

## Записи о рабочем времени

В [REST 3.0](../rest-v3.md) появились методы [timeman.record.*](./record/index.md). Они возвращают записи о рабочем времени сотрудника и описание полей записи. Методы вызывают по адресу `/rest/api/`.

Записи рабочего времени показывают, когда сотрудник начал и завершил рабочий день, сколько времени заняли перерывы и сколько часов было отработано за выбранный период. Эти данные помогают анализировать рабочую нагрузку, отслеживать незакрытые или неподтвержденные дни и сверять фактически отработанное время.

## Связь с другими объектами

Методы учета рабочего времени работают с сотрудниками и подразделениями Битрикс24.

**Пользователь.** Сотрудника передают в параметре `USER_ID`, а в методе [timeman.record.list](./record/timeman-record-list.md) — в поле фильтра `userId`. Идентификатор сотрудника возвращает метод [user.get](../user/user-get.md).

**Подразделение.** Метод [timeman.timecontrol.reports.users.get](./timecontrol/timeman-timecontrol-reports-users-get.md) получает сотрудников подразделения по параметру `DEPARTMENT_ID`. Идентификатор подразделения возвращает метод [department.get](../departments/department-get.md).

## Права доступа {#access}

Права зависят от того, чьи данные получает или меняет метод:

- любой пользователь — свой рабочий день, свои настройки рабочего времени и причины своих отсутствий
- пользователь с правом «Чтение всех рабочих графиков» — рабочий график. Сотрудники получают это право по умолчанию
- пользователь с правом «Открытие/закрытие чужого рабочего дня» или «Редактирование всех записей» — рабочий день и настройки другого сотрудника. Руководитель отдела без одного из этих прав управлять днем подчиненного не может
- пользователь с правом «Чтение в соответствии с настройками субординации» — свои записи о рабочем времени, а руководитель отдела — еще и записи своих подчиненных
- пользователь с правом «Чтение всех записей» — записи о рабочем времени любого сотрудника
- руководитель отдела — отчеты контроля времени по своим подчиненным
- администратор — отчеты по любому сотруднику, настройки контроля времени, диапазоны офисной сети и проверка IP-адреса. В облачном Битрикс24 с настройками контроля времени, диапазонами офисной сети и проверкой IP-адреса работает и интегратор
- пользователь, которому в настройках контроля времени открыт полный отчет, — отчеты по любому сотруднику
- пользователь, которому открыт простой отчет, — свой отчет

Пользователь, которому отчет открыт в настройках контроля времени, видит его, только пока контроль включен. Руководитель и администратор видят отчеты и при выключенном контроле.

Как авторизовать запросы, описано в статье [Авторизация в REST](../../settings/how-to-call-rest-api/authorization.md), ограничения на частоту запросов — в статье [Лимиты REST API](../../settings/performance/limits.md).
