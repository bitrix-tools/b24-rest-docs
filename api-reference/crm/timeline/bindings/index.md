# Связи записей таймлайна с элементами CRM: обзор методов

Группа методов `crm.timeline.bindings.*` управляет связями записи таймлайна с элементами CRM. Связь определяет, в таймлайне каких элементов показывается запись: одна запись может быть связана сразу с несколькими элементами.

Например, комментарий из лида нужно показать в таймлайне сделки — для этого запись связывают со сделкой и снимают связь с лидом.

## Как начать работу

1. Получите `OWNER_ID` методом [crm.timeline.comment.add](../comments/crm-timeline-comment-add.md) или [crm.timeline.logmessage.add](../logmessage/crm-timeline-logmessage-add.md) — это идентификатор самой записи таймлайна, а не элемента CRM
2. Определите элемент CRM, с которым связываете запись: его тип `ENTITY_TYPE` и идентификатор `ENTITY_ID`
3. Проверьте структуру полей связи методом [crm.timeline.bindings.fields](./crm-timeline-bindings-fields.md)
4. Добавьте связь записи таймлайна с элементом CRM методом [crm.timeline.bindings.bind](./crm-timeline-bindings-bind.md)
5. Проверьте текущие связи записи таймлайна методом [crm.timeline.bindings.list](./crm-timeline-bindings-list.md) с фильтром `OWNER_ID`
6. Удалите нужную связь методом [crm.timeline.bindings.unbind](./crm-timeline-bindings-unbind.md)

## Особенности работы методов

- Связь с элементом, в котором создана запись таймлайна, появляется автоматически. Методы раздела добавляют и удаляют любые связи, включая эту.
- Чтение связей доступно любому пользователю. Для добавления и удаления нужно право на изменение элемента CRM из `ENTITY_ID`.
- Метод [crm.timeline.bindings.list](./crm-timeline-bindings-list.md) возвращает связи только одной записи таймлайна и отдает их страницами по 50.

## Связь с другими объектами

Методы раздела соединяют два объекта — запись таймлайна и элемент CRM, а у дел для этого своя группа методов.

**Записи таймлайна.** Все методы раздела принимают идентификатор записи таймлайна `OWNER_ID`. Сами записи создают, изменяют и перечисляют методы разделов [Комментарии таймлайна](../comments/index.md) и [Журнал лог-записей](../logmessage/index.md).

**Элементы CRM.** Элемент CRM задают парой значений: тип `ENTITY_TYPE` и идентификатор `ENTITY_ID`. В `ENTITY_TYPE` передают символьный код типа объекта CRM `entityTypeName`, например `deal`. Допустимые коды перечислены на страницах методов, общее устройство кодов — в разделе [Тип объекта CRM](../../data-types.md#object_type).

Идентификатор `ENTITY_ID` возвращает универсальный метод [crm.item.list](../../universal/crm-item-list.md) — он работает с лидами, сделками, контактами, компаниями, предложениями, счетами и смарт-процессами. Для дел идентификатор возвращает метод [crm.activity.list](../activities/activity-base/crm-activity-list.md), для заказов — методы раздела [Заказ в Интернет-магазине](../../../sale/order/index.md).

**Дела.** Не путайте связи записи таймлайна со связями дела. Привязкой дела к элементам CRM управляет отдельная группа методов [crm.activity.binding.*](../activities/binding/index.md).
