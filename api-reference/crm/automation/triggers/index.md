# Триггеры автоматизации CRM: обзор методов

Триггеры автоматизации CRM помогают приложению передавать внешние события в CRM. Если для объекта настроен триггер приложения, событие может перевести его на нужную стадию или в статус.

Например, приложение телефонии регистрирует триггер «Звонок завершен», администратор привязывает его к стадии «В работе», и после звонка приложение переводит сделку на эту стадию. Методы ниже позволяют зарегистрировать триггер, получить список триггеров приложения, отправить событие в автоматизацию CRM и удалить ненужный триггер.

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

## Как начать работу

1. Зарегистрируйте триггер методом [crm.automation.trigger.add](./crm-automation-trigger-add.md)

2. Привяжите зарегистрированный триггер к нужной стадии или статусу в настройках автоматизации CRM, в разделе «Роботы и триггеры». Методов для привязки нет

3. При необходимости получите список триггеров приложения методом [crm.automation.trigger.list](./crm-automation-trigger-list.md)

4. Подготовьте идентификаторы объекта CRM: `OWNER_TYPE_ID` и `OWNER_ID`

5. Запустите триггер методом [crm.automation.trigger.execute](./crm-automation-trigger-execute.md) и проверьте стадию объекта методом [crm.item.get](../../universal/crm-item-get.md)

6. Когда триггер больше не нужен, удалите его методом [crm.automation.trigger.delete](./crm-automation-trigger-delete.md) и уберите привязку в настройках автоматизации

## Ключевые параметры

**CODE.** Идентификатор триггера внутри приложения. Приложение задает его при регистрации триггера в методе [crm.automation.trigger.add](./crm-automation-trigger-add.md). Затем этот идентификатор используют в методах [crm.automation.trigger.execute](./crm-automation-trigger-execute.md) и [crm.automation.trigger.delete](./crm-automation-trigger-delete.md).

Если вызвать метод [crm.automation.trigger.add](./crm-automation-trigger-add.md) повторно с тем же `CODE`, он обновит название `NAME` триггера.

**OWNER_TYPE_ID.** Идентификатор типа объекта CRM. Используется в методе [crm.automation.trigger.execute](./crm-automation-trigger-execute.md). Триггеры есть в лидах, сделках, предложениях, счетах и смарт-процессах. Если передать контакт или компанию, триггер сработает для связанных с ними объектов, например сделок.

**OWNER_ID.** Идентификатор конкретного объекта CRM. Используется в методе [crm.automation.trigger.execute](./crm-automation-trigger-execute.md).

## Что важно учитывать

- Метод [crm.automation.trigger.list](./crm-automation-trigger-list.md) возвращает только триггеры текущего приложения, весь список за один вызов. У каждого триггера есть название `NAME` и код `CODE`

- Метод [crm.automation.trigger.execute](./crm-automation-trigger-execute.md) отправляет событие в автоматизацию CRM и возвращает `true`, даже если стадия не сменилась. Стадия сменится, только если к ней привязан триггер текущего приложения с тем же `CODE` и выполнены его условия

- На стадию, которая в воронке раньше текущей, объект перейдет, только если в настройках триггера разрешен переход на предыдущую стадию

- Метод [crm.automation.trigger.delete](./crm-automation-trigger-delete.md) не убирает привязки триггера в настройках автоматизации, они остаются и после удаления приложения. Уберите их вручную: если то же приложение снова зарегистрирует триггер с тем же `CODE`, старая привязка опять начнет срабатывать

## Связь с другими объектами

**Автоматизация CRM.** Зарегистрированный триггер появляется в настройках автоматизации CRM, в разделе «Роботы и триггеры», с названием приложения в квадратных скобках, например «[Телефония] Звонок завершен». Там его привязывают к стадии или статусу. Запуск webhook-триггера, который настраивают без приложения, описан в разделе [Автоматизация CRM](../index.md).

**Объекты CRM.** В методе [crm.automation.trigger.execute](./crm-automation-trigger-execute.md) параметры `OWNER_TYPE_ID` и `OWNER_ID` определяют тип объекта CRM и конкретный объект для запуска триггера. Значение `OWNER_TYPE_ID` можно получить методом [crm.enum.ownertype](../../auxiliary/enum/crm-enum-owner-type.md). Идентификатор `OWNER_ID` получают универсальным методом [crm.item.list](../../universal/crm-item-list.md).
