# Поиск и обработка дубликатов в CRM: обзор методов

Дубликат — это несколько элементов CRM, за которыми стоит один и тот же человек или организация. Первый звонок клиента создает контакт с именем и номером телефона, письмо от него же — второй контакт с именем и адресом электронной почты. Битрикс24 умеет находить такие пары и объединять их в один элемент.

Поиск дубликатов работает только по лидам, контактам и компаниям — и в интерфейсе, и через метод [crm.duplicate.findbycomm](./crm-duplicate-find-by-comm.md). Объединение работает шире: метод [crm.entity.mergeBatch](./crm-entity-merge-batch.md) принимает также сделки, счета, коммерческие предложения и элементы смарт-процессов, если идентификаторы объединяемых элементов вы определили сами.

## Поиск дубликатов через REST

Метод [crm.duplicate.findbycomm](./crm-duplicate-find-by-comm.md) ищет только по телефону и адресу электронной почты. Другие поля этому методу недоступны, даже если они добавлены в настройки поиска дубликатов.

В метод передают тип связи `type` со значением `PHONE` или `EMAIL` и список значений `values`. Необязательный `entity_type` сужает поиск до одного объекта — `LEAD`, `CONTACT` или `COMPANY`. В ответ приходят идентификаторы найденных элементов, сгруппированные по этим же типам.

Метод удобен для выбора элемента CRM. Например, у вас есть [дело с типом «письмо»](../timeline/activities/index.md), поступившее с почты `test@bitrix.com`. Чтобы сохранить письмо в CRM и не создать дубликат, проверьте, есть ли в базе лид, контакт или компания с таким адресом. Один и тот же адрес может быть записан у контакта и у связанной с ним компании — запрос вернет идентификаторы обоих элементов с указанием типов, и вы сможете выбрать, куда прикрепить письмо.

## Объединение дубликатов

Метод [crm.entity.mergeBatch](./crm-entity-merge-batch.md) объединяет несколько элементов одного типа. Можно объединить два лида, но нельзя объединить лид с контактом. Главным становится элемент, чей `id` стоит первым в массиве `entityIds`: в него переносятся данные остальных, а остальные удаляются.

Полное автоматическое объединение доступно в двух случаях:

- элементы идентичны друг другу
- элементы не идентичны, но разница в значениях полей не требует ручной обработки. Например, в одном элементе поле заполнено, а в другом это же поле пустое — сохранится значение из заполненного поля

Если автоматически объединить элементы невозможно, метод вернет статус `CONFLICT`. Причин может быть две:

- в элементах есть заполненные поля с разными значениями. Проверить значения всех полей можно методом `get`, например для лидов — [crm.lead.get](../leads/crm-lead-get.md)
- у пользователя, от имени которого выполняется запрос, нет доступа к одному или нескольким полям

Конфликт разрешают вручную в интерфейсе Битрикс24 — ссылки для каждого типа объекта приведены на странице метода [crm.entity.mergeBatch](./crm-entity-merge-batch.md).

## Настройка поиска дубликатов в интерфейсе

В интерфейсе Битрикс24 сотрудник сам выбирает, по каким полям отбирать дубликаты. По умолчанию доступны:

- **Лиды** — Ф.И.О., название компании, телефон, адрес электронной почты
- **Контакты** — Ф.И.О., телефон, адрес электронной почты, реквизиты и банковские реквизиты
- **Компании** — название компании, телефон, адрес электронной почты, реквизиты и банковские реквизиты

Состав реквизитов зависит от страны. Для России это ИНН, ОГРН, ОГРНИП и расчетный счет.

Этот список можно расширить методами `crm.duplicate.volatileType.*` — добавить стандартные и пользовательские поля. Добавленные поля появятся в настройках поиска у всех сотрудников. Всего можно подключить не более семи дополнительных полей суммарно для лидов, контактов и компаний. Подробности — в разделе [Настройки поиска дубликатов по любым полям](./volatile-type/index.md).

Настройки влияют только на поиск дубликатов в интерфейсе. Метод `crm.duplicate.findbycomm` их не учитывает.
