Методы для работы с этими полями собраны в разделе [Пользовательские поля коммерческих предложений](../index.md).

Подробно работа с событиями описана в статье [Концепция и преимущества обработки событий](../../../../events/index.md).

## Что приходит в обработчик

События пользовательских полей не передают описание поля целиком — в обработчик приходит ключ, по которому поле можно запросить методом.

В `data.FIELDS` приходят три значения:

- `ID` — идентификатор пользовательского поля. По нему полное описание поля возвращает метод [crm.quote.userfield.get](../crm-quote-user-field-get.md)
- `ENTITY_ID` — символьный идентификатор объекта, к которому относится поле. Для коммерческих предложений это всегда `CRM_QUOTE`
- `FIELD_NAME` — полное имя поля с префиксом `UF_CRM_`. Под этим именем значение поля передается в методы [crm.quote.add](../../crm-quote-add.md) и [crm.quote.update](../../crm-quote-update.md)

Все четыре события приходят с одним и тем же набором полей. Различать их нужно по коду события в поле `event`, а не по составу `data.FIELDS`. После удаления поля описание по идентификатору получить уже нельзя.
