# Пользовательские поля контактов: обзор методов и событий

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Пользовательские поля хранят информацию о контакте в различных форматах данных: строка, число, ссылка, адрес и другие. Поле создается один раз и появляется в карточках всех контактов Битрикс24.

{% note warning "" %}

Развитие методов `crm.contact.userfield.*` остановлено. Для новой разработки используйте методы REST 3.0 [crm.contact.field.custom.*](../../rest-v3/fields/index.md). Поля типов «Список» `enumeration` и «Файл» `file` методы REST 3.0 не создают, для них используйте [crm.contact.userfield.add](./crm-contact-userfield-add.md).

{% endnote %}

## Имена пользовательских полей

Имя поля собирает Битрикс24, а не разработчик. К коду, который вы передаете в параметре `FIELD_NAME` метода [crm.contact.userfield.add](./crm-contact-userfield-add.md), при необходимости добавляется префикс `UF_CRM_`: код `MANAGER_NOTE` превращается в имя `UF_CRM_MANAGER_NOTE`. Полные правила преобразования описаны на странице метода.

Полученное имя — это ключ, по которому значение поля записывают и читают в методах контактов, например [crm.contact.add](../crm-contact-add.md) и [crm.contact.list](../crm-contact-list.md). Метод [crm.contact.fields](../crm-contact-fields.md) возвращает пользовательские поля вместе с системными.

## Как начать работу

1. Выберите тип поля. Список типов с идентификаторами для параметра `USER_TYPE_ID` возвращает метод [crm.userfield.types](../../universal/user-defined-fields/crm-userfield-types.md), например `double` — число. Общие характеристики любого поля — обязательность, множественность, сортировку — описывает метод [crm.userfield.fields](../../universal/user-defined-fields/crm-userfield-fields.md).
2. Узнайте настройки типа для параметра `SETTINGS` методом [crm.userfield.settings.fields](../../universal/user-defined-fields/crm-userfield-settings-fields.md), например `PRECISION` — точность числа. Метод `crm.contact.userfield.add` принимает не все настройки типа. Поддерживаемые настройки перечислены на [странице метода](./crm-contact-userfield-add.md#settings).
3. Создайте поле, например типа `string` с кодом `MANAGER_NOTE`, методом [crm.contact.userfield.add](./crm-contact-userfield-add.md). Метод вернет идентификатор поля.
4. Получите имя поля с префиксом `UF_CRM_` методом [crm.contact.userfield.get](./crm-contact-userfield-get.md) по идентификатору из ответа `crm.contact.userfield.add` или найдите его в ответе [crm.contact.userfield.list](./crm-contact-userfield-list.md).
5. Запишите значение в контакт методом [crm.contact.update](../crm-contact-update.md): `"fields": {"UF_CRM_MANAGER_NOTE": "Перезвонить в пятницу"}`. Для поля типа `enumeration` передайте `ID` элемента из массива `LIST`.
6. Прочитайте значение методом [crm.contact.get](../crm-contact-get.md) — оно придет в поле `UF_CRM_MANAGER_NOTE`.

Методы `crm.contact.userfield.*` работают только с полями контактов. Чтобы управлять полями разных объектов одной группой методов, используйте [userfieldconfig.*](../../universal/userfieldconfig/index.md). Выбор между двумя группами методов описан на странице [Пользовательские поля в CRM](../../universal/user-defined-fields/index.md).

Структура объекта пользовательского поля описана в разделе [`userfield`](./crm-contact-userfield-get.md#userfield).

## Ошибки при работе с пользовательскими полями {#errors}

При создании или удалении пользовательских полей запрос может прерваться с ошибкой [INTERNAL_SERVER_ERROR](../../../../error-codes.md). Это внутренняя ошибка сервера. Причину можно найти в логах сервера на момент выполнения запроса.

* В облачном Битрикс24 напишите обращение в [техническую поддержку](../../../../bitrix-support.md), чтобы получить детали ошибки.
* В коробочном Битрикс24 запросите лог ошибок сервера у администратора сервера или администратора хостинга, затем напишите в [техническую поддержку](../../../../bitrix-support.md) и приложите лог для анализа.

### Частые причины серверных ошибок

1. Для контактов можно создать 1016 пользовательских полей — это ограничение архитектуры базы данных. Если в Битрикс24 уже есть 1016 полей для контактов, при попытке создать новое поле метод [crm.contact.userfield.add](./crm-contact-userfield-add.md) вернет ошибку `INTERNAL_SERVER_ERROR`.

    Проверить количество пользовательских полей контактов можно методом [crm.contact.userfield.list](./crm-contact-userfield-list.md).

2. На серверах есть ограничение для времени выполнения одного запроса — `max_execution_time`. Стандартное время — 60 секунд. Если запрос выполняется дольше, он прерывается с ошибкой `INTERNAL_SERVER_ERROR`.

    Время [создания](./crm-contact-userfield-add.md) или [удаления](./crm-contact-userfield-delete.md) пользовательского поля контактов зависит от количества контактов. Когда поле создается, оно добавляется во все карточки контактов. При удалении поле исчезает из всех карточек.

    Чтобы проверить количество контактов, используйте метод [crm.contact.list](../crm-contact-list.md).

## Обзор методов и событий {#all-methods}

События уведомляют о настройке самих полей, а не об изменении их значений в контактах. Как подписаться на них, описано на странице [событий пользовательских полей контактов](./events/index.md).

> Scope: [`crm`](../../../scopes/permissions.md)
>
> Кто может выполнять метод: в зависимости от метода. Создавать, изменять и удалять поле может пользователь с правом «Разрешить изменять настройки» в CRM. Получить поле и список полей может любой пользователь с правом на чтение контактов. Подписаться на события может любой пользователь, для офлайн-событий нужны права администратора
