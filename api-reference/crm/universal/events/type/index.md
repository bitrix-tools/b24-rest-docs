# Обзор событий при работе с пользовательскими типами CRM

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

События дают возможность приложениям реагировать на изменения практически в реальном времени: получать уведомления о добавлении, обновлении или удалении пользовательских типов CRM.

Пользовательский тип CRM — это [смарт-процесс](../../user-defined-object-types/index.md). События раздела срабатывают, когда создается, изменяется или удаляется сам смарт-процесс. Изменения элементов внутри смарт-процесса отслеживают события раздела [События элементов смарт-процессов](../index.md), а изменения пользовательских полей — [события настроек пользовательских полей](../../userfieldconfig/events/index.md).

Подробно работа с событиями описана в статье [Концепция и преимущества обработки событий](../../../../events/index.md).

> Быстрый переход: [все события](#all-events)

## Что приходит в обработчик

Во всех событиях раздела обработчик получает объект `data.FIELDS` с единственным ключом `ID`. В нем приходит первичный ключ записи типа, а не `entityTypeId` смарт-процесса.

Сокращенный пример тела POST-запроса для `onCrmTypeAdd`. Полный состав `auth` приведен на [странице события](on-crm-type-add.md#auth).

```json
{
    "event": "ONCRMTYPEADD",
    "event_handler_id": "7",
    "data": {
        "FIELDS": {
            "ID": "45"
        }
    },
    "ts": "1723545943",
    "auth": {
        "scope": "crm",
        "domain": "some-domain.bitrix24.com"
    }
}
```

Токены авторизации в `auth` могут отсутствовать. Если обработчик работает в приложении, проверяйте `auth` и храните авторизацию, полученную при установке приложения, для последующих вызовов методов.

Чтобы получить `entityTypeId` и остальные настройки, передайте это значение как `id` в метод [crm.type.get](../../user-defined-object-types/crm-type-get.md). Для вызова нужны права на чтение смарт-процесса или административный доступ к нему. Для события удаления данные типа уже недоступны — сопоставляйте `ID` с тем, что вы сохранили в своей системе раньше.

Например, приложение синхронизирует свой список смарт-процессов с Битрикс24. Сначала оно получает существующие типы методом [crm.type.list](../../user-defined-object-types/crm-type-list.md) — для этого нужен административный доступ к CRM. После `onCrmTypeAdd` приложение получает `data.FIELDS.ID`, вызывает `crm.type.get` с этим значением в параметре `id` и сохраняет настройки вместе с `ID`. После `onCrmTypeUpdate` оно повторяет запрос и обновляет запись. После `onCrmTypeDelete` — удаляет запись из своего списка по сохраненному `ID`.
