Методы `crm.category.*` управляют воронками. Воронка — это отдельная ветка работы с объектом CRM со своим набором стадий и своими настройками карточки.

Воронки используют, чтобы разделить работу по отделам или типам продаж. Чаще всего их настраивают для сделок и смарт-процессов.

{% note warning "DEPRECATED" %}

Развитие методов `crm.category.*` остановлено. Для поддерживаемых объектов используйте [методы работы с воронками REST 3.0](../../rest-v3/categories/index.md). Для воронок счетов, документов CRM и документов КЭДО пока используйте `crm.category.*`.

{% endnote %}

## Какие объекты поддерживают воронки

Объект, для которого нужна воронка, задается параметром `entityTypeId`. Воронки поддерживают не все объекты CRM.

#|
|| **Объект** | **`entityTypeId`** ||
|| Сделка | `2` ||
|| Контакт | `3` ||
|| Компания | `4` ||
|| Счет | `31` ||
|| Документ CRM | `36` ||
|| Документ КЭДО | `39` ||
|| Смарт-процесс | от `128` ||
|#

Идентификатор смарт-процесса возвращает метод [crm.type.list](../user-defined-object-types/crm-type-list.md), полная таблица типов — в справочнике [типов объектов CRM](../../data-types.md#object_type). Для объекта без поддержки воронок, например лида, методы `crm.category.*` вернут ошибку `ENTITY_TYPE_NOT_SUPPORTED`.

## Как начать работу

Для объектов, которые поддерживает REST 3.0, начните с [методов работы с воронками REST 3.0](../../rest-v3/categories/index.md). Шаги ниже — для `crm.category.*`.

1. Определите `entityTypeId` объекта, для которого нужна воронка.
2. Создайте воронку методом [crm.category.add](./crm-category-add.md) или найдите подходящую среди существующих методом [crm.category.list](./crm-category-list.md).
3. При необходимости настройте стадии выбранной воронки группой методов [crm.status.*](../../status/index.md): у каждой воронки свой справочник стадий.
4. Привяжите элемент к воронке: передайте `id` воронки как `categoryId` в метод [crm.item.add](../crm-item-add.md) или [crm.item.update](../crm-item-update.md).
5. При необходимости настройте вид карточки для этой воронки группой методов [crm.item.details.configuration.*](../item-details-configuration/index.md).

## Что важно учитывать

**Поля воронки.** Основные поля: `id` — идентификатор, `name` — название, `sort` — порядок сортировки, `entityTypeId` — тип объекта CRM, `isDefault` — признак воронки по умолчанию. Полный состав полей для выбранного типа объекта возвращает [crm.category.fields](./crm-category-fields.md).

**Права доступа.** Метод [crm.category.list](./crm-category-list.md) доступен любому пользователю, но возвращает только те воронки, к которым у пользователя есть права на чтение.

**Воронка по умолчанию.** Поведение `isDefault` зависит от типа объекта: в сделках поле изменить нельзя. Подробности — в описании [создания](./crm-category-add.md#parametr-fields) и [изменения](./crm-category-update.md#parametr-fields) воронки.

**Удаление воронки.** Воронку с элементами удалить нельзя. Остальные ограничения зависят от типа объекта и описаны в методе [crm.category.delete](./crm-category-delete.md).

## Связь с другими объектами

**Смарт-процессы.** Методы `crm.category.*` доступны и при выключенном показе воронок в интерфейсе: опция `isCategoriesEnabled` управляет только их отображением. Проверить настройку и получить `entityTypeId` смарт-процесса можно методом [crm.type.list](../user-defined-object-types/crm-type-list.md).

**Стадии.** Каждая воронка определяет свой справочник стадий с уникальным `ENTITY_ID`. Со стадиями работает группа методов [crm.status.*](../../status/index.md). Идентификаторы справочников возвращает метод [crm.status.entity.types](../../status/crm-status-entity-types.md).

**Карточки сделок.** Настройки карточек сделок зависят от воронки. Чтобы настроить карточку для конкретной воронки, передайте `id` воронки как `dealCategoryId` в методах [crm.deal.details.configuration.get](../../deals/custom-form/crm-deal-details-configuration-get.md) и [crm.deal.details.configuration.set](../../deals/custom-form/crm-deal-details-configuration-set.md).
