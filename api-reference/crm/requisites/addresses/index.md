# Адреса реквизитов CRM: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга

Адреса хранят улицу, город, почтовый индекс и другие данные о местоположении. Например, приложение может сохранить фактический и юридический адреса компании в ее реквизите. У лида реквизитов нет, поэтому его адрес привязан к самому лиду.

> Быстрый переход: [все методы](#all-methods)
>
> Пользовательская документация: [Как добавить реквизиты вашей компании](https://helpdesk.bitrix24.ru/open/24341258/)

## Как начать работу

1. Выберите тип адреса `TYPE_ID` методом [crm.enum.addresstype](../../auxiliary/enum/crm-enum-address-type.md)
2. Определите тип владельца `ENTITY_TYPE_ID` и получите его идентификатор `ENTITY_ID` — источники значений приведены в [таблице полей](#fields)
3. Передайте эти три поля и текст адреса в метод [crm.address.add](./crm-address-add.md)
4. Проверьте сохраненный адрес методом [crm.address.list](./crm-address-list.md), задав в `filter` его `TYPE_ID`, `ENTITY_TYPE_ID` и `ENTITY_ID`
5. Для изменения или удаления передайте тот же набор идентификаторов в `fields` метода [crm.address.update](./crm-address-update.md) или [crm.address.delete](./crm-address-delete.md)

## Идентификаторы адресов

У адреса CRM нет отдельного поля `ID`. Его определяет сочетание `TYPE_ID`, `ENTITY_TYPE_ID` и `ENTITY_ID`: тип адреса, тип владельца и идентификатор владельца. У одного реквизита может быть несколько адресов разных типов.

Для адреса компании или контакта работайте с реквизитом: в `ENTITY_ID` передайте ID реквизита, а не компании или контакта.

## Результаты методов

Метод [crm.address.list](./crm-address-list.md) возвращает массив адресов в `result`. Каждый элемент содержит поля из таблицы выше. Параметр `select` задает набор полей; если его не передать, метод вернет все доступные поля. Если адресов по фильтру нет, `result` будет пустым массивом `[]`.

Методы [crm.address.add](./crm-address-add.md), [crm.address.update](./crm-address-update.md) и [crm.address.delete](./crm-address-delete.md) возвращают `true` в `result` при успешном выполнении запроса.

Метод [crm.address.fields](./crm-address-fields.md) возвращает в `result` объект с описаниями полей: их типами, названиями и признаками обязательности, доступности для изменения и другими атрибутами.

{% note warning "Проверяйте сохраненный адрес" %}

Если передать в [crm.address.add](./crm-address-add.md) только `TYPE_ID`, `ENTITY_TYPE_ID` и `ENTITY_ID`, метод вернет `true`, но не создаст адрес. Передайте текстовые поля адреса или `LOC_ADDR_ID` существующего адреса местоположения, затем проверьте результат методом [crm.address.list](./crm-address-list.md).

При обновлении через [crm.address.update](./crm-address-update.md) передавайте все текстовые поля, которые нужно сохранить. Если передать только часть, Битрикс24 очистит остальные текстовые поля адреса CRM.

{% endnote %}

## Обзор методов {#all-methods}

> Scope: [`crm`](../../../scopes/permissions.md)
>
> Кто может выполнять методы: в зависимости от метода — пользователь с правом на добавление, изменение или удаление компании, контакта или лида, к которым относится адрес. Для получения списка нужны права на чтение контактов, компаний и лидов; описание полей может получить любой пользователь
