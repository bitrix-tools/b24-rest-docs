# Поля счета в REST 3.0

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

{% note info "" %}

Поля относятся к методам REST 3.0. Особенности вызова и формат ответа новой версии API описаны в [обзоре REST 3.0](../../../rest-v3.md).

{% endnote %}

Поля счета возвращают методы [crm.smartinvoice.get](./crm-entity-get-rest-v3.md) и [crm.smartinvoice.list](./crm-entity-list-rest-v3.md), а принимают методы [crm.smartinvoice.add](./crm-entity-add-rest-v3.md) и [crm.smartinvoice.update](./crm-entity-update-rest-v3.md). Значения множественных полей по одному добавляют и удаляют методы [crm.smartinvoice.addfieldvalue](./crm-entity-add-field-value-rest-v3.md) и [crm.smartinvoice.deletefieldvalue](./crm-entity-delete-field-value-rest-v3.md). Список полей с признаками возвращает метод [crm.smartinvoice.field.list](../fields/crm-entity-field-list-rest-v3.md).

Методы `crm.smartinvoice.*` работают со счетами нового типа, у которых `entityTypeId = 31`. Товары счета хранятся отдельно от полей, их возвращает метод [crm.smartinvoice.productrow.list](../product-rows/crm-entity-product-row-list-rest-v3.md).

Часть полей существует в двух видах: как идентификатор и как связанный объект, например `assignedById` и `assignedBy`. Идентификатор можно передать при записи, а связанный объект — только запросить в `select`.

## Какие поля принимают и возвращают методы {#methods}

#|
|| **Метод** | **Принимает** | **Возвращает** ||
|| [crm.smartinvoice.add](./crm-entity-add-rest-v3.md) | Поля таблицы [Объект счета](#item), которые можно изменять, и пользовательские поля. Обязательных полей нет: счет создается и с пустым объектом `fields` | Идентификатор созданного счета `id` ||
|| [crm.smartinvoice.update](./crm-entity-update-rest-v3.md) | `id` счета и те же поля, что `add`. Поля, которых нет в `fields`, сохраняют текущие значения | Признак успеха `true` ||
|| [crm.smartinvoice.get](./crm-entity-get-rest-v3.md) | `id` счета и `select` | Без `select` — только `id`. С `select` — только перечисленные поля, `id` не добавляется автоматически. Связанный объект целиком, например `assignedBy`, возвращает все свои поля, а путь через точку, например `assignedBy.firstName`, — только выбранные. Подробнее — в разделе [Связанные объекты](#relations) ||
|| [crm.smartinvoice.list](./crm-entity-list-rest-v3.md) | `select`, `filter`, `order`, `pagination` | Без `select` — только `id` каждого счета. Поля и связанные объекты запрашиваются в `select` так же, как в `get` ||
|| [crm.smartinvoice.addfieldvalue](./crm-entity-add-field-value-rest-v3.md), [crm.smartinvoice.deletefieldvalue](./crm-entity-delete-field-value-rest-v3.md) | `id` счета, имя множественного поля `fieldName` и значение `value`. Подходят поля `contactsId`, `observersId` и множественные пользовательские поля. Для других полей метод вернет ошибку «The field is not supported.» | Признак успеха `true` ||
|#

Поля с пометкой «только чтение» методы `add` и `update` не принимают и возвращают ошибку `BITRIX_REST_V3_EXCEPTION_VALIDATION_DTOVALIDATIONEXCEPTION` с текстом «Поле "taxValue" не доступно к заполнению». Связанные объекты, например `company` и `stage`, тоже только для чтения: для записи передавайте идентификатор — `companyId`, `stageId`.

Поля со значениями из справочников метод проверяет при записи. Если значения нет в справочнике, метод вернет ошибку «Значение поля не содержится в списке допустимых значений». Для стадии, источника и валюты в тексте ошибки перечислены допустимые значения.

Логические поля принимают и возвращают `true` или `false`. Значения `Y`, `N`, `1` и `0` не подходят: метод вернет ошибку «В поле `opened` требуется тип данных `bool` для такого запроса».

Поля типа `date` — `beginTime` и `closeTime` — принимают и возвращают дату в формате `YYYY-MM-DD`, например `2026-11-03`. Дату со временем или в формате `03.11.2026` такое поле не принимает. Поля типа `datetime` возвращаются в формате ISO 8601, например `2026-11-03T14:52:21+03:00`. В фильтре по полю `datetime` тоже передавайте дату со временем.

Фильтровать и сортировать можно только по полям, у которых это указано в описании. На другие поля метод `list` вернет ошибку «требуется наличие атрибута `Filterable`» или «`Sortable`». Через точку можно фильтровать по полям связанных элементов CRM и объекта `lastCommunication`, например `["company.title", "=", "Ромашка"]` или `["myCompany.title", "=", "Моя компания"]`. По полям сотрудников, стадии и источника, например `assignedBy.id` или `stage.semanticId`, фильтр не работает: метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_INVALIDFILTEREXCEPTION`. Формат фильтра описан на странице [crm.<тип>.list](./crm-entity-list-rest-v3.md) и в статье [Обзор REST API 3.0](../../../rest-v3.md#filter).

{% note warning "" %}

Поля `closed`, `stageSemanticId` и `stageSemantic` есть в ответе `crm.smartinvoice.field.list`, но методы `get` и `list` их не принимают. На такое поле в `select`, `filter` или `order` метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_UNKNOWNDTOPROPERTYEXCEPTION`. Группу стадии можно получить из поля `semanticId` объекта стадии: `"select": ["stage.semanticId"]`.

{% endnote %}

## Связанные объекты {#relations}

Связанный объект запрашивается в `select` по имени поля без суффикса `Id`: `assignedBy`, `stage`, `company`. Имя объекта целиком возвращает все его поля, путь через точку — только выбранные, например `["stage.name", "assignedBy.firstName"]`. Путь поддерживает один уровень вложенности.

Связанный элемент CRM — `contact`, `contacts`, `company`, `myCompany`, `relatedDeal`, `relatedQuote` — по имени целиком возвращает только `id`. Остальные поля элемента запрашивайте через точку. Через точку доступны поля из [объекта элемента CRM](#crm-item) и любые поля типа связанного элемента, например `["company.title", "company.phone", "myCompany.title"]`.

Если связь не заполнена, объект приходит как `null`, а массив объектов, например `observers` или `contacts`, — как пустой массив.

## Пользовательские поля {#userfields}

Пользовательские поля счета называются `UF_CRM_SMART_INVOICE_<код>` или `UF_CRM_<код>`, например `UF_CRM_619F45A0AF6DB`. Их передают и запрашивают по имени так же, как стандартные поля. Список пользовательских полей счета возвращает метод [crm.smartinvoice.field.custom.list](../fields/crm-entity-field-custom-list-rest-v3.md).

Значение поля типа «Деньги» передается объектом `{"sum": 150.5, "currencyId": "RUB"}`. Строка вида `150.5|RUB` не подходит: метод вернет ошибку «В поле `UF_CRM_…` требуется тип данных `MoneyDto` для такого запроса».

У каждого пользовательского поля есть парное поле `UF_CRM_…_data` — только для чтения, запрашивается в `select`. Оно содержит значение в нескольких представлениях:

- `value` — значение в том же формате, что в самом поле
- `rawValue` — значение в формате хранения, например `150.5|RUB` для поля «Деньги»
- `formattedValue` — значение для показа пользователю: `150.50 ₽` для денег, имя сотрудника для поля «Привязка к сотруднику»
- `extra` — дополнительные данные: для денег — `amount`, `currencyId` и `currencyFullName`, для сотрудника — поля объекта [сотрудника](#employee). Для строки, числа и даты — `null`

У множественного пользовательского поля `UF_CRM_…_data` — массив таких объектов.
