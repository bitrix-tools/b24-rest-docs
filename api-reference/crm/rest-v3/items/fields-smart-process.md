# Поля смарт-процесса в REST 3.0

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

{% note info "" %}

Поля относятся к методам REST 3.0. Особенности вызова и формат ответа новой версии API описаны в [обзоре REST 3.0](../../../rest-v3.md).

{% endnote %}

Поля элемента смарт-процесса возвращают методы [`crm.smartprocess<entityTypeId>.get`](./crm-entity-get-rest-v3.md) и [`crm.smartprocess<entityTypeId>.list`](./crm-entity-list-rest-v3.md), а принимают методы [`crm.smartprocess<entityTypeId>.add`](./crm-entity-add-rest-v3.md) и [`crm.smartprocess<entityTypeId>.update`](./crm-entity-update-rest-v3.md). В имя метода подставляется идентификатор типа смарт-процесса `entityTypeId`, например `crm.smartprocess1038.get`. Идентификаторы и настройки типов возвращает метод [crm.type.list](../../universal/user-defined-object-types/crm-type-list.md).

Состав полей зависит от настроек типа смарт-процесса: без воронок у элемента нет `categoryId`, без стадий — `stageId` и других полей стадии. У таких полей в таблице [Объект смарт-процесса](#item) указано, какая настройка типа нужна. Список полей конкретного типа возвращает метод [`crm.smartprocess<entityTypeId>.field.list`](../fields/crm-entity-field-list-rest-v3.md).

Часть полей существует в двух видах: как идентификатор и как связанный объект, например `assignedById` и `assignedBy`. Идентификатор можно передать при записи, а связанный объект — только запросить в `select`.

## Какие поля принимают и возвращают методы {#methods}

#|
|| **Метод** | **Принимает** | **Возвращает** ||
|| [`crm.smartprocess<entityTypeId>.add`](./crm-entity-add-rest-v3.md) | Поля таблицы [Объект смарт-процесса](#item), которые можно изменять, и пользовательские поля. Обязательных полей нет: элемент создается и с пустым объектом `fields` | Идентификатор созданного элемента `id` ||
|| [`crm.smartprocess<entityTypeId>.update`](./crm-entity-update-rest-v3.md) | `id` элемента и те же поля, что `add`. Поля, которых нет в `fields`, сохраняют текущие значения | Признак успеха `true` ||
|| [`crm.smartprocess<entityTypeId>.get`](./crm-entity-get-rest-v3.md) | `id` элемента и `select` | Без `select` — только `id`. С `select` — только перечисленные поля, `id` не добавляется автоматически. Связанный объект целиком, например `assignedBy`, возвращает все свои поля, а путь через точку, например `assignedBy.firstName`, — только выбранные. Подробнее — в разделе [Связанные объекты](#relations) ||
|| [`crm.smartprocess<entityTypeId>.list`](./crm-entity-list-rest-v3.md) | `select`, `filter`, `order`, `pagination` | Без `select` — только `id` каждого элемента. Поля и связанные объекты запрашиваются в `select` так же, как в `get` ||
|#

Поля с пометкой «только чтение» методы `add` и `update` не принимают и возвращают ошибку `BITRIX_REST_V3_EXCEPTION_VALIDATION_DTOVALIDATIONEXCEPTION` с текстом «Поле "contactId" не доступно к заполнению». Связанные объекты, например `company` и `stage`, тоже только для чтения: для записи передавайте идентификатор — `companyId`, `stageId`.

Поля со значениями из справочников метод проверяет при записи. Если значения нет в справочнике, метод вернет ошибку «Значение поля не содержится в списке допустимых значений». Для стадии, источника и валюты в тексте ошибки перечислены допустимые значения.

Логические поля принимают и возвращают `true` или `false`. Значения `Y`, `N`, `1` и `0` не подходят: метод вернет ошибку «В поле `opened` требуется тип данных `bool` для такого запроса».

Поля типа `date` принимают и возвращают дату в формате `YYYY-MM-DD`, например `2026-11-03`. Дату со временем или в формате `03.11.2026` такое поле не принимает. Поля типа `datetime` возвращаются в формате ISO 8601, например `2026-11-03T14:47:23+03:00`. В фильтре по полю `datetime` тоже передавайте дату со временем: значение `2026-11-03` метод не примет.

Фильтровать и сортировать можно только по полям, у которых это указано в описании. На другие поля метод `list` вернет ошибку «требуется наличие атрибута `Filterable`» или «`Sortable`». Через точку можно фильтровать по полям связанных элементов CRM и объекта `lastCommunication`, например `["company.title", "=", "Ромашка"]`. По полям сотрудников, стадии, воронки и источника, например `assignedBy.id` или `stage.semanticId`, фильтр не работает: метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_INVALIDFILTEREXCEPTION`. Формат фильтра описан на странице [crm.<тип>.list](./crm-entity-list-rest-v3.md) и в статье [Обзор REST API 3.0](../../../rest-v3.md#filter).

{% note warning "" %}

Поля `closed`, `stageSemanticId` и `stageSemantic` есть в ответе `crm.smartprocess<entityTypeId>.field.list`, но методы `get` и `list` их не принимают. На такое поле в `select`, `filter` или `order` метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_UNKNOWNDTOPROPERTYEXCEPTION`. Группу стадии можно получить из поля `semanticId` объекта стадии: `"select": ["stage.semanticId"]`.

{% endnote %}

### Поля связей с другими типами {#related}

Поля `related<Код типа>Id` и `related<Код типа>` появляются, когда в Битрикс24 настроена связь, в которой смарт-процесс подчинен другому типу объекта. Для каждого родительского типа у смарт-процесса есть пара полей:

- `related<Код типа>Id` — идентификатор родительского элемента, например `relatedLeadId` для лида, `relatedSmartInvoiceId` для счета, `relatedSmartProcess177Id` для смарт-процесса с `entityTypeId = 177`
- `related<Код типа>` — родительский элемент как объект типа [элемент CRM](#crm-item), например `relatedLead`

Название поля в ответе `field.list` совпадает с названием родительского типа, например «Лид» или «Закупка оборудования». Метод проверяет, что элемент с переданным идентификатором существует. Если элемента нет, метод вернет ошибку «Значение поля не содержится в списке допустимых значений».

Состав этих полей у каждого типа свой. Актуальный список возвращает метод [`crm.smartprocess<entityTypeId>.field.list`](../fields/crm-entity-field-list-rest-v3.md).

## Связанные объекты {#relations}

Связанный объект запрашивается в `select` по имени поля без суффикса `Id`: `assignedBy`, `stage`, `category`. Имя объекта целиком возвращает все его поля, путь через точку — только выбранные, например `["stage.name", "assignedBy.firstName"]`. Путь поддерживает один уровень вложенности.

Связанный элемент CRM — `contact`, `company`, `myCompany`, `related<Код типа>` — по имени целиком возвращает только `id`. Остальные поля элемента запрашивайте через точку, например `["company.title", "company.url"]`.

Если связь не заполнена, объект приходит как `null`, а массив объектов, например `observers` или `contacts`, — как пустой массив.

## Пользовательские поля {#userfields}

Пользовательские поля смарт-процесса называются `UF_CRM_<id типа>_<код>`, например `UF_CRM_3_1628508893`. В имени стоит идентификатор типа `id`, а не `entityTypeId`: поле из примера принадлежит типу с `id = 3` и `entityTypeId = 174`. Оба идентификатора возвращает метод [crm.type.list](../../universal/user-defined-object-types/crm-type-list.md). Пользовательские поля передают и запрашивают по имени так же, как стандартные поля. Список пользовательских полей типа возвращает метод [`crm.smartprocess<entityTypeId>.field.custom.list`](../fields/crm-entity-field-custom-list-rest-v3.md).

У каждого пользовательского поля есть парное поле `UF_CRM_…_data` — только для чтения, запрашивается в `select`. Оно содержит значение в нескольких представлениях:

- `value` — значение в том же формате, что в самом поле
- `rawValue` — значение в формате хранения, например `100.5|RUB` для поля «Деньги»
- `formattedValue` — значение для показа пользователю: `100.50 ₽` для денег, имя сотрудника для поля «Привязка к сотруднику», текст варианта для списка
- `extra` — дополнительные данные: для денег — `amount`, `currencyId` и `currencyFullName`, для сотрудника — поля объекта [сотрудника](#employee). Для строки, даты и списка — `null`

У множественного пользовательского поля `UF_CRM_…_data` — массив таких объектов.
