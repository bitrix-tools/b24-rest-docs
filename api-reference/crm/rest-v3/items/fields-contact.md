# Поля контакта в REST 3.0

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

{% note info "" %}

Поля относятся к методам REST 3.0. Особенности вызова и формат ответа новой версии API описаны в [обзоре REST 3.0](../../../rest-v3.md).

{% endnote %}

Поля контакта возвращают методы [crm.contact.get](./crm-entity-get-rest-v3.md) и [crm.contact.list](./crm-entity-list-rest-v3.md), а принимают методы [crm.contact.add](./crm-entity-add-rest-v3.md) и [crm.contact.update](./crm-entity-update-rest-v3.md). Значения множественных полей по одному добавляют и удаляют методы [crm.contact.addfieldvalue](./crm-entity-add-field-value-rest-v3.md) и [crm.contact.deletefieldvalue](./crm-entity-delete-field-value-rest-v3.md). Список полей с признаками возвращает метод [crm.contact.field.list](../fields/crm-entity-field-list-rest-v3.md).

Часть полей существует в двух видах: как идентификатор и как связанный объект, например `assignedById` и `assignedBy`. Идентификатор можно передать при записи, а связанный объект — только запросить в `select`.

## Какие поля принимают и возвращают методы {#methods}

#|
|| **Метод** | **Принимает** | **Возвращает** ||
|| [crm.contact.add](./crm-entity-add-rest-v3.md) | Поля таблицы [Объект контакта](#item), которые можно изменять, и пользовательские поля. Обязательно хотя бы одно из полей `name` или `lastName`, иначе метод вернет ошибку «At least one of name or lastName is required.» | Идентификатор созданного контакта `id` ||
|| [crm.contact.update](./crm-entity-update-rest-v3.md) | `id` контакта и те же поля, что `add`. Поля, которых нет в `fields`, сохраняют текущие значения | Признак успеха `true` ||
|| [crm.contact.get](./crm-entity-get-rest-v3.md) | `id` контакта и `select` | Без `select` — только `id`. С `select` — только перечисленные поля, `id` не добавляется автоматически. Связанный объект целиком, например `assignedBy`, возвращает все свои поля, а путь через точку, например `assignedBy.firstName`, — только выбранные. Подробнее — в разделе [Связанные объекты](#relations) ||
|| [crm.contact.list](./crm-entity-list-rest-v3.md) | `select`, `filter`, `order`, `pagination` | Без `select` — только `id` каждого контакта. Поля и связанные объекты запрашиваются в `select` так же, как в `get` ||
|| [crm.contact.addfieldvalue](./crm-entity-add-field-value-rest-v3.md), [crm.contact.deletefieldvalue](./crm-entity-delete-field-value-rest-v3.md) | `id` контакта, имя множественного поля `fieldName` и значение `value`. Подходят поля `phone`, `email`, `web`, `im`, `companiesId`, `observersId` и множественные пользовательские поля. Для других полей метод вернет ошибку «The field is not supported.» | Признак успеха `true` ||
|#

Поля с пометкой «только чтение» методы `add` и `update` не принимают и возвращают ошибку `BITRIX_REST_V3_EXCEPTION_VALIDATION_DTOVALIDATIONEXCEPTION` с текстом «Поле "companyId" не доступно к заполнению». Связанные объекты, например `company` и `assignedBy`, тоже только для чтения: для записи передавайте идентификатор — `companiesId`, `assignedById`.

Поля со значениями из справочников метод проверяет при записи. Если значения нет в справочнике, метод вернет ошибку «Значение поля не содержится в списке допустимых значений». Для типа контакта, обращения и источника в тексте ошибки перечислены допустимые значения.

Логические поля принимают и возвращают `true` или `false`. Значения `Y`, `N`, `1` и `0` не подходят: метод вернет ошибку «В поле `opened` требуется тип данных `bool` для такого запроса».

Поле `birthdayTime` типа `date` принимает и возвращает дату в формате `YYYY-MM-DD`, например `1990-05-15`. Дату со временем или в формате `15.05.1990` поле не принимает. Поля типа `datetime` возвращаются в формате ISO 8601, например `2026-11-03T14:42:28+03:00`. В фильтре по полю `datetime` тоже передавайте дату со временем.

Фильтровать и сортировать можно только по полям, у которых это указано в описании. На другие поля метод `list` вернет ошибку «требуется наличие атрибута `Filterable`» или «`Sortable`». Через точку можно фильтровать по полям связанных элементов CRM, значений телефона, почты, сайта и мессенджера, объектов `utm` и `lastCommunication`, например `["company.title", "=", "Ромашка"]` или `["phone.value", "=", "+79990000003"]`. По полям сотрудников и справочников, например `assignedBy.id` или `type.name`, фильтр не работает: метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_INVALIDFILTEREXCEPTION`. Формат фильтра описан на странице [crm.<тип>.list](./crm-entity-list-rest-v3.md) и в статье [Обзор REST API 3.0](../../../rest-v3.md#filter).

{% note warning "" %}

Фильтр по полю `companiesId` сейчас не работает: метод `crm.contact.list` отвечает HTTP-статусом 500 и ошибкой `INTERNAL_SERVER_ERROR`. Чтобы найти контакты компании, фильтруйте по основной компании `companyId` или запросите поле `contactsId` у компании методом [crm.company.get](./crm-entity-get-rest-v3.md).

{% endnote %}

[`integer`](../../../data-types.md) | Идентификатор значения. Назначается при записи, передавать его нельзя: метод вернет ошибку «Поле "id" не доступно к заполнению» ||
|| **valueTypeId**
[`string`](../../../data-types.md) | Тип значения, например `WORK` или `MOBILE`. Обязательное поле при записи. Допустимые типы для каждого поля возвращают методы [crm.dictionary.phonetype.list, crm.dictionary.emailtype.list, crm.dictionary.webtype.list и crm.dictionary.imtype.list](../dictionaries/crm-dictionary-list-rest-v3.md) ||
|| **valueType**
[`object`](../../../data-types.md) | Тип значения с названием: `id`, `name` — полное название, например `Мобильный телефон`, `nameShort` — краткое, например `Мобильный`. Только чтение ||
|| **value**
[`string`](../../../data-types.md) | Значение: номер телефона, адрес почты, адрес сайта или идентификатор в мессенджере. Обязательное поле при записи ||
|#

При записи передавайте массив объектов с полями `valueTypeId` и `value`:

```json
{
    "phone": [
        {"valueTypeId": "WORK", "value": "+79990000001"},
        {"valueTypeId": "MOBILE", "value": "+79990000002"}
    ]
}
```

В ответе каждое значение приходит с `id` и объектом `valueType`:

```json
{
    "phone": [
        {
            "id": 8871,
            "valueTypeId": "MOBILE",
            "valueType": {
                "id": "MOBILE",
                "name": "Мобильный телефон",
                "nameShort": "Мобильный"
            },
            "value": "+79990000003"
        }
    ]
}
```

Как работает запись:

- `crm.contact.update` заменяет все значения поля переданным массивом. Значения, которых нет в массиве, удаляются. Другие множественные поля, которых нет в `fields`, не меняются
- пустой массив, например `"phone": []`, удаляет все значения поля
- одно значение добавляет метод [crm.contact.addfieldvalue](./crm-entity-add-field-value-rest-v3.md), удаляет — [crm.contact.deletefieldvalue](./crm-entity-delete-field-value-rest-v3.md). В `value` передайте объект `{"valueTypeId": "MOBILE", "value": "+79990000008"}`. Если такое значение уже есть, `addfieldvalue` вернет ошибку «The field value already exists.»
- в одном поле может быть до 50 значений, во всех четырех полях вместе — до 100. При превышении метод вернет ошибку «Too many phone multifields.»

## Связанные объекты {#relations}

Связанный объект запрашивается в `select` по имени поля без суффикса `Id`: `assignedBy`, `honorific`, `company`. Имя объекта целиком возвращает все его поля, путь через точку — только выбранные, например `["type.name", "assignedBy.firstName"]`. Путь поддерживает один уровень вложенности: `company.createdBy.firstName` метод не примет.

Связанный элемент CRM — `company`, `companies`, `lead` — по имени целиком возвращает только `id`. Остальные поля элемента запрашивайте через точку. Через точку доступны поля из [объекта элемента CRM](#crm-item) и любые поля типа связанного элемента, например `["company.title", "company.phone", "company.industryId"]`. Поля компании описаны в статье [Поля компании в REST 3.0](./fields-company.md).

Если связь не заполнена, объект приходит как `null`, а массив объектов, например `observers` или `companies`, — как пустой массив.

## Пользовательские поля {#userfields}

Пользовательские поля контакта называются `UF_CRM_<код>`, например `UF_CRM_1716289811`. Их передают и запрашивают по имени так же, как стандартные поля. Список пользовательских полей контакта возвращает метод [crm.contact.field.custom.list](../fields/crm-entity-field-custom-list-rest-v3.md).

Значение поля типа «Деньги» передается объектом `{"sum": 150.5, "currencyId": "RUB"}`. Строка вида `150.5|RUB` не подходит: метод вернет ошибку «В поле `UF_CRM_…` требуется тип данных `MoneyDto` для такого запроса».

У каждого пользовательского поля есть парное поле `UF_CRM_…_data` — только для чтения, запрашивается в `select`. Оно содержит значение в нескольких представлениях:

- `value` — значение в том же формате, что в самом поле
- `rawValue` — значение в формате хранения, например `150.5|RUB` для поля «Деньги»
- `formattedValue` — значение для показа пользователю: `150.50 ₽` для денег, имя сотрудника для поля «Привязка к сотруднику»
- `extra` — дополнительные данные: для денег — `amount`, `currencyId` и `currencyFullName`, для сотрудника — поля объекта [сотрудника](#employee). Для строки, числа и даты — `null`

У множественного пользовательского поля `UF_CRM_…_data` — массив таких объектов.
