# Поля предложения в REST 3.0

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

{% note info "" %}

Поля относятся к методам REST 3.0. Особенности вызова и формат ответа новой версии API описаны в [обзоре REST 3.0](../../../rest-v3.md).

{% endnote %}

Поля предложения возвращают методы [crm.quote.get](./crm-entity-get-rest-v3.md) и [crm.quote.list](./crm-entity-list-rest-v3.md), а принимают методы [crm.quote.add](./crm-entity-add-rest-v3.md) и [crm.quote.update](./crm-entity-update-rest-v3.md). Список полей с признаками возвращает метод [crm.quote.field.list](../fields/crm-entity-field-list-rest-v3.md).

Часть полей существует в двух видах: как идентификатор и как связанный объект, например `assignedById` и `assignedBy`. Идентификатор можно передать при записи, а связанный объект — только запросить в `select`.

## Какие поля принимают и возвращают методы {#methods}

#|
|| **Метод** | **Принимает** | **Возвращает** ||
|| [crm.quote.add](./crm-entity-add-rest-v3.md) | Поля таблицы [Объект предложения](#item), которые можно изменять, и пользовательские поля. Обязательных полей нет: предложение создается и с пустым объектом `fields` | Идентификатор созданного предложения `id` ||
|| [crm.quote.update](./crm-entity-update-rest-v3.md) | `id` предложения и те же поля, что `add`. Поля, которых нет в `fields`, сохраняют текущие значения | Признак успеха `true` ||
|| [crm.quote.get](./crm-entity-get-rest-v3.md) | `id` предложения и `select` | Без `select` — только `id`. С `select` — только перечисленные поля, `id` не добавляется автоматически. Связанный объект целиком, например `assignedBy`, возвращает все свои поля, а путь через точку, например `assignedBy.firstName`, — только выбранные. Подробнее — в разделе [Связанные объекты](#relations) ||
|| [crm.quote.list](./crm-entity-list-rest-v3.md) | `select`, `filter`, `order`, `pagination` | Без `select` — только `id` каждого предложения. Поля и связанные объекты запрашиваются в `select` так же, как в `get` ||
|#

Поля с пометкой «только чтение» методы `add` и `update` не принимают и возвращают ошибку `BITRIX_REST_V3_EXCEPTION_VALIDATION_DTOVALIDATIONEXCEPTION` с текстом «Поле "personTypeId" не доступно к заполнению». Связанные объекты, например `deal` и `stage`, тоже только для чтения: для записи передавайте идентификатор — `dealId`, `stageId`.

Поля со значениями из справочников метод проверяет при записи. Если значения нет в справочнике, метод вернет ошибку «Значение поля не содержится в списке допустимых значений». Для стадии и валюты в тексте ошибки перечислены допустимые значения.

Логические поля принимают и возвращают `true` или `false`. Значения `Y`, `N`, `1` и `0` не подходят: метод вернет ошибку «В поле `opened` требуется тип данных `bool` для такого запроса».

Поля типа `date` принимают и возвращают дату в формате `YYYY-MM-DD`, например `2026-12-01`. Дату со временем или в формате `01.12.2026` такое поле не принимает. Поля типа `datetime` возвращаются в формате ISO 8601, например `2026-11-03T14:48:50+03:00`. В фильтре по полю `datetime` тоже передавайте дату со временем: значение `2026-11-03` метод не примет.

Фильтровать и сортировать можно только по полям, у которых это указано в описании. На другие поля метод `list` вернет ошибку «требуется наличие атрибута `Filterable`» или «`Sortable`». Через точку можно фильтровать по полям связанных элементов CRM и объектов `lastCommunication` и `utm`, например `["deal.title", "=", "Поставка оборудования"]`. По полям сотрудников и стадии, например `assignedBy.id` или `stage.semanticId`, фильтр не работает: метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_INVALIDFILTEREXCEPTION`. Формат фильтра описан на странице [crm.<тип>.list](./crm-entity-list-rest-v3.md) и в статье [Обзор REST API 3.0](../../../rest-v3.md#filter).

{% note warning "" %}

Поля `movedTime`, `movedById`, `movedBy`, `stageSemanticId` и `stageSemantic` есть в ответе `crm.quote.field.list`, но методы `get` и `list` их не принимают. На такое поле в `select`, `filter` или `order` метод вернет ошибку `BITRIX_REST_V3_EXCEPTION_UNKNOWNDTOPROPERTYEXCEPTION`. Группу стадии можно получить из поля `semanticId` объекта стадии: `"select": ["stage.semanticId"]`.

{% endnote %}

## Связанные объекты {#relations}

Связанный объект запрашивается в `select` по имени поля без суффикса `Id`: `assignedBy`, `stage`, `personType`. Имя объекта целиком возвращает все его поля, путь через точку — только выбранные, например `["stage.name", "assignedBy.firstName"]`. Путь поддерживает один уровень вложенности.

Связанный элемент CRM — `deal`, `lead`, `contact`, `company`, `myCompany` — по имени целиком возвращает только `id`. Остальные поля элемента запрашивайте через точку, например `["deal.title", "deal.url"]`.

Если связь не заполнена, объект приходит как `null`, а массив объектов, например `contacts`, — как пустой массив.

## Пользовательские поля {#userfields}

Пользовательские поля предложения называются `UF_CRM_<код>`, например `UF_CRM_6710EFCBAF22C`. Их передают и запрашивают по имени так же, как стандартные поля. Список пользовательских полей возвращает метод [crm.quote.field.custom.list](../fields/crm-entity-field-custom-list-rest-v3.md).

У каждого пользовательского поля есть парное поле `UF_CRM_…_data` — только для чтения, запрашивается в `select`. Оно содержит значение в нескольких представлениях:

- `value` — значение в том же формате, что в самом поле
- `rawValue` — значение в формате хранения, например `100.5|RUB` для поля «Деньги»
- `formattedValue` — значение для показа пользователю: `100.50 ₽` для денег, имя сотрудника для поля «Привязка к сотруднику», текст варианта для списка
- `extra` — дополнительные данные: для денег — `amount`, `currencyId` и `currencyFullName`, для сотрудника — поля объекта [сотрудника](#employee). Для строки, даты и списка — `null`

У множественного пользовательского поля `UF_CRM_…_data` — массив таких объектов.
