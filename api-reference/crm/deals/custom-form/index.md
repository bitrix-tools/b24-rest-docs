# Управление карточками сделок: обзор методов

{% note tip "" %}

Группа методов crm.deal.details.configuration.* управляет настройками карточки для двух представлений:

* «Общий вид» — вид карточки для всех сотрудников
* «Мой вид» — личная настройка карточки сотрудника

Для каждого вида карточки можно настроить секции, внутри секции — перечень полей. Например, создать секцию «Информация об оплате» и вывести в ней поля «Сумма и валюта» и «Аванс». Для полей, которые не относятся к платежной информации, создать другую секцию.

{% note warning "" %}

Развитие методов `crm.deal.details.configuration.*` остановлено. Для новой разработки используйте универсальные методы [crm.item.details.configuration.*](../../universal/item-details-configuration/index.md) с `entityTypeId = 2`.

{% endnote %}

## Актуальная версия API

Карточка сделки настраивается теми же методами, что и карточка любого другого объекта CRM. Группа [crm.item.details.configuration.*](../../universal/item-details-configuration/index.md) отличается от crm.deal.details.configuration.* одним дополнительным параметром `entityTypeId` — идентификатором типа объекта. Имена методов совпадают: `get`, `set`, `reset` и `forceCommonScopeForAll`. Для сделки передавайте `entityTypeId = 2`, остальные параметры те же.

## Какую карточку меняет метод

Метод работает с одной конкретной карточкой. Ее задают три параметра, общие для обеих групп методов. Без них метод обратится к личной карточке текущего пользователя в воронке сделок по умолчанию.

#|
|| **Параметр** | **Что задает** | **Значения** ||
|| `scope` | Представление карточки | `P` — «Мой вид», личные настройки. `C` — «Общий вид», настройки для всех сотрудников. По умолчанию — `P` ||
|| `userId` | Владельца личных настроек | Идентификатор пользователя из метода [user.get](../../../user/user-get.md). Нужен, только когда вы читаете или меняете личную карточку другого сотрудника ||
|| `extras.dealCategoryId` | Воронку сделок | Идентификатор воронки из метода [crm.category.list](../../universal/category/crm-category-list.md) с `entityTypeId = 2`. Если не указан, берется воронка по умолчанию ||
|#

## Как начать работу

Порядок для новой разработки — на универсальных методах.

1. Получите идентификаторы полей сделки методом [crm.item.fields](../../universal/crm-item-fields.md) с `entityTypeId = 2` — из них собирается состав секций
2. Узнайте идентификатор нужной воронки методом [crm.category.list](../../universal/category/crm-category-list.md) с параметром `entityTypeId = 2`
3. Посмотрите текущую структуру карточки методом [crm.item.details.configuration.get](../../universal/item-details-configuration/crm-item-details-configuration-get.md) — он вернет список секций с полями
4. Задайте свою структуру методом [crm.item.details.configuration.set](../../universal/item-details-configuration/crm-item-details-configuration-set.md), передав `scope` и состав секций
5. Верните настройки по умолчанию методом [crm.item.details.configuration.reset](../../universal/item-details-configuration/crm-item-details-configuration-reset.md), если структура больше не нужна

## Связь карточки сделки с другими объектами

**Поля сделки.** Секция карточки — это набор полей сделки, поэтому структура карточки собирается из их идентификаторов. Метод [crm.deal.fields](../crm-deal-fields.md) возвращает и системные, и пользовательские поля. Новое пользовательское поле, созданное методом [crm.deal.userfield.add](../user-defined-fields/crm-deal-userfield-add.md), тоже можно вывести в секцию — под именем с префиксом `UF_CRM_`.

**Воронки сделок.** У каждой воронки своя структура карточки: в воронке «Продажи» могут быть одни секции и поля, в воронке «Сервисное обслуживание» — другие. Воронка выбирается параметром `extras.dealCategoryId`, поэтому настройку нужно повторить для каждой воронки, где она нужна.

**Пользователь.** Личная карточка принадлежит конкретному сотруднику. Чтобы прочитать или изменить чужую личную карточку, передайте его идентификатор в параметре `userId` и получите его методом [user.get](../../../user/user-get.md).
