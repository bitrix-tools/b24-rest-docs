Пользовательские поля хранят информацию о сделке в различных форматах данных: строка, число, ссылка, адрес и другие. Поле создается один раз и появляется в карточках всех сделок Битрикс24.

> Быстрый переход: [все методы и события](#all-methods)
>
> Пользовательская документация: [Пользовательские поля в CRM](https://helpdesk.bitrix24.ru/open/22048980/)

## Имена пользовательских полей

Имя поля собирает Битрикс24, а не разработчик. К коду, который вы передаете в параметре `FIELD_NAME` метода [crm.deal.userfield.add](./crm-deal-userfield-add.md), всегда добавляется префикс `UF_CRM_`: код `MANAGER_NOTE` превращается в имя `UF_CRM_MANAGER_NOTE`. Полные правила преобразования описаны на странице метода.

Полученное имя — это ключ, по которому значение поля читается и записывается в остальных методах сделок:

- в ответе методов [crm.deal.get](../crm-deal-get.md) и [crm.deal.list](../crm-deal-list.md) значение приходит в поле `UF_CRM_MANAGER_NOTE`
- в методах [crm.deal.add](../crm-deal-add.md) и [crm.deal.update](../crm-deal-update.md) значение передается в `fields` под тем же именем
- метод [crm.deal.fields](../crm-deal-fields.md) возвращает пользовательские поля вместе с системными

## Типы пользовательских полей

Тип поля задается параметром `USER_TYPE_ID` при создании. Список доступных типов с их идентификаторами и названиями возвращает метод [crm.userfield.types](../../universal/user-defined-fields/crm-userfield-types.md).

```json
{
    "result": [
        {
            "ID": "double",
            "title": "Число"
        }
    ]
}
```

Метод [crm.userfield.fields](../../universal/user-defined-fields/crm-userfield-fields.md) возвращает характеристики, которые можно задать любому пользовательскому полю, — обязательность, множественность, сортировку и другие.

```json
{
    "result": {
        "MANDATORY": {
            "type": "char",
            "title": "Обязательное"
        }
    }
}
```

## Настройки пользовательских полей

У каждого типа поля свой набор дополнительных настроек — параметр `SETTINGS`. Список настроек, поддерживаемых конкретным типом, возвращает метод [crm.userfield.settings.fields](../../universal/user-defined-fields/crm-userfield-settings-fields.md).

```json
{
    "result": {
        "DEFAULT_VALUE": {
            "type": "double",
            "title": "Значение по умолчанию"
        },
        "PRECISION": {
            "type": "int",
            "title": "Точность"
        }
    }
}
```

## Ошибки при работе с пользовательскими полями

При создании или удалении пользовательских полей запрос может прерваться с ошибкой [INTERNAL_SERVER_ERROR](../../../../error-codes.md). Это внутренняя ошибка сервера. Причину можно найти в логах сервера на момент выполнения запроса.

* В облачном Битрикс24 напишите обращение в [техническую поддержку](../../../../bitrix-support.md), чтобы получить детали ошибки.
* В коробочном Битрикс24 запросите лог ошибок сервера у администратора сервера или администратора хостинга, затем напишите в [техническую поддержку](../../../../bitrix-support.md) и приложите лог для анализа.

### Частые причины серверных ошибок

1. Для сделок можно создать 1016 пользовательских полей — это ограничение архитектуры базы данных. Если в Битрикс24 уже есть 1016 полей для сделок, при попытке создать новое поле метод [crm.deal.userfield.add](./crm-deal-userfield-add.md) вернет ошибку [INTERNAL_SERVER_ERROR](../../../../error-codes.md).

    Проверить количество пользовательских полей сделок можно методом [crm.deal.userfield.list](./crm-deal-userfield-list.md).

2. На серверах есть ограничение для времени выполнения одного запроса — `max_execution_time`. Стандартное время — 60 секунд. Если запрос выполняется дольше, он прерывается с ошибкой [INTERNAL_SERVER_ERROR](../../../../error-codes.md).

    Время [создания](./crm-deal-userfield-add.md) или [удаления](./crm-deal-userfield-delete.md) пользовательского поля сделок зависит от количества сделок. Когда поле создается, оно добавляется во все карточки сделок. Когда поле удаляется, оно удаляется из всех карточек. Чем меньше сделок в Битрикс24, тем быстрее создаются и удаляются поля.

    Чтобы проверить количество сделок, используйте метод [crm.deal.list](../crm-deal-list.md).

## Обзор методов и событий {#all-methods}

События уведомляют о настройке самих полей, а не об изменении их значений в сделках. Как подписаться на них, описано на странице [событий пользовательских полей сделок](./events/index.md).

> Scope: [`crm`](../../../scopes/permissions.md)
>
> Кто может выполнять метод: в зависимости от метода — создание, изменение и удаление поля доступны администратору CRM с правом «разрешить изменять настройки», а получить поле и список полей может любой пользователь с правом «чтения» сделок. Подписаться на события может любой пользователь
