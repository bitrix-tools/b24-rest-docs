# Бизнес-процессы и роботы: обзор методов

Бизнес-процессы автоматизируют работу с документами, CRM-объектами, файлами и элементами списков. Методы `bizproc.*` запускают процессы по шаблонам, управляют активными экземплярами, обрабатывают задания пользователей и добавляют в автоматизацию собственные действия или роботов приложения.

Процесс может стартовать автоматически при событии в Битрикс24 или вручную по инициативе пользователя. Через REST API запуск выполняется методом [bizproc.workflow.start](./bizproc-workflow-start.md).

Для новой разработки чаще выбирают роботов приложений. Роботы доступны в CRM-автоматизации, бизнес-процессах и умных сценариях, а действия приложений удобны для поддержки уже работающих интеграций в дизайнере бизнес-процессов.

## Как начать работу

1. Подготовьте шаблон бизнес-процесса в интерфейсе Битрикс24 или добавьте его методом [bizproc.workflow.template.add](./template/bizproc-workflow-template-add.md)
2. Определите документ, для которого будет выполняться процесс. Для запуска нужен `DOCUMENT_ID`, например `['crm', 'CCrmDocumentLead', 'LEAD_1']`
3. Запустите процесс методом [bizproc.workflow.start](./bizproc-workflow-start.md), передайте `TEMPLATE_ID`, `DOCUMENT_ID` и входные параметры шаблона
4. Контролируйте активные процессы методом [bizproc.workflow.instances](./bizproc-workflow-instances.md)
5. Обрабатывайте задания пользователей методами группы [bizproc.task.*](./bizproc-task/index.md), если сценарий требует согласования, ознакомления или дополнительной информации

## Связь с другими объектами

Бизнес-процессы связаны с документами Битрикс24, шаблонами, заданиями пользователей и внешними обработчиками приложения.

**Документ.** Процесс запускается для конкретного документа: лида, сделки, элемента списка, файла Диска или другого поддерживаемого объекта. Связь передается в параметре `DOCUMENT_ID` метода [bizproc.workflow.start](./bizproc-workflow-start.md). Тип документа должен совпадать с типом, для которого создан шаблон.

**Шаблон бизнес-процесса.** Шаблон задает логику процесса и набор входных параметров. Управлять шаблонами можно методами группы [bizproc.workflow.template.*](./template/index.md). Идентификатор шаблона `TEMPLATE_ID` используется при запуске процесса и фильтрации списка активных процессов.

**Задание бизнес-процесса.** Задание появляется, когда процессу нужно действие пользователя: согласование, ознакомление или ввод дополнительных данных. Получить задания можно методом [bizproc.task.list](./bizproc-task/bizproc-task-list.md), выполнить — методом [bizproc.task.complete](./bizproc-task/bizproc-task-complete.md), делегировать — методом [bizproc.task.delegate](./bizproc-task/bizproc-task-delegate.md).

**Приложение.** Роботы и действия приложений вызывают внешний обработчик `HANDLER`. Если обработчик должен вернуть результат в процесс, при регистрации укажите выходные параметры и режим ожидания ответа, затем передайте значения методом [bizproc.event.send](./bizproc-robot/bizproc-event-send.md).

## Что важно учитывать

- Методы управления шаблонами, роботами и действиями выполняет администратор
- Методы роботов и действий работают только в контексте установленного приложения
- Робот или действие с ожиданием результата получает `EVENT_TOKEN` во время выполнения сценария. Этот ключ нужен для метода [bizproc.event.send](./bizproc-robot/bizproc-event-send.md)
- Запущенный процесс использует копию шаблона на момент старта. Изменения в шаблоне не меняют уже активный процесс
