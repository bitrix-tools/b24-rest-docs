# Роботы приложений: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Роботы приложений добавляют в автоматизацию Битрикс24 шаг, который вызывает обработчик приложения. Такой шаг принимает входные параметры, может дождаться ответа внешней системы и вернуть выходные значения в процесс. Например, робот на стадии сделки может передать заказ во внешнюю систему учета и вернуть номер заказа для следующих шагов автоматизации.

В REST API роботы приложений и [действия приложений](../bizproc-activity/index.md) близки по модели. Для каждого типа есть отдельные методы регистрации, обновления, удаления и получения списка. Внутри платформы используется общий механизм выполнения.

Роботов можно использовать в CRM-автоматизации, бизнес-процессах и умных сценариях. Поэтому для новой разработки рекомендуется выбирать роботов, а действия приложений использовать в первую очередь для поддержки уже существующих интеграций.

## Какие задачи решают роботы приложений

- Выполняют внешние действия в автоматизации CRM и бизнес-процессах
- Возвращают вычисленные данные в процесс для следующих шагов
- Ограничивают доступность по типу документа и редакции Битрикс24
- Записывают сообщения в журнал процесса в ходе выполнения сценария

## Как работает ожидание результата {#handler}

Если робот должен дождаться ответа внешней системы, укажите `RETURN_PROPERTIES` и `USE_SUBSCRIPTION = 'Y'` при регистрации или обновлении через [bizproc.robot.add](./bizproc-robot-add.md) и [bizproc.robot.update](./bizproc-robot-update.md).

Дальше сценарий работает так:

1. Робот запускается в автоматизации и отправляет данные на обработчик приложения `HANDLER`
2. Приложение получает уникальный ключ `EVENT_TOKEN` и рассчитывает результат
3. Приложение возвращает значения в процесс с помощью метода [bizproc.event.send](./bizproc-event-send.md)
4. При необходимости приложение добавляет пояснение в журнал процесса через `LOG_MESSAGE`

Запрос на `HANDLER` Битрикс24 отправляет методом POST через сервер очередей. Данные приходят в формате `application/x-www-form-urlencoded`, в примере они показаны в формате JSON:

```json
{
    "workflow_id": "6ab5bcfde8e8b0.39728274",
    "code": "test_robot",
    "document_id": [
        "crm",
        "CCrmDocumentDeal",
        "DEAL_17"
    ],
    "document_type": [
        "crm",
        "CCrmDocumentDeal",
        "DEAL"
    ],
    "event_token": "6ab5bcfde8e8b0.39728274|A1|rKrsZ31xjG1jMJL2iEjmSTP3h2K10FiI.e02ccd45c3520894e790a7b58f4f04932f5e9805a03cdc041b9c5dc5aff49653",
    "properties": {
        "text": "Напомнить клиенту о встрече"
    },
    "use_subscription": "Y",
    "timeout_duration": "0",
    "ts": "1790295294",
    "auth": {
        "access_token": "s6p6eclrvim6da22ft9ch94ekreb52lv",
        "refresh_token": "t5o5dbkqauh5cz11es8bg83djqda41ku",
        "domain": "some-domain.bitrix24.ru",
        "client_endpoint": "https://some-domain.bitrix24.ru/rest/",
        "application_token": "51856fefc120afa4b628cc82d3935cce"
    }
}
```

Что важно в запросе:

- `event_token` — ключ этого запуска робота. Его передают в метод [bizproc.event.send](./bizproc-event-send.md)
- `properties` — значения входных параметров из `PROPERTIES`, которые задали в настройках робота
- `document_id` — документ, для которого запущен робот. В примере это сделка с ID 17
- `timeout_duration` — сколько секунд процесс будет ждать ответа. Значение `0` означает, что срок не ограничен
- `auth` — токены `access_token` и `refresh_token` пользователя, от имени которого работает робот. Это пользователь из параметра `AUTH_USER_ID`, а администратор может выбрать другого в настройках робота. Остальные ключи `auth` описаны в статье [События](../../events/index.md#auth)

Чтобы вернуть результат, приложение вызывает [bizproc.event.send](./bizproc-event-send.md) с токеном из запроса. В `RETURN_VALUES` передайте значения с ключами из `RETURN_PROPERTIES`, в `LOG_MESSAGE` — текст для журнала процесса. В примере при регистрации робота объявлен выходной параметр `outputString` типа `string`:

```json
{
    "EVENT_TOKEN": "6ab5bcfde8e8b0.39728274|A1|rKrsZ31xjG1jMJL2iEjmSTP3h2K10FiI.e02ccd45c3520894e790a7b58f4f04932f5e9805a03cdc041b9c5dc5aff49653",
    "RETURN_VALUES": {
        "outputString": "ORDER-1024"
    },
    "LOG_MESSAGE": "Заказ передан в систему учета"
}
```

Если шаг с этим токеном еще ждет ответа, робот завершится, и следующие шаги автоматизации смогут использовать значение `outputString`. Ключи, которых нет в `RETURN_PROPERTIES`, Битрикс24 не сохранит.

{% note warning "" %}

Ответ `true` метода [bizproc.event.send](./bizproc-event-send.md) не подтверждает, что процесс принял результат. Метод вернет `true` и на токен робота, который уже завершился или не ждет ответа. Процесс в этом случае не изменится.

{% endnote %}

## Как начать работу

1. Подготовьте обработчик — страницу приложения с внешним адресом, на которую Битрикс24 будет отправлять данные робота
2. Зарегистрируйте робота методом [bizproc.robot.add](./bizproc-robot-add.md). Передайте код `CODE`, название `NAME` и адрес обработчика `HANDLER`
3. Добавьте робота на стадию в автоматизации CRM или в шаблон бизнес-процесса и запустите сценарий
4. Примите запрос на обработчике и, если робот ждет ответа, верните результат методом [bizproc.event.send](./bizproc-event-send.md). Как устроен обмен, описано в разделе [Как работает ожидание результата](#handler)
5. Проверяйте роботов приложения методом [bizproc.robot.list](./bizproc-robot-list.md), изменяйте методом [bizproc.robot.update](./bizproc-robot-update.md) и удаляйте ненужных методом [bizproc.robot.delete](./bizproc-robot-delete.md)

## Что важно учитывать

- Методы управления роботами [bizproc.robot.add](./bizproc-robot-add.md), [bizproc.robot.update](./bizproc-robot-update.md), [bizproc.robot.list](./bizproc-robot-list.md), [bizproc.robot.delete](./bizproc-robot-delete.md) работают только в контексте приложения и только от имени администратора. Через вебхук они вернут ошибку `ACCESS_DENIED` с текстом `Access denied! Application context required`
- Методу [bizproc.event.send](./bizproc-event-send.md) контекст приложения не нужен: Битрикс24 проверяет токен `event_token`. С неверным токеном метод вернет ошибку `ACCESS_DENIED`

## Связь с другими объектами

**Типы документов.** Где показывать робота, задает параметр `FILTER` метода [bizproc.robot.add](./bizproc-robot-add.md): например, только в автоматизации сделок. Параметр `DOCUMENT_TYPE` задает тип документа, по которому Битрикс24 определяет типы полей для `PROPERTIES` и `RETURN_PROPERTIES`.

**Действия приложений.** Роботы и [действия](../bizproc-activity/index.md) приложения получают на обработчик одинаковый запрос и возвращают результат одним методом [bizproc.event.send](./bizproc-event-send.md). Коды у них общие: если у приложения уже есть действие с таким же `CODE`, робот не зарегистрируется — метод вернет ошибку `ERROR_ACTIVITY_ALREADY_INSTALLED`.
