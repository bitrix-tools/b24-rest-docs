# Боты: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы управляют жизненным циклом чат-бота: регистрация, изменение свойств, получение данных, просмотр списка и удаление.

> Быстрый переход: [все методы](#all-methods)

## Переход с imbot на imbot.v2

Методы второй версии заменяют устаревшие [imbot.register](../../../outdated/bots/imbot-register.md), [imbot.update](../../../outdated/bots/imbot-update.md), [imbot.unregister](../../../outdated/bots/imbot-unregister.md) и [imbot.bot.list](../../../outdated/bots/imbot-bot-list.md). У метода [imbot.v2.Bot.get](./bot-get.md) аналога в первой версии нет. Для новой интеграции выбирайте вторую версию.

Если бот уже работает на старых методах, сопоставьте параметры по [таблице миграции](../../migration.md#metody): например, `CODE` переходит в `fields.code`, а вместо `EVENT_HANDLER` задают `fields.eventMode` и `fields.webhookUrl`. Обе версии работают параллельно, но бот получает события в формате той версии, через которую его зарегистрировали.

## Как работать с ботами

1. Зарегистрируйте бота через [imbot.v2.Bot.register](./bot-register.md). Сохраните ID бота из поля ответа `result.bot.id`. Его передают в параметре `botId` в методах, которые работают с конкретным ботом: изменение и удаление бота, его чаты, сообщения и команды.
2. При необходимости обновите свойства методом [imbot.v2.Bot.update](./bot-update.md).
3. Получайте данные по одному боту через [imbot.v2.Bot.get](./bot-get.md) или список через [imbot.v2.Bot.list](./bot-list.md).
4. Удалите бота методом [imbot.v2.Bot.unregister](./bot-unregister.md), если он больше не нужен.

Полное описание полей объекта Bot — [Объекты и поля](../../entities.md#bot).

## Ключевые параметры бота {#key-fields}

Эти параметры задаются при регистрации и определяют, как бот будет работать дальше.

#|
|| **Параметр** | **Что определяет** | **Где описан подробно** ||
|| `fields.code` | Уникальный код бота в рамках приложения. По нему [imbot.v2.Bot.register](./bot-register.md) распознает повторную регистрацию и возвращает существующего бота | [imbot.v2.Bot.register](./bot-register.md) ||
|| `fields.botToken` | Токен авторизации бота. Обязателен при вызовах через вебхук, для OAuth не нужен. При регистрации его передают в `fields`, в остальных методах — на верхнем уровне запроса как `botToken`. Используйте токен не длиннее 40 символов: такой лимит действует при смене токена | [Авторизация](../../index.md#auth) ||
|| `fields.type` | Поведение бота в чатах, по умолчанию `bot`. От типа зависит, получает ли бот все сообщения чата или только упоминания | [Типы ботов](../../index.md#bot-types) ||
|| `fields.eventMode` | Способ доставки событий: `fetch` — бот сам забирает события, `webhook` — Битрикс24 отправляет их на URL бота | [Режимы доставки событий](../events/index.md) ||
|#

## Лимиты и ошибки {#errors}

Ограничение: одно приложение может зарегистрировать не более 100 ботов. Остальные лимиты раздела — [Лимиты](../../index.md#limits).

Если вызов не прошел, метод вернет код ошибки в поле `error`. Типичные ошибки:

- `BOT_TOKEN_NOT_SPECIFIED` — запрос через вебхук отправлен без `botToken`
- `BOT_NOT_FOUND` — бота с переданным `botId` нет
- `BOT_OWNERSHIP_ERROR` — бота зарегистрировало другое приложение или вебхук с другим `botToken`

Структура ответа при ошибке описана в разделе [Формат ответа](../../index.md#format-otveta), полный список кодов — на страницах методов.

## Связь с другими объектами {#relations}

**События.** Бот получает события `ONIMBOTV2*` в том режиме, который задан в `fields.eventMode`. В режиме `fetch` бот сам забирает события методом [imbot.v2.Event.get](../events/event-get.md). В режиме `webhook` Битрикс24 подписывает бота на события при регистрации и удаляет подписки вместе с ботом — вызывать [event.bind](../../../../events/event-bind.md) вручную не нужно. Если у приложения остаются другие боты, подписки сохранятся до удаления последнего из них — подробнее в [imbot.v2.Bot.unregister](./bot-unregister.md#event-subscriptions). Форматы данных — [События imbot.v2](../events/events.md).

**Чаты.** Зарегистрированный бот может создавать групповые чаты и управлять участниками. Во всех таких вызовах передается `botId` из ответа [imbot.v2.Bot.register](./bot-register.md) — [Чаты](../chats/index.md).

**Команды.** Слэш-команды регистрируются отдельно и привязываются к боту по `botId` — [Команды](../commands/index.md).

**Открытые линии.** Свойство `fields.isSupportOpenline` включает поддержку Открытых линий для бота типа `openline` — [imbot.v2.Bot.register](./bot-register.md).

**Контекст бота.** Приложение может передать боту произвольные JSON-данные при открытии чата — [Передача контекста боту](../bot-context.md).
