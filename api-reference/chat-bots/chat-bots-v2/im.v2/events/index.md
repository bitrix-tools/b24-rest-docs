# События: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы подписывают пользователя на события мессенджера и возвращают их в режиме polling. Используйте их, если интеграции нужно читать поток событий от имени пользователя или приложения.

> Быстрый переход: [все методы и события](#all-methods)

## Как работать с событиями {#how-to-start}

1. Включите запись событий через [im.v2.Event.subscribe](./event-subscribe.md). Метод идемпотентный: повторный вызов безопасен.
2. Получайте накопленные события через [im.v2.Event.get](./event-get.md).
3. Передавайте `offset`, чтобы подтверждать уже обработанные записи. Значение берите из поля `nextOffset` предыдущего ответа.
4. Завершите подписку методом [im.v2.Event.unsubscribe](./event-unsubscribe.md).

{% note info "Что такое режим polling" %}

Polling — режим получения событий, при котором приложение само периодически запрашивает у сервера накопленные события. Сервер не знает об адресе приложения и ничего не отправляет сам — он только накапливает очередь и отдает ее по запросу.

Это отличает polling от webhook: в webhook-режиме Битрикс24 сам вызывает URL приложения при каждом новом событии. Polling удобен, если у приложения нет постоянного HTTP-сервера или публичного URL.

{% endnote %}

Без подписки события не записываются, и [im.v2.Event.get](./event-get.md) вернет пустой массив `events`. После отписки уже накопленные события остаются доступными до истечения срока хранения или до подтверждения через `offset`.

## Лимиты и ограничения {#limits}

#|
|| **Ограничение** | **Значение** ||
|| Событий за один вызов `im.v2.Event.get` | 1–1000, по умолчанию 100 ||
|| Срок хранения записанных событий | 24 часа ||
|| Способ доставки | Только polling. Webhook-режим для пользовательских событий не поддерживается ||
|| Число получателей | События одного пользователя может получать только одно приложение. Если пользователя подпишут несколько приложений, вызов с `offset` подтвердит и удалит записи для всех ||
|#

{% note warning "" %}

Ограничение на одного получателя намеренное: предполагается, что на события пользователя мгновенно реагирует один агент. Если нужно несколько независимых обработчиков, используйте разные пользовательские контексты или webhook-подписки.

{% endnote %}

## Чем отличается от событий чат-бота {#vs-imbot}

#|
|| **Если вам нужно** | **Открывайте раздел** ||
|| Читать поток событий от имени пользователя или приложения, без регистрации бота | Методы `im.v2.Event.*` на этой странице ||
|| Получать события бота — входящие сообщения, вызовы команд, добавление бота в чат | [События imbot.v2](../../imbot.v2/events/index.md) ||
|#

Отличий два. События `im.v2` требуют явной подписки, а подписка на события бота `ONIMBOTV2*` создается автоматически при регистрации бота. Кроме того, события `im.v2` доступны только через polling, а события бота можно получать и в webhook-режиме.

### События {#event-types}

Тип события приходит в поле `events[].type` ответа [im.v2.Event.get](./event-get.md), данные — в поле `events[].data`.

#|
|| **Событие** | **Вызывается** ||
|| [ONIMV2MESSAGEADD](./events.md#onimv2messageadd) | При появлении нового сообщения в чате, в котором состоит подписанный пользователь ||
|| [ONIMV2MESSAGEUPDATE](./events.md#onimv2messageupdate) | При редактировании сообщения в чате ||
|| [ONIMV2MESSAGEDELETE](./events.md#onimv2messagedelete) | При удалении сообщения в чате ||
|| [ONIMV2REACTIONCHANGE](./events.md#onimv2reactionchange) | При добавлении или удалении реакции на сообщение в чате ||
|| [ONIMV2JOINCHAT](./events.md#onimv2joinchat) | При добавлении нового участника в чат ||
|#
