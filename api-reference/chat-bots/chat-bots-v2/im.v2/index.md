# Работа с чатом: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы `im.v2` позволяют получать события пользователя при работе с чатами и работать с файлами в чатах без регистрации отдельного чат-бота.

{% note info "" %}

`im.v2` — методы нового поколения для работы с чатами. Сейчас их меньше, чем в основном разделе, но они будут постепенно заменять текущие реализации.

Уже существующие методы мессенджера доступны в разделе [Чаты с пользователем](../../../chats/index.md).

{% endnote %}

## Как выбрать раздел {#how-to-choose}

`im.v2` и `imbot.v2` решают разные задачи и не заменяют друг друга.

Основные отличия от методов бот-платформы:

- вызовы выполняются от имени текущего пользователя — параметры `botId` и `botToken` не нужны
- нужен scope `im`, а не `imbot`
- события требуют явной подписки и доставляются только в режиме polling

## Работа с событиями {#events}

Сначала приложение подписывается на запись событий, а затем само периодически забирает накопленную очередь.

1. Подпишитесь на запись событий через [im.v2.Event.subscribe](./events/event-subscribe.md).
2. Периодически получайте новые события через [im.v2.Event.get](./events/event-get.md).
3. Передавайте `offset`, чтобы подтверждать уже обработанные события.
4. Для остановки записи используйте [im.v2.Event.unsubscribe](./events/event-unsubscribe.md).

{% note info "Что такое режим polling" %}

Polling — режим получения событий, при котором приложение само периодически запрашивает у сервера накопленные события. Сервер не знает об адресе приложения и ничего не отправляет сам — он только накапливает очередь и отдает ее по запросу.

Это отличает polling от webhook: в webhook-режиме Битрикс24 сам вызывает URL приложения при каждом новом событии. Polling удобен, если у приложения нет постоянного HTTP-сервера или публичного URL.

{% endnote %}

Типы событий, которые приходят в поле `events[].type`: `ONIMV2MESSAGEADD`, `ONIMV2MESSAGEUPDATE`, `ONIMV2MESSAGEDELETE`, `ONIMV2REACTIONCHANGE`, `ONIMV2JOINCHAT`. Описание данных каждого — [Форматы событий](./events/events.md).

## Работа с файлами {#files}

- загрузите файл в чат через [im.v2.File.upload](./files/file-upload.md)
- получите ссылку для скачивания загруженного файла через [im.v2.File.download](./files/file-download.md)

Адресат задается параметром `dialogId`: для групповых чатов — `chat{chatId}`, для личных — ID собеседника. Подробнее — [Формат dialogId](../index.md#dialog-id).

## Лимиты и ограничения {#limits}

#|
|| **Ограничение** | **Значение** ||
|| Событий за один вызов `im.v2.Event.get` | 1–1000, по умолчанию 100 ||
|| Срок хранения записанных событий | 24 часа ||
|| Число получателей событий | События одного пользователя может получать только одно приложение ||
|| Максимальный размер файла в `im.v2.File.upload` | 100 МБ ||
|#

Общие лимиты REST API распространяются и на методы раздела — [Лимиты REST API](../../../../limits.md).
