# Файлы: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы загружают файлы в чат и возвращают ссылку на скачивание загруженного файла.

> Быстрый переход: [все методы](#all-methods)

## Порядок работы с файлом {#how-to-start}

1. Загрузите файл методом [im.v2.File.upload](./file-upload.md). Метод объединяет три шага устаревшего API в один вызов: загружает файл на Диск, прикрепляет его к чату и отправляет сообщение.
2. Сохраните из ответа `result.file.id` — это ID файла на Диске, и `result.messageId` — ID созданного сообщения с файлом.
3. Чтобы получить ссылку на скачивание, вызовите [im.v2.File.download](./file-download.md) и передайте `result.file.id` в параметре `fileId`.

Чат для загрузки задается параметром `dialogId` метода [im.v2.File.upload](./file-upload.md): для групповых чатов — `chat{chatId}`, для личных — ID собеседника. Подробнее — [Формат dialogId](../../index.md#dialog-id). Описание полей объекта File — [Объекты и поля](../../entities.md#file).

Оба метода появились в [im.v2](../index.md). В предыдущем поколении ту же задачу решала цепочка из трех вызовов: [im.disk.folder.get](../../../../chats/files/im-disk-folder-get.md), [disk.folder.uploadFile](../../../../disk/folder/disk-folder-upload-file.md) и [im.disk.file.commit](../../../../chats/files/im-disk-file-commit.md). Она описана в подразделе [Файлы в чатах](../../../../chats/files/index.md).

## Ограничения {#limits}

#|
|| **Ограничение** | **Значение** ||
|| Максимальный размер файла | 100 МБ ||
|| Формат передачи содержимого | Строка Base64 в `fields.content`, без префикса `data:*/*;base64,` ||
|| Текст сообщения вместе с файлом | Необязательный параметр `fields.message` ||
|#

Если метод [im.v2.File.upload](./file-upload.md) не может принять файл, он возвращает ошибку, и файл не появляется в чате. Типичные ошибки:

- `FILE_TOO_LARGE` — файл больше допустимого размера
- `FILE_INVALID_CONTENT` — содержимое не в формате Base64 или передано с префиксом `data:*/*;base64,`
- `FILE_EMPTY` — не передано имя файла или его содержимое

Структура ответа при ошибке описана в разделе [Формат ответа](../../index.md#format-otveta), полный список кодов — на странице метода.

Как подготовить содержимое файла — [Как загружать файлы](../../../../files/how-to-upload-files.md).

## Связь с другими объектами {#relations}

**Пользователь.** Методы работают от имени пользователя, чей вебхук или OAuth-токен приложения передан в запросе: файл появляется в чате как файл этого пользователя, отдельная регистрация бота не нужна. Способы авторизации — [Авторизация](../../index.md#auth).

**Чаты.** Файл загружается в конкретный диалог. Сами чаты создают и настраивают методами раздела [Чаты с пользователем](../../../../chats/index.md).

**События.** Загрузка файла создает сообщение в чате. Если приложение подписало пользователя на события методом [im.v2.Event.subscribe](../events/event-subscribe.md), оно получит событие [ONIMV2MESSAGEADD](../events/events.md#onimv2messageadd) при следующем вызове [im.v2.Event.get](../events/event-get.md) — [События im.v2](../events/index.md).

**Файлы от имени бота.** Те же операции от имени зарегистрированного чат-бота выполняют методы [imbot.v2.File.upload и imbot.v2.File.download](../../imbot.v2/files/index.md) — им нужен `botId`, а при вызове через вебхук еще и `botToken`.
