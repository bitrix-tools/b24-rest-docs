# Документы в Базе знаний 2.0: обзор методов

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Документы в Базе знаний 2.0 хранят содержимое базы знаний: заголовки, вложенные страницы и текст в Markdown. Методы `note.document.*` помогают создать документ, найти его в дереве, списке или поиске, обновить заголовок или содержимое, переместить ветку документов, получить схему полей документов, дерева и поиска, архивировать ветку или перенести ее в корзину и вернуть обратно.

>
> Пользовательская документация: [Битрикс24 База знаний 2.0: как создать и настроить](https://helpdesk.bitrix24.ru/open/28444346/)

## Как начать работу

1. Создайте базу знаний методом [note.collection.add](../collection/note-collection-add.md), если ее еще нет
2. Создайте корневой документ методом [note.document.add](./note-document-add.md)
3. Если нужна вложенная структура, создавайте дочерние документы тем же методом `note.document.add`, передавая `parentId` родительского документа
4. Получите структуру страниц одной базы знаний методом [note.document.tree.list](./note-document-tree-list.md). Чтобы обойти все доступные пользователю документы во всех базах знаний, используйте [note.document.list](./note-document-list.md)
5. Читайте отдельный документ методом [note.document.get](./note-document-get.md), если нужно получить его Markdown и служебные поля
6. Ищите документы методом [note.document.search.list](./note-document-search-list.md), если известна тема или часть текста
7. Обновляйте заголовок и содержимое методом [note.document.update](./note-document-update.md). Чтобы перенести документ в другую ветку или базу знаний либо изменить его позицию среди соседних, используйте [note.document.move](./note-document-move.md)
8. Уточните состав и типы полей методами `note.document.field.*`, `note.document.tree.field.*` и `note.document.search.field.*`, если строите форму, таблицу или поиск на своей стороне
9. Архивируйте документ методом [note.document.archive](./note-document-archive.md), если нужно скрыть его из активной работы, но сохранить структуру. Вернуть документ из архива можно методом [note.document.unarchive](./note-document-unarchive.md)
10. Удаляйте документ методом [note.document.delete](./note-document-delete.md), если нужно перенести его и дочерние страницы в корзину. Восстановить документ из корзины можно методом [note.document.restore](./note-document-restore.md)

## Ограничения и особенности

- При создании вложенной страницы родительский документ должен принадлежать той же базе знаний. Нельзя создать дочернюю страницу в одной базе знаний и привязать ее к документу из другой
- Размер содержимого `markdown` ограничен `1 048 576` байт. Если документ получается слишком большим, текст нужно сокращать или разбивать на несколько страниц
- В `markdown` можно вставить блок `assetMarkdown` из ответа [note.file.add](../file/note-file-add.md), например `[[image fileId=5001]]`. Для изображений и видео доступны параметры `width` и `align`; их формат описан в [note.document.update](./note-document-update.md). Для обычных файлов эти параметры не применяются
- Если у документа есть несохраненные изменения совместного редактора, обновление `markdown` может завершиться конфликтом. В таком случае нужно повторить запрос с `overwrite=true`, если содержимое действительно нужно перезаписать
- Каждый документ находится в одном из состояний, которое возвращается в поле `state`: `live` — активный, `archived` — в архиве, `trashed` — в корзине. Метод `note.document.tree.list` возвращает только активные документы, `note.document.list` — активные по умолчанию, а остальные по фильтру `state`. Метод `note.document.get` читает документ в любом состоянии
- Архивация документа затрагивает и все дочерние страницы ниже него. Обратный метод `note.document.unarchive` работает иначе: возвращает только указанный документ. Чтобы вернуть ветку целиком, вызывайте его для каждого документа сверху вниз, иначе дочерние страницы окажутся на верхнем уровне базы знаний
- Удаление документа тоже работает каскадно и переносит в корзину все поддерево страниц. Метод `note.document.restore` возвращает это поддерево целиком. Если в корзине лежит вся база знаний, документ отдельно не восстанавливается — восстановите базу знаний методом [note.collection.restore](../collection/note-collection-restore.md)
- Перемещение методом `note.document.move` переносит документ вместе со всеми дочерними страницами. Для переноса в другую базу знаний нужно право «Редактирование» в обеих базах знаний
- Метод `note.document.list` не сообщает об отказе в доступе: недоступные документы просто не попадают в ответ, поэтому пустой список — штатный результат

## Связь с другими объектами

**Базы знаний.** При создании документ связывается с [базой знаний](../collection/index.md) через `collectionId`. Изменить базу знаний документа можно методом [note.document.move](./note-document-move.md).

**Файлы.** Вложения привязаны к конкретному документу. Порядок загрузки и вставки вложений описан в [обзоре методов работы с файлами](../file/index.md).
