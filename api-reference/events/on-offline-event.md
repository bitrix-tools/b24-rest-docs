# Событие при появлении новых записей в очереди офлайн-событий onOfflineEvent

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

> Scope: [`базовый`](../scopes/permissions.md)
>
> Кто может подписаться: любой пользователь

Событие `ONOFFLINEEVENT` сработает, когда в очереди [офлайн-событий](./offline-events.md) появятся новые записи.

Событие заменяет опрос очереди по таймеру: приложение получает сигнал и забирает накопленные записи методами [event.offline.get](./event-offline-get.md) или [event.offline.list](./event-offline-list.md).

Подписывайтесь на `ONOFFLINEEVENT` только как на обычное событие — с URL обработчика в параметре `handler` метода [event.bind](./event-bind.md). Подписка с `event_type = offline` возвращает ошибку `ERROR_ARGUMENT` с текстом `Offline event cannot be registered for this event`: само уведомление об очереди в очередь не складывается.

Подписаться может любой пользователь, но только из приложения: `event.bind` работает лишь с авторизацией OAuth 2.0 и отклоняет вызов вебхука. Забрать записи из очереди методами `event.offline.*` может только администратор и тоже только в контексте приложения. Подробнее в статье [{#T}](./offline-events.md).

{% note info "" %}

События не будут отправляться в приложение, пока установка не завершена. [Проверьте установку приложения](../../settings/app-installation/installation-finish.md)

{% endnote %}

### Параметр data {#data}

Событие не передает данные о конкретных изменениях, а сообщает только о появлении новых записей в очереди. Полезной нагрузки у него нет, поэтому `data` приходит пустым — не стройте обработчик на разборе этого параметра.

Чтобы получить сами события, вызовите [event.offline.get](./event-offline-get.md) или [event.offline.list](./event-offline-list.md). Состав записи очереди описан на страницах этих методов.

## Периодичность уведомлений {#min-timeout}

Битрикс24 не отправляет отдельное уведомление на каждую запись очереди. Минимальный интервал между уведомлениями задается параметром `minTimeout` в объекте `options` при подписке методом [event.bind](./event-bind.md).

Это единственный параметр `options`, который поддерживает `ONOFFLINEEVENT`.

#|
|| **Название**
`тип` | **Описание** ||
|| **minTimeout**
[`integer`](../data-types.md) | Минимальный интервал между уведомлениями в секундах. По умолчанию — 1.

`0` — обработчик получит одно уведомление на один запрос к Битрикс24, сколько бы записей этот запрос ни добавил в очередь.

Больше `0` — первое срабатывание отправляет уведомление сразу, следующее уйдет не раньше, чем через указанное число секунд ||
|#

Тело запроса `event.bind` для подписки с интервалом 60 секунд:

```json
{
    "event": "ONOFFLINEEVENT",
    "handler": "https://example.com/handler.php",
    "options": {
        "minTimeout": 60
    }
}
```
