# Инструменты для локальных интеграций

Локальные интеграции — это программные решения, которые создаются и настраиваются на конкретном Битрикс24. Локальную интеграцию нельзя установить на другой Битрикс24: ее права доступа, обработчики событий и виджеты настраивает сотрудник той же компании. Если интеграцию нужно устанавливать на разные Битрикс24, выбирайте [тиражное приложение](../market/index.md).

Локальную интеграцию строят на двух инструментах — вебхуках и локальных приложениях. Они различаются способом авторизации, местом выполнения кода и набором доступных возможностей. Параметры, ответы и ошибки отдельных методов описаны в [Справочнике REST API](../api-reference/index.md).

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

## Типовые задачи для локальных интеграций

Локальные интеграции решают задачи, которые ограничены одним Битрикс24:

- импорт данных в CRM или другие инструменты Битрикс24
- обмен данными с внутренними системами компании
- автоматизация, связанная с массовой обработкой данных клиентов
- встраивание своих элементов в интерфейс Битрикс24

Готовые последовательности методов для таких задач собраны в статье [Локальные интеграции: сценарии использования](./use-cases.md).

## Как начать работу {#how-to-start}

1. Определите задачу интеграции и выберите инструмент в [таблице](#choose-tool).
2. Проверьте [права доступа](#rights): нужный `scope` и права сотрудника, от имени которого интеграция будет обращаться к Битрикс24.
3. Создайте интеграцию в разделе [Разработчикам](./developers-area.md) — *Приложения > Разработчикам*. Для серверного приложения заранее разместите обработчик на своем сервере и откройте его по HTTPS.
4. Проверьте первый запрос в генераторе запросов или по инструкции [Как выполнить свой первый запрос к API](../first-steps/first-rest-api-call.md).
5. Разберите готовый сценарий из статьи [Локальные интеграции: сценарии использования](./use-cases.md) и соберите свою последовательность методов.

## Входящие и исходящие вебхуки

[Вебхуки](./local-webhooks.md) подходят для быстрых интеграций, когда не требуется сложная логика авторизации.

Входящий вебхук — это секретный код, который сотрудник получает в интерфейсе Битрикс24 и подставляет в URL запроса. Входящий вебхук может быть ограничен датой окончания. Исходящий вебхук работает в обратную сторону: при наступлении события Битрикс24 сам отправляет данные на URL вашего обработчика.

Часть методов через вебхуки недоступна, потому что их логика требует контекста приложения. Это методы встраивания приложений в интерфейс Битрикс24, события телефонии и часть событий чат-ботов. Для таких сценариев нужно локальное приложение.

{% note warning "" %}

Для работы исходящего вебхука в коробочной версии Битрикс24 нужна активная лицензия, на демо-режимах исходящий вебхук недоступен

{% endnote %}

## Локальные приложения

[Локальные приложения](./local-apps.md) позволяют:

- создавать пользовательский интерфейс
- выполнять серверную обработку
- подписываться на события
- настраивать права доступа

Приложения делятся на статичные и серверные. Статичное приложение работает в браузере на HTML и JS, серверное выполняет код на вашем сервере. Серверные приложения различаются наличием интерфейса, поэтому вариантов три:

- [Статичное приложение](./static-local-app.md) — работает в браузере, не требует своего сервера, отображается как отдельная страница в интерфейсе Битрикс24
- [Серверное приложение с интерфейсом](./serverside-local-app-with-ui.md) — код выполняется на вашем сервере, отображается как страница или [встраиваемый виджет](../api-reference/widgets/index.md) внутри Битрикс24
- [Серверное приложение без интерфейса](./serverside-local-app-with-no-ui.md) — работает в фоне на вашем сервере, не отображается в интерфейсе, подходит для автоматических задач и синхронизации

{% note info "" %}

Статичное приложение не получает события Битрикс24 — у него нет серверного обработчика, которому Битрикс24 мог бы их передать. Если интеграция должна реагировать на изменение данных, выбирайте серверное приложение или исходящий вебхук

{% endnote %}

## Права доступа и безопасность {#rights}

- **Права.** Интеграция работает в рамках прав того сотрудника, который ее создал, и списка [scope](../api-reference/scopes/permissions.md), выбранного при создании. Метод вернет ошибку, если нужного `scope` нет или у сотрудника нет прав на объект.
- **Доступ к REST API.** Локальная интеграция работает, только если у Битрикс24 есть [доступ к REST API](../first-steps/access-to-rest-api.md) — по подписке Маркетплейс, в пробном режиме или по NFR-ключу.
- **Протокол.** Запросы вебхука выполняются только по HTTPS. Обработчик серверного приложения тоже должен быть доступен по HTTPS до того, как вы добавите приложение в Битрикс24.
- **Секретный код.** Утечка URL дает доступ к Битрикс24 в рамках прав вебхука до удаления вебхука или окончания срока действия. Не передавайте URL вебхука во внешние системы и не публикуйте его в коде клиентской части.
- **Удаление.** Удалить интеграцию может администратор Битрикс24 или сотрудник, который ее создал. Секретные коды чужих вебхуков недоступны даже администратору.

## Раздел Разработчикам

Раздел [Разработчикам](./developers-area.md) собирает инструменты для работы с локальными интеграциями. Открыть его можно через левое меню Битрикс24 по пути *Приложения > Разработчикам*.

### Готовые сценарии

Шаблоны для типовых задач с примерами кода и предустановленными параметрами на базе вебхуков и локальных приложений. Здесь же находится генератор запросов: он подбирает параметры метода, выполняет запрос и отдает готовый пример кода.

### Интеграции

Список всех созданных вебхуков и приложений с информацией о правах доступа, событиях и виджетах. Из списка можно перейти к настройкам интеграции или удалить ее.

### Статистика

График общего количества запросов и детализация по каждой интеграции. Помогает контролировать нагрузку и находить интеграцию, из-за которой REST заблокирован.
