# 1С:Предприятие: типовые сценарии интеграции по REST API

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Страница помогает выбрать туториал для интеграции 1С:Предприятия с Битрикс24: передать контрагента, выставить счет, выгрузить номенклатуру, прикрепить печатную форму.

REST API Битрикс24 не требует специальной библиотеки для 1С. Конфигурация обращается к Битрикс24 обычным HTTP-запросом: объекты `HTTPСоединение` и `HTTPЗапрос` отправляют тело в формате JSON, встроенные функции `ЗаписатьJSON` и `ПрочитатьJSON` собирают и разбирают данные. Весь код в туториалах раздела написан на встроенном языке 1С:Предприятия и работает в любой конфигурации — типовой или самописной.

> Быстрый переход: [все туториалы раздела](#tutorials) и [что нужно перед началом](#before-start)

{% note info "" %}

Если задача — типовой обмен документами и справочниками с 1С:Управление торговлей, 1С:Бухгалтерия или другой типовой конфигурацией, сначала посмотрите готовые решения в [Битрикс24 Маркет](https://www.bitrix24.ru/apps/). Собственная интеграция на REST API нужна, когда готовое решение не покрывает сценарий: нестандартная конфигурация, свои документы, свои правила сопоставления объектов.

{% endnote %}

## Что нужно перед началом {#before-start}

- **Платформа 1С:Предприятие 8.3.10 и новее.** Примеры используют встроенную работу с JSON и объект `HTTPСоединение`. Отдельные примеры отмечены, если требуют более новой версии платформы
- **Входящий вебхук Битрикс24** со scope, которые нужны сценарию. Как создать вебхук — на странице [Как выполнить свой первый запрос к API](../../first-steps/first-rest-api-call.md). Вебхук выполняет запросы с правами пользователя, который его создал
- **Доступ в интернет с того компьютера, где выполняется код.** Код работает на стороне сервера 1С или в толстом клиенте. Если организация использует прокси, передайте объект `ИнтернетПрокси` в конструктор `HTTPСоединение`
- **Тестовый Битрикс24 и тестовые данные.** Сценарии создают и изменяют объекты CRM. Проверяйте примеры на тестовом Битрикс24, а не на рабочем

Вебхук подходит, когда интеграция работает с одним Битрикс24 — это основной случай для обмена с 1С. Если решение устанавливается разным клиентам, используйте [приложение с авторизацией OAuth 2.0](../../settings/oauth/index.md): код запросов остается тем же, меняется только способ передачи авторизации.

{% note alert "" %}

Секретный код вебхука дает полный доступ к данным в рамках своих scope. Храните его в константе или в защищенном хранилище конфигурации, не сохраняйте в коде модуля и не выгружайте вместе с обработкой.

{% endnote %}

## Как связать объекты 1С и Битрикс24 {#mapping}

Главный вопрос любого обмена — как при следующей выгрузке понять, что объект уже передан. В Битрикс24 для этого есть системные поля, куда записывают идентификатор объекта из внешней системы. Обычно это GUID ссылки 1С — значение `Строка(Объект.Ссылка.УникальныйИдентификатор())`.

#|
|| **Объект Битрикс24** | **Куда записать идентификатор 1С** ||
|| Компания, контакт, лид, сделка | Поля `ORIGINATOR_ID` — код внешней системы и `ORIGIN_ID` — идентификатор объекта в ней. Поля доступны в фильтре списочных методов ||
|| Реквизит, банковский реквизит | Поле `XML_ID` ||
|| Элемент смарт-процесса, счет | Поле `xmlId` методов [crm.item.*](../../api-reference/crm/universal/index.md) ||
|| Товар торгового каталога | Поле `xmlId` методов [catalog.product.*](../../api-reference/catalog/product/index.md) ||
|#

Второй вариант — хранить соответствие на стороне 1С в регистре сведений: ссылка на объект, тип объекта Битрикс24 и его идентификатор. Так удобно вести обмен сразу с несколькими Битрикс24 и видеть историю выгрузки.

Оба подхода дополняют друг друга: регистр сведений в 1С отвечает на вопрос «куда я выгрузил этот объект», а поля `ORIGIN_ID` и `xmlId` в Битрикс24 позволяют восстановить связь, если регистр потерян или обмен запускают с новой базы.

## Как начать работу

1. Создайте входящий вебхук и выполните тестовый запрос — [Как выполнить свой первый запрос к API](../../first-steps/first-rest-api-call.md)
2. Перенесите в свою конфигурацию общий модуль из туториала [Как выполнить первый запрос из 1С](./first-request.md). Он выполняет запрос, разбирает ответ и обрабатывает ошибки — остальные сценарии вызывают его функции
3. Выберите сценарий в таблице [Туториалы раздела](#tutorials) и адаптируйте пример под свою конфигурацию
4. Проверьте результат в интерфейсе Битрикс24

## Что учесть при обмене

- **Лимиты интенсивности.** Битрикс24 ограничивает частоту запросов: на большинстве тарифов это 2 запроса в секунду в среднем. При превышении метод возвращает ошибку `QUERY_LIMIT_EXCEEDED`. Подробно — на странице [Лимиты REST API](../../limits.md)
- **Один запрос — не дольше 60 секунд.** Долгую выгрузку разбивайте на страницы и запускайте фоновым или регламентным заданием, а не в сеансе пользователя
- **Пакетные вызовы.** Метод [batch](../../settings/how-to-call-rest-api/batch.md) передает до 50 вызовов в одном HTTP-запросе — это основной способ ускорить выгрузку из 1С
- **Часовые пояса.** Битрикс24 возвращает даты в формате ISO 8601 со смещением, например `2026-08-21T14:43:13+03:00`. В 1С тип `Дата` смещения не хранит, поэтому при разборе ответа приводите дату к нужному часовому поясу явно
- **Идемпотентность.** Обмен может повториться после сбоя связи. Перед созданием объекта проверяйте, не создан ли он раньше — по `ORIGIN_ID`, `xmlId` или по ИНН
