REST API — способ связать Битрикс24 с другими программами: сайтом, учетной системой, мобильным приложением или собственным сервисом. Программа отправляет в Битрикс24 запрос к методу — команде API, например «создать сделку». Битрикс24 выполняет действие и возвращает ответ с результатом.

Программу, которая работает с Битрикс24 через REST API, называют интеграцией. Она может создавать сделки в CRM из заявок с сайта, ставить задачи сотрудникам или отвечать клиентам в чатах через бота.

Для знакомства с REST API пройдите три шага:

1. [Получите доступ к REST API](#access)
2. [Выполните первый запрос](#first-call) и проверьте ответ Битрикс24
3. [Выберите дальнейший маршрут](#kak-vybrat-marshrut) под свою задачу

## Доступ к REST API {#access}

В облачном Битрикс24 в зоне ru для первого запроса из этой статьи нужна подписка Маркетплейс или пробный режим. Как их подключить, описано в статье [Как получить доступ к REST API](./access-to-rest-api.md). В коробочной версии для входящих вебхуков подписка не требуется. Партнеры, которые разрабатывают тиражные приложения, найдут там же, как получить NFR-ключ: он включает REST API в тестовом Битрикс24.

Когда доступ есть, переходите к разделу [Первый запрос к API](#first-call).

## Первый запрос к API {#first-call}

Для первого запроса создайте входящий вебхук. Это инструмент, который принимает запросы вашей программы по специальному адресу с секретным кодом. Пошаговая инструкция — в статье [Как выполнить свой первый запрос к API](./first-rest-api-call.md).

Проверьте вебхук методом [profile](../api-reference/common/users/profile.md): он работает без параметров и возвращает данные пользователя, от имени которого выполняется запрос. Для него не нужно выбирать отдельный [scope](../api-reference/scopes/permissions.md) — группу методов, доступную вебхуку.

Скопируйте адрес своего вебхука: в нем уже есть адрес Битрикс24, ID пользователя и секретный код. Допишите в конце `profile.json` и откройте получившийся адрес в браузере. Шаблон адреса:

```text
https://**put_your_bitrix24_address**/rest/**put_your_user_id_here**/**put_your_webhook_here**/profile.json
```

После проверки удалите этот адрес из истории браузера: в нем есть секретный код вебхука. Не публикуйте код в репозиториях, на веб-страницах и в логах.

Данные метода приходят в поле `result`, служебная информация о запросе — в поле `time`. Полный ответ с описанием полей есть на странице метода [profile](../api-reference/common/users/profile.md), а здесь он сокращен:

```json
{
    "result": {
        "ID": "1",
        "NAME": "Вадим",
        "LAST_NAME": "Валеев"
    },
    "time": {
        "duration": 0.0401120185852051
    }
}
```

Такой ответ значит, что вебхук работает. Дальше вызывайте методы под свою задачу, например [crm.item.add](../api-reference/crm/universal/crm-item-add.md), чтобы создать сделку. Для этого метода нужен scope `crm`: какой scope нужен другим методам, указано на их страницах.

Если вместо `result` пришли поля `error` и `error_description`, запрос не выполнился. Например, если в адресе ошибка в секретном коде вебхука или в ID пользователя, Битрикс24 вернет:

```json
{
    "error": "INVALID_CREDENTIALS",
    "error_description": "Invalid request credentials"
}
```

В этом случае сверьте ID пользователя и секретный код с адресом вебхука в Битрикс24. Что означают другие ошибки, описано в статье [Коды ошибок](../error-codes.md).

## Настройка REST API {#settings}

Раздел [Настройка и использование REST API](../settings/index.md) отвечает на вопросы, которые возникают при разработке интеграции:

- как вызывать методы и передавать параметры
- как авторизоваться через OAuth 2.0
- как установить и настроить приложение
- чем работа в облаке отличается от работы в коробочной версии
- как работать под нагрузкой и не упираться в лимиты

### Что подготовить перед началом

Выберите [способ подключения](#local-integrations): входящий вебхук или приложение. В его настройках укажите нужные [scope](../api-reference/scopes/permissions.md), например `crm` для работы с CRM. Права пользователя scope не расширяет: если пользователь не видит чужие сделки, интеграция от его имени их тоже не увидит.

Секретный код вебхука, токены и ключи приложения не должны попадать в публичные репозитории, на веб-страницы и в логи.

В облачном Битрикс24 учитывайте [лимиты REST API](../settings/performance/limits.md): если отправлять запросы слишком часто, сервис начнет временно их отклонять. В коробочной версии нагрузку настраивают на стороне сервера.

Если коробочный Битрикс24 или ваше приложение работает в закрытой сети компании, откройте статью [Необходимые сетевые доступы](../settings/cloud-and-on-premise/network-access.md). В ней описано, какие запросы разрешить на фаерволе и где взять IP-адреса. Облачному Битрикс24 такая настройка не нужна.

Чтобы разобраться в архитектуре приложений, авторизации и настройке окружения, изучите [курс по разработке приложений для Битрикс24](https://dev.1c-bitrix.ru/learning/course/index.php?COURSE_ID=266&INDEX=Y).

## Локальные интеграции {#local-integrations}

Раздел [Инструменты для локальных интеграций](../local-integrations/index.md) посвящен вебхукам и приложениям для интеграций, которые работают с одним Битрикс24 и не требуют публикации в Маркетплейсе. Там же есть примеры для автоматизации рутинных операций и обмена данными.

Выберите способ подключения:

- входящий вебхук — для интеграции, которая работает от имени одного пользователя. Запросы выполняются с правами того, кто создал вебхук
- приложение — для интеграции, которая работает от имени разных пользователей или встраивается в интерфейс Битрикс24. Приложение устанавливают в Битрикс24, например чтобы добавить вкладку в карточку сделки. Порядок установки описан в статье [Варианты установки приложений в Битрикс24](../settings/app-installation/index.md)
