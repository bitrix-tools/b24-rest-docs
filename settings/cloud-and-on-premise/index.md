# Облако и коробка Битрикс24

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Битрикс24 работает как облачный сервис и как коробочные установки на сервере клиента. Приложение на REST использует в обеих версиях одни и те же методы, события и OAuth-авторизацию. Раздел помогает подготовить приложение к работе с коробочной версией: учесть ее отличия, открыть нужные сетевые доступы на стороне клиента и соблюсти требования безопасности.

## Чем коробка отличается от облака

| Что отличается | Облако | Коробка | Подробнее |
|---|---|---|---|
| Версия REST | Всегда последняя | Обновления выходят позже облака, владелец может их не установить | [{#T}](on-premise/versions.md) |
| Состав модулей | Модули и обновления устанавливает Битрикс24 | Владелец может не установить или отключить модуль, например телефонию. Методов и событий такого модуля не будет | [{#T}](on-premise/index.md) |
| Доставка событий | Через очередь событий в облаке Битрикс24 | Тоже через облачную очередь событий. Если сетевой доступ к ней закрыт, события не приходят | [{#T}](network-access.md) |
| Проверка токенов | Сервер авторизации `oauth.bitrix24.tech` | Тот же сервер. Если доступ к нему закрыт, REST не работает. Обновлять токены нужно запросом напрямую к `oauth.bitrix24.tech` | [{#T}](on-premise/index.md) |
| Сетевые доступы | Настраивать не нужно | Администратор сети клиента открывает направления к серверам Битрикс24 | [{#T}](network-access.md) |
| Изолированная сеть | Не применяется | Можно подключить собственный механизм авторизации и событий без `oauth.bitrix24.tech`. Это крайний вариант: за безопасность авторизации отвечаете вы | [{#T}](on-premise/custom-auth-provider.md) |
| Свои методы REST | Недоступны | Можно добавить свои методы и scope | [{#T}](on-premise/custom-methods.md) |

## Когда нужен этот раздел

- Приложение будут устанавливать в коробочный Битрикс24 — проверьте доступность методов и событий при установке по статье [{#T}](on-premise/index.md)
- Внедряете решение у клиента с фаерволом — согласуйте с администратором сети правила из статьи [{#T}](network-access.md)
- Готовите приложение к публикации или релизу — пройдите чек-лист из статьи [{#T}](security-recommendations.md). Рекомендации применимы и к облаку, и к коробке
- Приложение работает только с облачным Битрикс24 — отличия коробки учитывать не нужно, сетевые доступы настраивать тоже
