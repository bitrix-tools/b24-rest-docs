Тиражное приложение перед работой нужно установить на конкретный Битрикс24. Эта страница объясняет, какие четыре варианта установочного процесса можно выбрать и чем они отличаются. После чтения вы сможете подобрать подходящий вариант установки для своего приложения.

Страница дает обзор и критерии выбора. Пошаговую настройку каждого варианта смотрите на дочерних страницах по ссылкам ниже.

## Порядок работы над тиражным приложением

Что такое установка и зачем она нужна, описано в обзоре [{#T}](../index.md). Ниже собрано то, что специфично для тиражных приложений.

Обычный порядок работы: разработчик создает приложение в кабинете разработчика, пишет код и тестирует его, устанавливая приложение из кабинета на доступный Битрикс24 с административным доступом, и только после проверки готовности отправляет решение на модерацию. Опубликованное решение пользователи устанавливают из Битрикс24 Маркетплейс. Подробнее о подготовке к публикации — в разделе [{#T}](../../../market/preparing-to-publish/how-to-add-app.md).

Вариант установки выбирают по сценарию онбординга пользователей. Заранее определите, какой будет процедура установки и нужна ли она вообще.

## Варианты установочного процесса

Существует четыре варианта установочного процесса:

- **Добавление без установочного сценария** — приложение начинает работать сразу после установки. Подходит, когда приложению не нужны одноразовые настройки при установке.
- **[Добавление с мастером установки](./installation-master.md)** — при установке Битрикс24 открывает ваш интерфейс, где можно выполнить одноразовые операции: зарегистрировать виджеты, подписаться на события и другое. Подходит приложениям с интерфейсом, которым нужна первичная настройка.
- **[Добавление с мастером настройки для REST-only приложения](./rest-only-installation-master.md)** — встроенная форма Битрикс24 для приложений без своего интерфейса. Подходит, когда нужны простые настройки и данных от callback-обработчика недостаточно.
- **[Добавление с вызовом установочного callback](./installation-callback.md)** — после установки Битрикс24 отправляет токены OAuth на ваш обработчик. Подходит приложениям без интерфейса, вся логика которых работает в обработчиках событий.

Чаще всего для тиражных приложений выбирают мастер установки. При установке обычно нужно выполнить одноразовые операции — зарегистрировать места встройки виджетов, подписаться на события и другое.

Три варианта с отдельными страницами подробно разобраны по ссылкам в списке выше. Вариант «Добавление без установочного сценария» описан на этой странице.

## Добавление без установочного сценария

Чтобы процедура установки отсутствовала, а приложение сразу работало, заполните поле «Ссылка на приложение» в карточке версии. Укажите в нем основной URL приложения — по этому адресу интерфейс приложения встраивается в левое меню Битрикс24.

Для статического приложения — архива с файлами HTML и JS — достаточно поместить в архив файл index.html.

В обоих случаях после установки приложение сразу доступно пользователям без отдельной процедуры установки.

Если у приложения нет пользовательского интерфейса, отключите опцию «Добавлять свою страницу и пункт в главном меню». Установка в этом случае не нужна, но приложению все равно нужны токены REST API. Получить их поможет [callback-обработчик](./installation-callback.md), который Битрикс24 вызовет сразу после установки.
