# Варианты установки приложений в Битрикс24

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Установка приложения в Битрикс24 зависит от типа решения: локальное приложение, тиражное приложение или конфигурационное решение. Сценарий для каждого типа описан в отдельной статье — ссылки собраны в таблице ниже.

## Как устроена установка

Установка приложения — это его регистрация на конкретном Битрикс24, а не скачивание кода. После регистрации сервер авторизации Битрикс24 начинает выдавать приложению [токены OAuth 2.0](../oauth/index.md), с которыми оно работает через REST API этого Битрикс24.

Установка локального или тиражного приложения проходит в три этапа:

1. **Добавление приложения** — локальное приложение разработчик создает в разделе *Разработчикам* на своем Битрикс24, тиражное добавляет в [кабинете разработчика](../../market/preparing-to-publish/how-to-add-app.md), а после тестирования и модерации публикует в Битрикс24 Маркетплейс
2. **Установка на Битрикс24** — сервер регистрирует приложение и выдает ему токены OAuth 2.0. Установку запускает администратор Битрикс24 или сотрудник, которому администратор разрешил устанавливать приложения. Локальное приложение разработчик устанавливает на своем Битрикс24. Тиражное устанавливает администратор из Битрикс24 Маркетплейс или разработчик из кабинета разработчика на любой Битрикс24, где у него есть административный доступ
3. **Завершение установки** — приложение с мастером установки вызывает функцию JS SDK [BX24.installFinish()](../../sdk/bx24-js-sdk/system-functions/bx24-install-finish.md). Остальные приложения Битрикс24 считает установленными сразу. Есть ли у приложения мастер, задают его настройки. Подробности — в статье [Завершение установки приложений](./installation-finish.md)

После установки у приложения выходят новые версии, его могут удалить с Битрикс24. Что происходит в этих случаях, описано в статьях [{#T}](../app-update.md) и [{#T}](../app-uninstallation.md).

## Варианты установки

Типы решений и статьи об их установке — в таблице. Конфигурационное решение — готовый набор настроек Битрикс24, который работает без REST API. Битрикс24 загружает его из Битрикс24 Маркетплейс и сам применяет настройки.

#|
|| **Тип решения** | **Что это** | **Где описана установка** ||
|| Локальное приложение | Приложение, которое работает внутри одного Битрикс24, где его создали | [Локальные приложения](./local-apps/index.md) ||
|| Тиражное приложение | Приложение, которое публикуется в Битрикс24 Маркетплейс и устанавливается на разные Битрикс24 | [Тиражные приложения](./mass-market-apps/index.md) ||
|| Отраслевая CRM | Конфигурационное решение с настройками CRM: воронками сделок, стадиями лидов, пользовательскими полями, роботами и бизнес-процессами | [Установка отраслевых CRM](./vertical-crm-installation.md) ||
|| Умные сценарии | Конфигурационное решение на базе роботов CRM, встраиваемых в объекты за пределами воронок | [Установка умных сценариев](./smart-scripts-installation.md) ||
|| Шаблоны сайтов | Конфигурационное решение с готовым одностраничным или многостраничным сайтом | [Установка шаблонов сайтов](./site-templates-installation.md) ||
|#

В виде конфигурационных решений публикуют также [шаблоны BI-конструктора](../../market/preparing-to-publish/requirements-superset.md) и другие типы решений, которые не используют REST API.

**Как выбрать между локальным и тиражным приложением.** Локальное приложение подходит, когда интеграция нужна одному Битрикс24, например своей компании или одному клиенту. Его создают прямо в этом Битрикс24, без кабинета разработчика и модерации. Тиражное приложение выбирайте, когда решение нужно устанавливать на разные Битрикс24 — распространять через Битрикс24 Маркетплейс. Его создают в кабинете разработчика, а перед публикацией оно проходит модерацию.

{% note info "" %}

Если вы планируете тиражное приложение, ведите разработку сразу в кабинете разработчика. Сценарий установки тиражного приложения может отличаться от локального. Тогда установку, отлаженную на локальном приложении, придется переделывать.

{% endnote %}
