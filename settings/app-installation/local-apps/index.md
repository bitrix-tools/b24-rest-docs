# Установка локальных приложений: обзор сценариев

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Локальное приложение работает внутри одного Битрикс24 — там, где его создали. Сценарий установки определяет, что происходит после сохранения формы приложения. Страница помогает выбрать сценарий и заполнить для него форму. Виды локальных приложений и условия их создания описаны в статье [{#T}](../../../local-integrations/local-apps.md).

> Быстрый переход: [как выбрать сценарий](#installation-scenarios)
>
> Пользовательская документация: [Разработчикам: как создать вебхуки и приложения для Битрикс24](https://helpdesk.bitrix24.ru/open/20886106/#2)

## Связь с другими объектами

**OAuth 2.0.** Битрикс24 передает приложению данные авторизации, с которыми оно выполняет методы. Получение и обновление токенов описано в разделе [OAuth 2.0](../../oauth/index.md).

**События и виджеты.** Во время первоначальной настройки приложение может зарегистрировать [обработчики событий](../../../api-reference/events/index.md) или добавить [виджеты](../../../api-reference/widgets/index.md) в интерфейс Битрикс24.

## Как начать работу

1. Подготовьте код: ZIP-архив для статичного приложения или страницу и обработчик для серверного. Адреса серверного приложения должны начинаться с `https://` или `http://`, для рабочего приложения используйте HTTPS. В сценарии callback обработчик должен работать до сохранения формы: Битрикс24 отправит на него данные авторизации сразу после сохранения
2. Откройте форму: *Разработчикам*, вкладка *Готовые сценарии*, далее *Другое > Локальное приложение*
3. Укажите название, права доступа и поля сценария из таблицы [Как выбрать сценарий](#installation-scenarios)
4. Сохраните приложение. Если выбран [мастер установки](./installation-master.md), откройте приложение и пройдите настройку. Если выбран [callback установки](./installation-callback.md), проверьте, что обработчик сохранил токены

## Что важно учитывать

- **Доступ.** Создать локальное приложение может администратор Битрикс24 или сотрудник с правом на создание приложений. Как выдать это право, описано в разделе [Как настроить доступ к созданию приложений](../../../local-integrations/local-apps.md#local-app-access)
- **Права приложения.** Набор прав `scope` выбирают в форме. Мастер установки и обработчик callback вызывают методы только в пределах этого набора. Где хранить секретный ключ и токены, описано в статье [{#T}](../../../local-integrations/local-apps.md)
- **Смена сценария.** Сохранение формы не переустанавливает приложение. Если у сохраненного приложения изменить *Путь для первоначальной установки* или опцию *Приложение само завершает установку*, нажмите в форме *Переустановить*, чтобы применить новый сценарий

## Как выбрать сценарий {#installation-scenarios}

У серверного приложения сценарий определяют поле *Путь для первоначальной установки* и опция *Приложение само завершает установку*. По умолчанию опция выключена. У статичного приложения этих настроек нет: сценарий зависит от того, есть ли в корне архива файл `install.html`.
