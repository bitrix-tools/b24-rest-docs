# Как вызывать методы REST API

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Методы REST API Битрикс24 вызывают по HTTP. В запросе передают авторизационные данные и параметры метода, а в ответ получают `JSON` или `XML`. Запрос можно отправить из любого языка и инструмента, который работает с протоколом HTTP.

Материалы раздела объясняют, как собрать такой запрос и что учесть в рабочей интеграции. Описания конкретных методов и их параметров лежат в [Справочнике методов](../../api-reference/index.md).

Если вы делаете первый вызов, начните с авторизации и общей схемы запроса. Если интеграция уже работает, переходите сразу к материалам про кодирование, `batch` или списочные методы.

> Быстрый переход: [все материалы раздела](#all-materials)

## Что подготовить перед первым вызовом {#before-start}

**Адрес Битрикс24.** Подготовьте домен, к которому отправляете запросы. Если Битрикс24 меняет адрес, обработайте редирект по рекомендациям из статьи [об изменении адреса Битрикс24](./change-domen.md).

**Название метода и параметры.** Подготовьте имя метода и параметры запроса. Для первого теста возьмите пример со страницы [Первый вызов REST API](../../first-steps/first-rest-api-call.md) или простой метод чтения, например `user.current`.

## Как выбрать способ авторизации {#auth}

#|
|| **Сценарий** | **Что выбрать** ||
|| Быстрый первый вызов, проверка метода или локальная интеграция без приложения | Входящий вебхук ||
|| Локальное или тиражное приложение, работа от имени разных пользователей, управление доступом | OAuth 2.0 ||
|#

Способы отличаются только тем, как в запрос попадают авторизационные данные:

- у вебхука идентификатор пользователя и секретный код встроены в путь — `https://your-domain.bitrix24.com/rest/USER_ID/WEBHOOK_CODE/method`
- у приложения временный токен передается в параметре `auth` — `https://your-domain.bitrix24.com/rest/method?auth=ACCESS_TOKEN`

Подробности смотрите в статье [Авторизация в REST](./authorization.md).

## Как выполнить первый вызов {#first-call}

1. Выберите способ авторизации: вебхук или OAuth 2.0
2. Соберите URL запроса по схеме из статьи [Как выполняется запрос](./general-principles.md)
3. Передайте параметры в `GET` или `POST`. Для методов с поддержкой `JSON` используйте `POST` с телом запроса в этом формате
4. Закодируйте специальные символы и сложные параметры по правилам из статьи [Кодирование данных](./data-encoding.md)
5. Выполните запрос и проверьте поле `result` или описание ошибки в ответе
6. Если метод возвращает список, обработайте поля `total` и `next` по статье [Особенности списочных методов](./list-methods-pecularities.md)
7. Если нужно сократить число обращений, объедините вызовы через [batch](./batch.md)

**Пример вызова.** Метод `user.current` возвращает данные пользователя, от имени которого выполняется запрос. Ему не нужны параметры, поэтому он подходит для проверки авторизации:

```bash
curl -X POST \
-H "Content-Type: application/json" \
-d '{}' \
https://your-domain.bitrix24.com/rest/1/8g9l071eismy9q2l/user.current.json
```

В адресе указаны домен Битрикс24, идентификатор пользователя, создавшего вебхук, секретный код вебхука и название метода. Успешный ответ содержит данные в поле `result` и время выполнения в объекте `time`:

```json
{
    "result": {
        "ID": "1",
        "ACTIVE": true,
        "NAME": "Иван",
        "LAST_NAME": "Петров"
    },
    "time": {
        "start": 1721722262.960948,
        "finish": 1721722262.985244,
        "duration": 0.024296045303344727,
        "processing": 0.0012989044189453125,
        "date_start": "2024-07-23T08:11:02+00:00",
        "date_finish": "2024-07-23T08:11:02+00:00",
        "operating": 0
    }
}
```

В примере ответа оставлены только ключевые поля. Полный состав данных смотрите на странице метода [user.current](../../api-reference/user/user-current.md).

Если авторизационные данные неверны или у пользователя нет прав, вместо `result` придет описание ошибки. Расшифровки смотрите в статье [Коды ошибок](../../error-codes.md).

## Права и безопасность {#security}

**Права пользователя.** Метод всегда выполняется от имени конкретного пользователя Битрикс24: для вебхука — от имени того, кто его создал, для приложения — от имени владельца токена. Через REST доступно ровно то, что доступно этому пользователю в интерфейсе.

**Скоупы.** Приложение дополнительно ограничено набором [скоупов](../../api-reference/scopes/permissions.md), которые запрошены при установке. Вебхуку скоупы выбирают при создании. Если метод вернул ошибку доступа, проверьте и права пользователя, и выданные скоупы.

**Секреты.** Код вебхука и токен приложения дают доступ к данным Битрикс24. Не публикуйте их, не передавайте в клиентский код и не пишите в логи. Токен OAuth 2.0 живет ограниченное время и обновляется — порядок описан в статье [Автоматическое продление токенов OAuth 2.0](../oauth/auto-renewal.md).

**Административный доступ.** Локальное приложение добавляет администратор Битрикс24. Вебхук может создать любой пользователь в пределах своих прав.

## Что учитывать в рабочих интеграциях {#production}

**Приложение.** Если интеграция работает как приложение, способ получения токена и сценарий работы с ним зависят от установки и контекста приложения. Подробности смотрите в разделе [OAuth 2.0](../oauth/index.md).

**Кодирование.** Проверяйте URL-кодирование при передаче специальных символов, например `&`, `?`, `%`, `[`, `]` и `#`. Отдельно проверьте вложенные запросы в [batch](./batch.md).

**Формат тела запроса.** Для массивов и вложенных объектов передавайте `POST` с `Content-Type: application/json`. Так структура параметров сохраняется без преобразования в строку запроса.

**Пакетные вызовы.** Метод [batch](./batch.md) выполняет до 50 команд за один запрос и позволяет использовать результат предыдущей команды в следующей.

**Лимиты.** При частых и тяжелых вызовах учитывайте [лимиты REST API](../performance/limits.md). Это особенно важно для списков и пакетных запросов. Как снизить нагрузку, описано в статье [Рекомендации по производительности](../performance/index.md).
