# Удаление приложений

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Когда администратор удаляет приложение, Битрикс24 снимает его подписки на события, встройки и другие регистрации, через которые приложение работает. Что станет с данными приложения, зависит от его типа. [Локальное приложение](../local-integrations/local-apps.md) Битрикс24 всегда удаляет с очисткой данных. При удалении [тиражного приложения](./app-installation/mass-market-apps/index.md) администратор сам решает, удалить данные или оставить их на случай повторной установки.

Например, если администратор удалил тиражное приложение платежной системы и не отметил удаление данных, приложение перестанет работать, а его платежная система останется в Битрикс24.

## Как приложение узнает об удалении

Приложение узнает об удалении по событию [OnAppUninstall](../api-reference/common/events/on-app-uninstall.md), если заранее подписалось на него. Тиражному приложению событие нужно, чтобы вовремя прекратить запросы к этому Битрикс24: после удаления приложение теряет доступ к REST API. Например, на вызов с прежним токеном Битрикс24 отвечает ошибкой `APPLICATION_NOT_FOUND`.

В поле `CLEAN` события Битрикс24 передает признак очистки данных: у тиражного приложения он зависит от выбора администратора, у локального очистка включена всегда.

Прежде чем прекратить работу по этому событию, проверьте, что его отправил Битрикс24: сверьте `application_token` из события с актуальным значением, которое приложение сохраняет при установке и обновляет по событию [ONAPPUPDATE](../api-reference/common/events/on-app-update.md). Как это сделать, описано в статье [{#T}](../api-reference/events/safe-event-handlers.md).

## Что удаляется всегда {#always}

Независимо от типа приложения и выбора очистки данных Битрикс24 удаляет:

- подписки на [события](../api-reference/events/index.md)
- [встройки](../api-reference/widgets/index.md) и [пользовательские типы полей](../api-reference/widgets/user-field/index.md)
- [роботов](../api-reference/bizproc/bizproc-robot/index.md) и [действия бизнес-процессов](../api-reference/bizproc/bizproc-activity/index.md)
- [чат-ботов](../api-reference/chat-bots/index.md)
- [коннекторы открытых линий](../api-reference/imopenlines/imconnector/index.md)
- [провайдеры сообщений](../api-reference/messageservice/index.md)
- [внешние линии телефонии](../api-reference/telephony/index.md#external-telephony)

Если у тиражного приложения есть [системный пользователь](./system-user.md), Битрикс24 деактивирует его независимо от выбора очистки данных.

## Что зависит от очистки данных

При удалении тиражного приложения Битрикс24 предлагает опцию *Удалить настройки и данные приложения*. Для платежных систем, касс и служб доставки очистка касается обработчиков приложения и всех объектов, которые их используют.

## Что остается после удаления

Удаление приложения не затрагивает объекты, которые приложение создало в инструментах Битрикс24:

- пользовательские поля и их значения
- [типы дел CRM](../api-reference/crm/timeline/activities/types/index.md)
- [смарт-процессы](../api-reference/crm/universal/user-defined-object-types/index.md)

Поля собственного типа приложения останутся, но перестанут отображаться в карточке — подробнее в описании метода [userfieldtype.delete](../api-reference/widgets/user-field/userfieldtype-delete.md).

## Повторная установка

Отменить удаление нельзя.

Тиражное приложение можно установить на тот же Битрикс24 повторно. Если администратор оставил данные при удалении, приложение снова получит доступ к своим хранилищам и настройкам. Подписки на события, встройки и другие регистрации из раздела [Что удаляется всегда](#always) приложению нужно создать заново.

Локальное приложение после удаления можно только создать заново. Новое приложение получит новую пару `client_id` и `client_secret` для [OAuth-авторизации](./oauth/index.md), даже если адреса обработчиков совпадают со старыми.
