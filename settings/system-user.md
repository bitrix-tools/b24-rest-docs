# Системный пользователь

Системный пользователь — это техническая учетная запись. Как и обычный сотрудник, в Битрикс24 он существует на уровне пользователя, но работником компании не является и нужен только для работы интеграций.

На странице описано, когда Битрикс24 создает системного пользователя, как на него переносятся вебхуки уволенного сотрудника, как приложение получает его авторизацию и как отключить связанные с ним интеграции.

## Типы системных пользователей

| Тип | Когда создается | Зачем нужен |
|---|---|---|
| Для вебхуков `RESOURCE_TYPE: WEBHOOK` | При увольнении сотрудника, если администратор сохранил его входящие вебхуки | Вебхуки продолжают работать после увольнения сотрудника |
| Для приложений `RESOURCE_TYPE: APP` | При установке тиражного приложения | Приложение работает без участия сотрудника, который его установил |

## Как работает перенос вебхуков {#webhooks}

Если у сотрудника есть входящие вебхуки, при увольнении открывается диалог выбора. Администратор, который увольняет сотрудника, выбирает один из двух вариантов:

- *Отключить интеграции и уволить* — вебхуки перестают работать
- *Сохранить интеграции и уволить* — создается системный пользователь с типом `RESOURCE_TYPE: WEBHOOK`, вебхуки сотрудника переносятся на него

Системный пользователь получает имя, фамилию и группы доступа уволенного сотрудника, поэтому вебхуки продолжают работать с теми же правами. Адреса вебхуков не меняются: запрос по старому адресу Битрикс24 выполняет от имени системного пользователя.

Сохраненный вебхук остается рабочим для любого, кто знает его адрес, в том числе для уволенного сотрудника. Если вебхук больше не нужен, выберите *Отключить интеграции и уволить* или удалите вебхук.

Если сотрудник отредактирует вебхук, работающий от имени системного пользователя, вебхук автоматически переходит к этому сотруднику.

## Системный пользователь приложения {#app}

Системный пользователь приложения нужен, чтобы тиражное приложение работало в фоне без участия сотрудника. Его авторизация не зависит от сотрудника, который установил приложение, и продолжает работать после его увольнения.

### Когда создается

При установке приложения после нажатия кнопки *Установить* открывается окно с флажком *Создать системного пользователя*:

- флажок включен — Битрикс24 создает системного пользователя и отправляет приложению событие [`ONAPPUSERREADY`](../api-reference/common/events/on-app-user-ready.md) с его авторизацией
- флажок снят — системный пользователь не создается и событие `ONAPPUSERREADY` не приходит. Событие `ONAPPINSTALL` приходит как обычно

Выбор сохраняется при первой установке приложения. Приложения, установленные до появления флажка, при обновлении получают системного пользователя, как раньше.

Системный пользователь не создается:

- для [локальных приложений](../local-integrations/local-apps.md)
- при установке через `CRestUtil::InstallApp`

Системный пользователь создается один раз для приложения и существует, пока приложение установлено. Если он для приложения уже есть, например после повторной установки, Битрикс24 активирует его снова и повторно отправляет `ONAPPUSERREADY`.

### Какие права получает

Битрикс24 берет у сотрудника, который установил приложение, часовой пояс, язык и группы доступа. Повышенные роли установившего сотрудника не наследуются: в оргструктуре системный пользователь получает роль обычного сотрудника.

### Как приложение получает авторизацию

Отдельного метода для получения системного пользователя приложения нет. Приложение узнает его идентификатор и токены из объекта `data` события `ONAPPUSERREADY`. Храните эти токены отдельно от токенов сотрудника, которые приходят в `ONAPPINSTALL`.

### Что происходит при увольнении сотрудника

Приложения при увольнении сотрудника на системного пользователя не переносятся, диалог выбора их не показывает. Токены, которые приложение получило от имени уволенного сотрудника, системному пользователю не передаются. Чтобы приложение продолжило работать, используйте для фоновых вызовов авторизацию из `ONAPPUSERREADY`.

### Что происходит при удалении приложения

При удалении приложения системный пользователь деактивируется, и его авторизация перестает работать.

## Параметры создаваемого пользователя

| Поле | Тип | Для вебхука | Для приложения |
|---|---|---|---|
| `NAME` | string | Имя уволенного сотрудника | Название приложения |
| `LAST_NAME` | string | Фамилия уволенного сотрудника | Пустая строка |
| `GROUP_ID` | array | Наследуется от уволенного сотрудника | Наследуется от сотрудника, который установил приложение |
| `TIME_ZONE` | string | Наследуется от уволенного сотрудника | Наследуется от сотрудника, который установил приложение |
| `LANGUAGE_ID` | string | Наследуется от уволенного сотрудника | Наследуется от сотрудника, который установил приложение |
| `EXTERNAL_AUTH_ID` | string | `rest_system` | `rest_system` |
| `ACTIVE` | boolean | `true` | `true` |

## Как найти системного пользователя

Системный пользователь — технический объект. В списке сотрудников он по умолчанию скрыт и не находится через поиск в Битрикс24. Чтобы увидеть системных пользователей, в списке сотрудников выберите пресет фильтра *Системные пользователи*.

Методы `user.get` и `user.search` системного пользователя не возвращают, в том числе при фильтрации по полю `EXTERNAL_AUTH_ID`.

## Как отключить интеграции системного пользователя

Системного пользователя можно уволить из его профиля или групповым действием в списке сотрудников с пресетом *Системные пользователи*. Диалог увольнения показывает связанные с ним приложение и входящие вебхуки. После подтверждения кнопкой *Отключить интеграции и уволить* они отключаются и перестают работать от имени системного пользователя.
