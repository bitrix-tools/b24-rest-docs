# Инициализация и авторизация: обзор функций

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Системные функции подготавливают встроенное приложение к работе. Их используют до вызовов API и работы с интерфейсом.

{% note info "" %}

Функции раздела работают только в контексте [приложения](../../../settings/app-installation/index.md).

{% endnote %}

> Быстрый переход: [все функции](#all-methods)

## Как начать работу

1. Дождитесь готовности библиотеки через [BX24.init](./bx24-init.md), чтобы получить данные Битрикс24 и перейти к следующим вызовам
2. Зарегистрируйте обработчик через [BX24.install](./bx24-install.md), если нужен сценарий первого запуска приложения у текущего пользователя
3. Завершите настройку вызовом [BX24.installFinish](./bx24-install-finish.md), чтобы перейти к обычной инициализации приложения
4. Получите текущие OAuth-данные через [BX24.getAuth](./bx24-get-auth.md) или обновите их через [BX24.refreshAuth](./bx24-refresh-auth.md)

## Что важно учитывать

- Функции работают только внутри фрейма приложения. Библиотека получает данные Битрикс24 от родительской страницы, поэтому вне приложения вызовы не проходят
- [BX24.getAuth](./bx24-get-auth.md) возвращает результат сразу: объект с данными авторизации или `false`, если библиотека еще не инициализирована или срок действия токена истек
- Остальные функции раздела не возвращают данные. Результат приходит в функцию обратного вызова
- Собственный scope функциям не нужен: они не обращаются к REST API. Права и scope проверяются в тех методах Битрикс24, которые вы вызываете после инициализации
- Токен обновляется автоматически при следующем вызове метода Битрикс24. Вызывайте [BX24.refreshAuth](./bx24-refresh-auth.md), только если токен нужен вашему коду до такого вызова

## Данные авторизации

[BX24.getAuth](./bx24-get-auth.md) и [BX24.refreshAuth](./bx24-refresh-auth.md) отдают один и тот же набор полей:

#|
|| **Поле** | **Описание** ||
|| **access_token** | Токен доступа. Библиотека подставляет его в запросы к Битрикс24 сама ||
|| **refresh_token** | Токен обновления. Нужен, чтобы получить новый `access_token` после истечения срока действия ||
|| **expires_in** | Момент истечения срока действия токена доступа ||
|| **domain** | Адрес Битрикс24, в котором открыто приложение, например `mycompany.bitrix24.ru` ||
|| **member_id** | Постоянный идентификатор Битрикс24. По нему связывают установку приложения с записью на своей стороне ||
|#

## Связь с другими объектами

**Приложение.** Данные авторизации выдаются установленному приложению. Идентификаторы `member_id` и `domain` из [BX24.getAuth](./bx24-get-auth.md) показывают, в каком Битрикс24 работает приложение — их сохраняют на своей стороне, чтобы связать пользователя с установкой. Порядок установки описывает раздел [Установка приложения](../../../settings/app-installation/index.md).

**Методы Битрикс24.** После инициализации библиотека сама подставляет токен в запросы, отдельная передача `auth` не нужна. Вызывать методы из клиентской части приложения помогает раздел [Вызов методов REST](../how-to-call-rest-methods/index.md).

**Настройки приложения.** Значения, которые приложение хранит в Битрикс24 между запусками, читают и записывают функции раздела [Настройки приложения](../options/index.md). Их удобно заполнять в обработчике первого запуска [BX24.install](./bx24-install.md).
