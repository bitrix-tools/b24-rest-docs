# Инициализация и авторизация в BX24.js: обзор функций

{% note tip "" %}

Выберите инструмент для разработки с AI-агентом:

- используйте [Битрикс24 Вайбкод](../../../ai-tools/vibecode.md), чтобы создать приложение для Битрикс24 по описанию задачи без знания языков программирования. Агент напишет код и разместит приложение на сервере без ручной настройки хостинга
- используйте [MCP-сервер](../../../ai-tools/mcp.md), чтобы разрабатывать интеграцию через REST API в своем проекте. Агент будет обращаться к официальной REST-документации

{% endnote %}

Функции инициализации и авторизации библиотеки BX24.js подготавливают встроенное приложение к работе и выдают его коду данные авторизации.

{% note info "" %}

Функции раздела работают только внутри фрейма [приложения](../../../settings/app-installation/index.md).

{% endnote %}

> Быстрый переход: [все функции](#all-methods)

## Как начать работу

1. Подключите библиотеку BX24.js на страницу приложения — как это сделать, описывает [обзор библиотеки](../index.md)
2. Зарегистрируйте обработчик [BX24.init](./bx24-init.md) для обычной работы приложения и обработчик [BX24.install](./bx24-install.md) для первого запуска у текущего пользователя. Обработчик первого запуска регистрируйте при загрузке страницы: зарегистрированный позже, он в цепочку не попадет
3. Завершите настройку вызовом [BX24.installFinish](./bx24-install-finish.md), если у приложения есть страница установки или обработчик первого запуска — что делает вызов на каждом этапе, описывают [этапы установки](./bx24-install-finish.md#stages)
4. Получите данные авторизации через [BX24.getAuth](./bx24-get-auth.md), если их нужно передать своему серверу

Цепочка `BX24.install` идет раньше обработчиков `BX24.init`. Внутри каждого семейства обработчики выполняются в порядке регистрации. Если обработчиков первого запуска нет или пользователь запускает приложение не в первый раз, обработчики `BX24.init` выполняются сразу.

```js
// BX24.install регистрируем при загрузке страницы: позже он в цепочку не попадет
BX24.install(function() {
    // первый запуск у текущего пользователя: настраиваем приложение под него
    BX24.installFinish();
});

BX24.init(function() {
    // обычная работа приложения
});
```

Собственный scope функциям не нужен: они не обращаются к REST API. [Права и scope](../../../api-reference/scopes/index.md) проверяются в тех методах Битрикс24, которые вы вызываете после инициализации.

## Данные авторизации {#auth-data}

[BX24.getAuth](./bx24-get-auth.md) и [BX24.refreshAuth](./bx24-refresh-auth.md) отдают объект одинаковой структуры из пяти полей: `getAuth` возвращает его синхронно, `refreshAuth` передает в обработчик. Состав и типы полей описывают [Возвращаемые данные BX24.getAuth](./bx24-get-auth.md#returns).

Обновлять токен вручную обычно не нужно — когда это все-таки требуется, разбирает [BX24.refreshAuth](./bx24-refresh-auth.md). Сервер, которому вы передали токены, продлевает авторизацию иначе: [Автоматическое продление авторизации](../../../settings/oauth/auto-renewal.md).

## Обработка ошибок {#errors}

Кодов ошибок REST у функций раздела нет, а неудача проявляется двумя способами.

**Молчаливый отказ.** Функция не делает ничего и не сообщает об этом: до готовности библиотеки [BX24.refreshAuth](./bx24-refresh-auth.md) не отправляет запрос, а [BX24.getAuth](./bx24-get-auth.md) возвращает `false` вместо объекта. Невызванный [BX24.installFinish](./bx24-install-finish.md) так же тихо останавливает цепочку первого запуска.

**Шумный отказ.** Разработчик видит ошибку в консоли или браузерный `alert`:

- `Unable to initialize Bitrix24 JS library!` — страница открыта не во фрейме приложения
- `BX24 is not defined` — библиотека не подключена. Текст сообщения дает браузер, поэтому он отличается: Safari пишет `Can't find variable: BX24`
- `Installation failed!` — необработанное синхронное исключение в обработчике [BX24.install](./bx24-install.md)
- `Unable to get new token! Reload page, please!` — Битрикс24 не смог выдать новый токен по запросу [BX24.refreshAuth](./bx24-refresh-auth.md)

Что делать в каждой ситуации, разбирают разделы «Обработка ошибок» на страницах функций.

## Связь с другими объектами

**Приложение.** Данные авторизации выдаются приложению, зарегистрированному в Битрикс24. Идентификаторы `member_id` и `domain` из [BX24.getAuth](./bx24-get-auth.md) показывают, в каком Битрикс24 работает приложение — их сохраняют на своей стороне, чтобы связать пользователя с установкой. Порядок установки описывает раздел [Установка приложения](../../../settings/app-installation/index.md).

**Методы Битрикс24.** После инициализации библиотека сама подставляет токен в запросы, отдельная передача `auth` не нужна. Вызывать методы из клиентской части приложения помогает раздел [Вызов методов REST](../how-to-call-rest-methods/index.md).

**Настройки приложения.** Значения, которые приложение хранит в Битрикс24 между запусками, читают и записывают функции раздела [Настройки приложения](../options/index.md). Внутри обработчика первого запуска [BX24.install](./bx24-install.md) эти функции еще не подключены — на этом этапе настройки читают и записывают методами Битрикс24.

**Интерфейс и контекст.** Готовность библиотеки — не то же самое, что готовность DOM-структуры страницы: за нее отвечают [BX24.ready](../additional-functions/bx24-ready.md) и [BX24.isReady](../additional-functions/bx24-is-ready.md) из раздела [Интерфейс, навигация и контекст](../additional-functions/index.md).

**Данные о Битрикс24 и пользователе.** Адрес Битрикс24 из поля `domain` возвращает и функция [BX24.getDomain](../additional-functions/bx24-get-domain.md). Признака прав в объекте авторизации нет — узнать, администратор ли текущий пользователь, помогает [BX24.isAdmin](../additional-functions/bx24-is-admin.md).

## Обзор функций {#all-methods}

### Инициализация и первый запуск

#|
|| **Функция** | **Описание** ||
|| [BX24.init](./bx24-init.md) | Регистрирует обработчик события «библиотека готова к работе» ||
|| [BX24.install](./bx24-install.md) | Регистрирует обработчик первого запуска приложения у текущего пользователя ||
|| [BX24.installFinish](./bx24-install-finish.md) | Сообщает об окончании работы инсталлятора или настройщика приложения ||
|#

Ни одна из этих функций не возвращает данные. Обработчик обязателен для `BX24.init` и `BX24.install`, а `BX24.installFinish` его не принимает.

### Авторизация приложения

#|
|| **Функция** | **Описание** ||
|| [BX24.getAuth](./bx24-get-auth.md) | Получает текущие данные для авторизации через OAuth 2.0 ||
|| [BX24.refreshAuth](./bx24-refresh-auth.md) | Принудительно обновляет данные авторизации ||
|#

Обе функции работают после инициализации библиотеки.
