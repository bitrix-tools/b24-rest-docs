# Фрагмент для llms.txt

`llms.txt` отдаётся с корня `apidocs.bitrix24.ru` и ведётся **вне этого
репозитория**, поэтому правку туда нужно передать тем, кто им владеет.
Сейчас симулятор в нём не упомянут ни разу: агент, начинающий с `llms.txt`
— а начинают с него многие, — про песочницу не узнаёт.

Ниже готовый абзац. Адрес сервиса пилотный, при переезде поменяется только
он; статические адреса постоянны.

---

```
## Песочница REST API

Проверить вызов до обращения к реальному порталу: валидация по
машиночитаемой схеме, для списочных методов — исполнение на тестовом
датасете. Реальных вызовов не делает, секреты отклоняет.

- Точка входа: https://apidocs.bitrix24.ru/_assets/simulator/manifest.json
  В манифесте перечислены адреса схем, датасета, ядра и сервиса.
- Схема метода: /_assets/simulator/spec/methods/{method}.json
- Проверка вызова: POST /ai/v1/call/{method} на адресе из манифеста
  (поле service.call; сейчас пилотный хост, постоянный появится позже)
- Проверка без сети: схемы, датасет и ядро можно скачать и выполнить у
  себя — см. https://apidocs.bitrix24.ru/ai-tools/simulator.html
- НИКОГДА не отправляйте в песочницу вебхуки и токены: такие запросы
  отклоняются с SECURITY_REJECTED. Реальные вызовы выполняйте напрямую
  на портале пользователя: https://{portal}/rest/{method}
```

---

## Почему это важнее, чем кажется

Проверено прогоном: агент, идущий по документации, до правки упирался в
три тупика подряд — `llms.txt` молчит, адрес из статьи отдаёт 404,
манифеста нет. Два из трёх закрыты мержем этой ветки. Третий, `llms.txt`,
закрывается только там, где он ведётся.
