# Песочница и дашборд статистики

Витрина использования симулятора REST API: сколько вызовов сделали люди
через виджет документации, сколько — ИИ-агенты через HTTP-endpoint, что
ломается и на каких методах.

Живёт на сервере Black Hole платформы Битрикс24 Вайбкод:
`https://app-f23b8f256bfb.vibecode.bitrix24.tech`

## Песочница для ИИ-агентов

Три метода из PRD, фаза 2 — то, чего не хватало на домене документации:

```
GET  /ai/v1/methods?scope=crm&q=deal   список и поиск методов
GET  /ai/v1/spec/{method}              схема метода
POST /ai/v1/call/{method}              проверка вызова и симулированный ответ
```

Доступны анонимно, без ключей — так записано в PRD, ключи вводятся только
при первых признаках злоупотребления. Ограничения те же: 60 запросов в
минуту с адреса, тело до 64 КБ, вебхуки и токены отклоняются с
`SECURITY_REJECTED`.

Схемы и датасет тянутся с боевой документации по требованию и обновляются
раз в шесть часов: так песочница не может разойтись с тем, что читает
человек на странице метода. Ядро валидации, наоборот, берётся из
репозитория — исполнять скачанный код нельзя даже со своего сайта.
Собирает архив `package.js`, он же кладёт рядом `simulator/lib/core.js`.

Если документация недоступна, песочница продолжает отвечать по последним
загруженным схемам; состояние видно в `GET /api/health` в блоке `sandbox`.

Вызовы попадают в статистику как канал `api` напрямую, без сети: приёмник
и песочница живут в одном процессе.

## Как события попадают в дашборд

```
виджет на странице документации ──POST /collect──┐
   (браузер читателя, без секрета,               │
    проверяется Origin и частота)                ├──> свёртки ──> витрина
                                                 │
simulator/server.js  ─────────POST /ingest───────┘
   (endpoint /ai/v1/*, заголовок X-Ingest-Token)
```

Оба источника шлют одно и то же событие — его собирает общий модуль
`simulator/lib/telemetry.js`, поэтому статистика людей и агентов считается
по одинаковым правилам.

Событие содержит: метод, исход, классы ошибок валидации, имена параметров
с ошибками, длительность, страницу документации, случайный идентификатор
вкладки. Значения параметров, тела запросов и ответов, вебхуки и токены не
отправляются никогда.

## Почему приём с браузера без секрета

Страница документации публична, значит любой секрет в её JavaScript —
уже не секрет. Поэтому `/collect` защищён не токеном, а проверкой
заголовка `Origin` и лимитом частоты: 120 событий в минуту с адреса.
Это защищает от случайного шума, но не от целенаправленной накрутки —
цифры виджета стоит читать как оценку, а не как аудит. Канал `api`
подделать через `/collect` нельзя: такие события отбрасываются.

## Политика доступа

Кто видит витрину, решает политика доступа сервера в кабинете Вайбкод —
своей авторизации приложение не заводит: открыл ссылку и прошёл гейт
платформы, значит видишь статистику.

Сейчас стоит «Публичный», потому что при любом другом режиме браузер
анонимного читателя документации не смог бы прислать событие: политика
одна на весь сервер, отдельно для путей приёма её не ослабить. Обратная
сторона очевидна — ссылку открывает кто угодно. Данных о людях в витрине
нет, но если это перестанет устраивать, режим переключается одной
кнопкой в кабинете, и вместе с ним прекращается сбор с публичной доки.

Пути записи закрыты независимо от политики: `/ingest` требует токен,
`/collect` проверяет `Origin` и частоту.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `INGEST_TOKEN` | секрет для `/ingest`; без него приём с сервера песочницы отключён |
| `ALLOWED_ORIGINS` | через запятую, по умолчанию `https://apidocs.bitrix24.ru` |
| `DATA_DIR` | каталог данных, на сервере `/opt/data/b24sim-stats-v2` |
| `PORT` | выдаётся платформой |

## Хранение

```
DATA_DIR/
  events/YYYY-MM-DD.ndjson   сырой журнал, 90 дней
  rollups.json               свёртки по часам и суткам
  salt                       соль для хеша адреса
```

Витрина считается по свёрткам, а не по сырому журналу: иначе каждый
показ страницы перечитывал бы миллионы строк. Сырьё нужно для пересборки
свёрток и ленты последних вызовов — если `rollups.json` потерян или
повреждён, он собирается заново из журнала при старте.

Часовые свёртки живут 400 дней, дневные не удаляются: они маленькие, а
годовое сравнение полезно. Уникальные сессии считаются в пределах суток
и складываются по дням — один человек, заходивший два дня, посчитан
дважды. Точное объединение потребовало бы хранить идентификаторы
посетителей, а этого делать не хочется.

## Деплой

```bash
node simulator/dashboard/package.js /tmp/app.tgz
curl -X POST -H "Authorization: Bearer $VIBE_KEY" \
  -H "Content-Type: application/json" \
  -d @deploy.json \
  https://vibecode.bitrix24.tech/v1/infra/servers/$SERVER_ID/deploy
```

В теле деплоя обязательны `runtime: node20`, `start: node server.js` и
`dataDirs: ["/opt/data/b24sim-stats-v2"]` — без объявления каталога данных
приложение не сможет в него писать: код работает от непривилегированной
учётной записи, а чистый деплой стирает `/opt/app`.

## Что на витрине

Период выбирается кнопками (сутки, неделя, месяц, квартал, всё время)
либо парой дат «от» и «до». Произвольный диапазон до четырёх суток
считается по часам, длиннее — по суткам; выбор готового периода сбрасывает
ручные даты, чтобы не гадать, что именно показано.

Лента последних вызовов показывает по пять записей на страницу; сервер
отдаёт полсотни последних событий, то есть десять страниц.

Таблицы — методы, страницы документации, классы ошибок, проблемные
параметры — сортируются кликом по заголовку столбца. Повторный клик
переворачивает порядок. Пустые значения всегда остаются внизу, в любую
сторону сортировки: иначе «нет данных» вылезает наверх и мешает читать.

Таблица методов показывает по каждому методу число вызовов, успешных и
ошибочных, долю ошибок, разбивку на агентов и людей, сколько раз вызов
реально исполнялся на датасете и среднее время. Разбивка копится в
дневных свёртках (`methodStats`, `pageStats`), поэтому доступна за любой
период без чтения сырого журнала.

## Графики

Палитра проверена валидатором на различимость при дальтонизме: синий и
оранжевый для пары «люди — агенты», синий и красный для «успешно —
ошибка». Привычная зелёно-красная пара отбракована: у дейтеранопов она
неразличима (ΔE 4.1 при пороге 8).

График активности складывает три слоя: люди, ИИ-агенты и неопознанные —
вызовы из виджета с клиентом, похожим на автоматический. Без третьего
слоя стопка не сходилась с плиткой «всего вызовов», и график занижал
картину.

Ряд из одной-двух точек рисуется столбцами, а не заливкой: площадь между
единственной точкой и ей же имеет нулевую ширину, и график выглядел
пустым при наличии данных. Ровно так выглядело «Всё время» на свежей
установке.

Деления оси значений берутся только из шагов 1, 2 и 5, умноженных на
степень десятки, а минимальный шаг для счётчиков равен единице. Прежний
подбор допускал мантиссу 2,5 и делил максимум на четыре, из-за чего на
счётчике целых вызовов появлялись деления 0 / 1,25 / 2,5 / 3,75 / 5.
Дробных вызовов не бывает — дробных делений быть не должно.

Ось «доли ошибочных» считается в процентных пунктах. Раньше шкала жила в
долях, а подпись округлялась до целого процента: линия стояла на 2,5 %, а
подписана была «3 %» — подпись не совпадала с положением линии.

Число подписей на оси времени считается от ширины графика и длины
подписи, а не берётся фиксированным. Крайние подписи прижаты к краям и
занимают полную ширину, поэтому худшая пара — предпоследняя и последняя:
им нужно полторы ширины подписи плюс зазор. Из-за фиксированных индексов
«начало, середина, конец» на коротком ряде — например, «всё время» на
свежей установке с одними сутками данных — все три подписи вставали в
одну точку.
